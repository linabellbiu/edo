# K3s 数据库选择验收

范围：原生 K3s 新建表单、检测与计划配置；复用已有安装权限和执行流程。页面采用隔离前端夹具，后端采用独立测试数据库与模拟 SSH，不代表真实安装或发布。

| ID | 角色与前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| KD-01 | 有安装权限，打开新建原生 K3s | 查看安装方式附近的数据库选择，切换默认/自定义安装 | SQLite 默认选中；两种安装方式均可选 etcd；展示两者区别 | 通过 |
| KD-02 | 同上，已通过检测 | 切换数据库，重新检测并预览；切换 k3d 后返回 | 检测失效；计划与快照中的配置匹配选择；模式草稿保留 | 通过 |
| KD-03 | 自定义安装 | 填写冲突的 cluster-init 或外部数据库连接 | 冲突明确拒绝；外部连接保持自定义语义，不静默切换 | 通过 |
| KD-04 | 添加节点或 k3d | 打开表单，提交非法数据库选择 | 页面不提供选择；后端拒绝不适用或未知类型 | 通过 |
| KD-05 | 有安装权限 | 在浅色、深色与窄屏查看及键盘切换 | 标签和说明可读，焦点可见，无横向溢出；不触发安装 | 通过 |

证据：

- `web/tests/k3s-provision.test.mjs` 的数据库选择用例覆盖默认值、两种安装方式、检测失效、模式草稿、外部连接与 YAML 优先级；相关四个前端文件共 95 个测试通过。
- `go test -race -timeout 30s -run '^TestDatastore' ./internal/k3s` 通过，使用独立 SQLite 测试数据库与模拟 SSH 验证计划、加密快照、未知类型、不适用模式及冲突拒绝。既有自定义数据库行为继续由原接口配置。
- `npm run build` 通过（含 TypeScript 检查）。
- 独立浏览器会话打开本机 `tests/fixtures/k3s-preflight.html`，确认安装方式下方直接显示选择及区别；鼠标与方向键可以切换，焦点可见。浅色 1280px、深色 1280px 与深色 390px 均无表单横向溢出。只使用内存检测夹具，没有生成实际安装任务。
- 页面截图保存在本机临时目录：`/tmp/edo-k3s-datastore-light.png`、`/tmp/edo-k3s-datastore-dark.png`、`/tmp/edo-k3s-datastore-dark-mobile.png`、`/tmp/edo-k3s-datastore-focus.png`；不作为真实主机安装证据。

完整后端套件：`go test -race -timeout 5m -json ./internal/k3s` 全部通过，用时 202.371 秒，保留竞争检测与全部用例。前两次分别在 120 秒和 180 秒预算内超时，位置为 Master 制品暂存与卸载 Shell 夹具；提高测试总时限后完成，未修改或跳过原有用例。详细结果：`/tmp/edo-k3s-datastore-backend-full.jsonl`。
