# EDO DevOps RBAC 验收记录

本记录对应 [验收计划](rbac-devops-acceptance-plan.md)。本轮仅操作独立本地 EDO，不部署远程服务器，不接管同时进行的 NAS/K3s 安装。主验收使用正常 Go 后端与前端项目，经真实 Docker 构建、双人审批和部署验证 RBAC。

## 正常项目的完整 Docker 流水线

沿用公开测试仓库 `linabellbiu/edo-release-fullstack-20261024`，读取实际提交 `ab1242cb1965fa0a254cdaf5f8670303470a9f31`，未修改仓库。前后端分别构建镜像、运行容器，前端通过 Nginx 代理后端健康与业务接口。构建、发布均使用本轮独立 Docker-in-Docker；不要求安装 K3s。本轮浏览器通过仅监听本机回环地址的临时 TCP 转发访问隔离 daemon 内的前端，不将这个验收入口说成 EDO 已配置外网或域名发布。

项目管理员配置本轮应用、环境和双人审批保护；构建维护人员查看并编辑构建及流水线配置；发布申请人启动流水线；两名独立审批人分别投票；运维人员执行回滚。只读成员检查实际运行、制品和部署结果。恢复管理员未代替这些普通账号执行成功路径。

## 已确认并修复的缺陷

1. **无法配置完整项目权限。** 目录有 115 项项目动作，角色及个人授权请求却最多接受 100 项。动作集合改为有界的 512 项，角色个数仍限制 100；未知权限、过量请求和越权委派仍拒绝，失败不部分写入。
2. **环境审核人不检查实际审批资格。** 旧版可把只有项目读取权限的成员设为必需审核人。候选列表与保存事务都复用当前项目授权计算，角色撤权、个人拒绝、成员移除、停用及部门变化都会影响资格。
3. **内置开发角色可关闭审批保护。** 真实普通账号在专属项目成功停用保护，取证后已恢复。固定 UUID 的开发模板只保留安全读取与明确列出的开发动作；初始化及新建项目时收敛旧模板，保留 UUID、成员关系和自定义角色。运维、审批、保护配置、密钥管理需要另行显式授权。
4. **部分长连接和 SQL 后台任务信任旧策略。** Casbin 允许后增加当前数据库项目权限复核。状态通知按每类资源重新过滤；SQL 检查、执行和审核同时核对动作及必要读取权限，保留冻结项目、授权人和禁止自审规则。
5. **MySQL 初始化不幂等。** 真实 MySQL 测试发现数据库排序规则与 Go 字节排序不同，同一权限集合被误判为变化并重建权限行。比较前使用一致的字节序，保留稳定行号断言。
6. **停用账号的休眠会话复活。** 真实在线请求及双 Cookie HTTP 回归均复现。停用状态与认证版本递增现在使用同一条条件更新；重新启用不恢复旧认证版本，重复启停保持幂等，新登录继续正常。
7. **内置 Docker 端点绕过主机项目范围。** 没有本地主机的项目仍能请求容器列表，真实请求返回 200，但当时隔离 daemon 为空，未读取其他项目容器内容。内置端点现在必须先核验当前项目可见且启用的真实本地主机；查找、连接、日志、终端、文件和改名均在访问 daemon 或写入前拒绝。独立路由回归同时验证原所属项目正常读取、越权请求的 daemon/日志/Exec 调用为零；不可见日志返回 404，真实 Docker 故障仍返回安全的 502。
8. **助手子工具信任旧资源动作。** 基础助手权限仍在而资源动作被撤销时，旧 Casbin 允许可继续读取项目记录或确认写操作。统一子工具授权追加当前数据库项目复核，覆盖原生工具、确认与输出；已通过 SQLite/MySQL 回归和本地模拟模型协议的 HTTP/SSE 红绿测试。`d67004a` 候选已包含修复，不代表真实模型 Key 联调。
9. **审批进度与本人操作状态缺失。** 第一票后页面仍提供相同审核操作，成功节点仍写“等待其他成员审核”。后端新增当前读取者的只读审批投影，按真实独立投票及最新项目权限计算人数、本人状态和能否审核；新记录写入完成说明，旧成功记录只纠正展示，不重写历史。SQLite/MySQL 竞争检测通过，新版真实两个组件的四票 UI 验收通过。
10. **Docker 回滚缺少一致的预览与页面入口，确认后目标漂移也未完全阻断。** 旧 POST 固定了目标镜像，但未检查页面确认的来源时间，后台也未完整绑定当前来源发布标签。新增预览、提交、排队执行与实际停止前的容器身份、来源发布和不可变镜像复核；无确认参数入口也不得绕过当前归属检查。旧实现的 10 项红测均成立，修复后漂移场景 Docker 写调用为零；完整 `deployment` / `dockerengine` SQLite 竞争检测分别 99.922 / 21.988 秒、MySQL 专项 38.753 秒通过。新版两组件均已通过真实页面预览及确认回退。
11. **制品和只读编辑交互不合理。** 长应用名挤压制品表格，容量使用 MB，禁用编辑时仍提示拖动。局部调整列宽和窄屏滚动、全文入口、GiB/MiB 与缺失值语义，并隐藏只读拖动提示。整合 861 项前端测试及类型检查通过后，`d67004a` 真实 UI 仍发现两条 scoped CSS 没有命中多根组件，1280/375 布局失败；单位、全文与只读项另有 7 项通过。`926917a` 只修正真实祖先选择器，未改全局表格。正式 Web 重新验收的 9 项全部通过：表格宽 1360px，375 视口容器宽 303px，实际可横滚，容量保持单行；临时实验及原失败证据分别保留，最终页面没有注入样式。

新增回归覆盖正常允许、越权拒绝、存储失败、事务回滚和撤权；没有添加依赖或修改数据库结构。

## 运行版本与验证边界

- 正常 Docker 项目的发布、升级、失败恢复及回滚已真实完成；新版审批、Docker 回滚入口、制品及只读交互均通过普通岗位实际页面验收。API/Web 换版由维护环境的另一会话在约定窗口完成，构建 daemon 保持运行。
- 当前 API 实际版本为 `EDO d67004a`，Web 镜像为 `edo-e2e-web:926917a-kzs`；就绪检查的数据库、Redis、NATS、builder 全部正常。本轮业务最终为两端健康 v4。main 后续有独立工具和结果文档，不能把 main 最新 SHA 当作 API 运行版本。本轮只提交 main 和更新本地验收实例，不推送或远程发布；远程 CI 不计入通过证据。
- MySQL 的 `access`、`cicd`、`sqlchange`、`account`、助手完整包及本轮 HTTP/Docker 专项竞争检测通过；首轮完整 HTTP MySQL 测试有超时和其他会话正在修复的 K3s 夹具失败，不能称完整 HTTP MySQL 全绿。相关 K3s 组随后独立通过。
- SQLFluff 冷启动镜像下载曾超时，原工单保留真实失败；在专属构建 daemon 预热后，通过正常重新检查完成验证。该冷启动体验问题尚未修复，不能把热缓存成功说成首次启动成功。
- 状态 WebSocket 的真实撤权关流已完成；局部通知按资源过滤缺少真实业务触发，仍记录前置未满足。助手只有确定性的本地模型协议与 HTTP/SSE 测试，没有真实模型 Key 验收。
- 本轮不执行 Kubernetes、远程 SSH 部署或现有生产集群变更；不把 Docker 成功当作这些目标已验证。
