# EDO 多镜像 Compose 验收

范围：一条流水线，前序阶段并行构建和推送多个镜像，部署直接读取 EDO 中保存的 Compose 与实际构建 Tag。没有汇总清单阶段，不以主机原 Compose 为发布配置。自动回归、页面交互与真实外部执行分别记录。

| ID | 角色与前置 | 操作 | 预期 | 当前结果 |
| --- | --- | --- | --- | --- |
| MC-01 | 可执行流水线；仓库含固定子模块 | 隔离检出相同提交与子模块 | 固定 gitlink，不串用工作区，不跨站复用凭据 | 已有自动回归通过 |
| MC-02 | 可配置发布；两个服务共用一个输出镜像 | 在应用多镜像向导填写 EDO Compose、Tag、服务映射，创建草稿 | 原子生成构建、部署两个阶段；镜像去重；无运行副作用 | 定向 API 与前端回归通过 |
| MC-03 | 同次运行产出多个镜像 | 关联服务与前序构建，使用 Tag 变量部署 | 每个镜像检查归属、构建节点与固定提交；采用实际 Tag 并固定摘要；不把密钥展开进脚本 | 定向后端回归通过 |
| MC-04 | 配置未填完、错误 YAML 或映射 | 保存草稿，再启用或运行 | 草稿可继续编辑；启用和运行阻断不完整配置；同阶段来源及重复输出拒绝 | 流水线完整竞争回归与定向后端回归通过 |
| MC-05 | 可配置发布 | 编辑镜像名/Tag、部署方案 YAML 和服务映射；窄屏打开 | 均可通过正常页面修改；行号、高亮、格式化及错误定位可用 | 前端构建与 1643 项回归通过；桌面与 390 像素窄屏已检查，无横向溢出 |
| MC-06 | 生产已有健康手工栈，已核对原数据卷 | 建立监听基线后推送 dev-plat-* Tag，追踪并行构建、推送和部署 | 所有镜像属于同一固定提交，实际 Compose 与健康通过，数据库及原卷保留 | 待真实验收 |
| MC-07 | 隔离命令替身 | 分别模拟拉取失败、更新失败和成功 | 拉取失败不更新；更新失败恢复旧镜像且本次仍失败；无 down 或主机构建 | 隔离 Shell 回归通过 |
| MC-08 | 下游主机架构与 EDO 不同 | 直接关联多个上游镜像 | 所有构建沿下游主机选择目标架构 | 定向后端回归通过 |
| MC-09 | 本机独立限额 Compose 项目，含一次性 Init | 使用实际 Docker Compose 接管并验收 | Init 正常退出不被误判；不改动现有其他项目 | 真实 Compose 接管成功；健康失败后恢复上一镜像，本次仍失败；原容器基线保持 |

前端回归使用本机 Node.js 的 `--no-experimental-webstorage`，避免未配置的全局存储对象干扰夹具。完整后端回归需要本机测试端口；沙箱内因禁止监听失败的结果单独保留，不计为产品失败或测试通过。

新增部署任务服务映射与撤权/项目切换回归另有 2 项通过；最终受影响前端定向回归共 45 项通过。后端流水线、部署、Docker 相关完整竞争回归已通过，HTTP、SSH 部署与变量目录完整竞争回归均通过。无 SQL 表结构变化。
