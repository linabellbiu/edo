# EDO 多镜像 Compose 验收

范围：同一项目内，由 Tag 固定提交，分别构建镜像、汇总制品并通过主机脚本更新已有 Compose。部署主机不构建源码。

| ID | 角色与前置 | 操作 | 预期 | 当前结果 |
| --- | --- | --- | --- | --- |
| MC-01 | 可执行流水线；父仓库含固定 gitlink | 两个隔离工作区读取相同子模块，缓存另有新版本 | 均使用 gitlink 固定版本，互不串用，不携带 `.git` | 自动回归通过 |
| MC-02 | 仓库使用认证 | 分别配置同站、跨站和本地地址子模块，以及路径逃逸 | 只向相同远端身份复用凭据；拒绝本地与逃逸路径 | 自动回归通过 |
| MC-03 | 同次运行前序阶段产出多个镜像 | 后续脚本读取制品清单 | 只包含前序阶段、本项目、本应用、本次提交的可用产物；不含凭据和存储路径 | 自动回归通过 |
| MC-04 | 制品已过期、归属变化或提交不符 | 生成制品清单 | 明确失败，不以其他运行或同阶段产物替代 | 自动回归通过 |
| MC-05 | Dockerfile 构建方案 | 使用固定运行变量作为版本参数 | 参数绑定本次提交，不执行 Shell 或展开宿主环境 | 自动回归通过 |
| MC-06 | 已保存仓库、镜像仓库与生产主机；现有栈健康 | 建立监听基线后推送 `dev-plat-*` Tag，追踪构建、推送与发布 | 五类镜像属于同一提交，使用摘要部署；保留现有数据库、卷与配置，Compose 和健康验收成功 | 待真实验收 |
| MC-07 | 可配置发布且有构建方案创建权限；两个服务共用一个方案 | 在通用“已有 Compose 项目”表单填写任意项目名、文件、目录与服务映射，创建草稿 | 去重构建；原子生成并行构建、清单、部署三阶段，不启动任务；所选主机必须准确匹配环境 | API、页面状态及事务回归通过；桌面与窄屏真实表单已检查 |
| MC-08 | 已有 Compose 项目模板；隔离命令替身 | 分别模拟镜像拉取失败、更新失败与正常更新 | 拉取失败不更新；更新失败恢复旧镜像且本次仍失败；不执行 down 或主机构建 | 隔离 Shell 真实执行回归通过，不代替生产外部执行 |
| MC-09 | 多镜像汇总依赖；下游为另一架构 | 汇总节点选择上游构建，在同阶段或前序阶段分别引用 | 拒绝同阶段隐式依赖；前序镜像沿下游实际主机选择目标架构 | 自动回归通过 |

相关包 `repository`、`pipeline`、`variablecatalog`、`httpapi`、`sshdeploy`、`dockerengine` 完整回归包含竞争检测并通过；新增 HTTP 和 Shell 用例也分别通过。前端类型与构建、1641 项完整回归通过；本机 Node.js 26 使用 `--no-experimental-webstorage` 避免其未配置的全局存储对象干扰测试夹具。此前两项旧断言分别仍要求旧 sudo 文案和固定 NGINX FROM，已对齐现有产品文案及可覆盖镜像参数，同时保留非 root 与只读权限检查。

自动回归与表单预览不代替 MC-06 的真实远端验证；配置创建、构建成功与生产发布成功分别记录。
