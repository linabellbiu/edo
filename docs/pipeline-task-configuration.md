## 配置及执行约定

- 新任务直接配置，自定义构建支持命名构建物和构建缓存；镜像构建在启用或执行前必须选择镜像仓库，Dockerfile 和 Context 都相对于本次固定 Commit 的仓库根目录。草稿允许镜像仓库待配置。
- 每个命名构建物可以包含多个文件或目录，统一由 Go 归档为 tar.gz。一个构建的命名归档共同保存在不可变文件制品中；下游明确选择其中一个后下载到指定相对路径，脚本通过 `${构建物标识}` 引用下载路径。缓存继续复用现有隔离、锁文件、容量和过期机制。
- 主机部署提供自定义部署和 docker-compose 部署；Kubernetes 部署继续保留独立任务入口。独立方案的历史记录、现有引用和管理接口继续保留，未删除或迁移已有业务数据。
- Compose 的仓库文件、上传/编辑正文、非密钥 YAML 配置及上游产物共用后端服务解析。仓库绑定运行固定 Commit；配置正文按固定修订读取；本次上游产物在部署前解析并固定实际正文，后续重启及重建不重新读取分支头。单文件产物直接解析，归档通过安全相对路径读取。
- 文件服务预览只返回服务名与预览 Commit，不返回配置正文、变量值或基础设施错误；上传不执行。所有来源在实际部署时再次校验，动态来源未生成时只说明解析时机。
- 自定义部署仅读取用户手动关联的精确容器名，不枚举同主机其他容器。关联、重启与重建命令进入成功部署的运行快照；未关联时继续作为纯脚本部署，不显示 Docker 服务。
- Docker 状态读取保留创建时间、重启次数、镜像、日志及终端。重启、停止、重建分别鉴权，确认绑定精确容器 ID、命令及配置修订；已被其他应用声明的容器不能重复接管。
- 自定义命令在原部署主机非交互执行；动作实际影响取决于用户保存的脚本。重启或重建必须核验实际容器代次变化，不能仅凭脚本退出码宣称容器已重启。内置 docker-compose 因配置变化需要重建时，确认并复核重建权限；自定义部署始终执行用户指定的对应命令，容器环境更新由其重建命令处理。
- 取消独立方案前置不改变既有运行实例的身份。当前应用只按自身工作流任务、成功部署记录及实际运行时身份展示实例，未运行草稿不覆盖实例所用参数。

## 自定义构建工作区与统一 dockercompose（2026-11-08）

自定义构建在 EDO 为本次任务检出的独立仓库工作区直接执行，固定从仓库根目录开始，使用 EDO 所在环境已有的工具链；子目录由脚本自行 `cd`。页面移除运行镜像与工作目录。Docker 安装 EDO 时，这里的运行环境是 API 容器；EDO 不自动安装工具链，也不将工作区目录隔离描述为操作系统沙箱。普通 Shell 任务及已有运行快照的隔离执行方式保持原有语义，新构建快照明确记录 `workspace` 模式。

执行继续使用当前项目权限、固定 Commit、脱敏日志、任务超时、缓存和制品存储。任务使用独立 HOME 和临时文件，不继承 EDO 的数据库、加密密钥等服务环境变量；保存的构建变量与文件密钥按原权限和版本注入。取消及收尾清理同组子进程。产物保持总体 1 GiB / 100000 条目边界，拒绝链接、特殊文件和越界路径；报告同样拒绝可能阻塞的特殊文件。

新建部署只提供一个 Docker Compose 入口，单服务和多服务共用 Compose 解析流程。2026-11-10 起，新运行按用户配置的 image 执行，不自动匹配上游镜像；部署仓库由用户独立选择并保存。已有单镜像方案保留 UUID、类型和历史执行语义，不自动迁移数据。表单及新建任务默认文件名为 `compose.yaml`，仍支持用户明确指定的 `docker-compose.yaml` 或其他合法路径。文件标题、上传按钮同一行，脚本标题、上传按钮同一行，继续支持 YAML 全屏、格式化和 Shell 自动检查。新规则及验证范围见[部署镜像独立配置验收](acceptance/independent-deployment-images-20261110.md)，下表保留原批次验收结果。

通用执行能力复用 Go 官方 `os/exec`、`os.Root`、`io/fs` 及项目现有进程组处理方式，文件归档、缓存与权限继续复用现有实现；没有新增第三方依赖或数据库列。标准库由 Go 持续维护，适配项目支持的 Linux/macOS，避免额外常驻执行服务；产物边界、审计和权限仍属于 EDO 自身业务规则。
