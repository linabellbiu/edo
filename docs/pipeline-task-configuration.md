# 本轮业务用例（本地合成页面及隔离自动化）

| ID | 角色与前置 | 操作 | 预期 |
| --- | --- | --- | --- |
| PIPE-01 | 当前项目可编辑流水线 | 选择自定义构建，编辑脚本，添加命名构建物和多个路径，打开缓存并保存重开 | 配置回显，名称唯一、路径安全，缓存真实参与任务 |
| PIPE-02 | 当前项目可编辑流水线且可读仓库 | 选择镜像构建，关联镜像仓库并填写 Dockerfile、Context | 缺少仓库或路径不合法时拒绝，配置在任务中保存 |
| PIPE-03 | 当前项目可编辑流水线 | 仓库路径、上传、正文、配置和上游产物切换 Compose 来源 | 统一解析服务；固定 Commit，未生成产物延迟到部署前解析，错误不沿用旧列表 |
| PIPE-04 | 当前项目可编辑流水线 | 配置自定义部署，不关联或手动关联容器名及重启、重建命令 | 不自动发现；只展示绑定服务，命令静态检查与运行快照生效 |
| PIPE-05 | 有容器动作权限且已有成功部署 | 对绑定容器预览并操作，替换 ID、其他应用及撤权后再请求 | 精确 ID、项目、应用、配置确认及独立 RBAC 生效，不接管其他服务 |
| PIPE-06 | 当前应用有 inline 部署成功记录 | 查看应用关联服务、切换应用与流水线、修改未运行草稿 | 实例继续可见，只显示所属应用；草稿不覆盖已成功部署参数 |

依赖继续复用官方 Moby 客户端、已有 YAML 包、mvdan.cc/sh/v3 和 Go archive/tar、compress/gzip，未引入新依赖。

## 配置及执行约定

- 新任务直接配置，自定义构建支持命名构建物和构建缓存；镜像构建在启用或执行前必须选择镜像仓库，Dockerfile 和 Context 都相对于本次固定 Commit 的仓库根目录。草稿允许镜像仓库待配置。
- 每个命名构建物可以包含多个文件或目录，统一由 Go 归档为 tar.gz。一个构建的命名归档共同保存在不可变文件制品中；下游明确选择其中一个后下载到指定相对路径，脚本通过 `${构建物标识}` 引用下载路径。缓存继续复用现有隔离、锁文件、容量和过期机制。
- 主机部署提供自定义部署和 docker-compose 部署；Kubernetes 部署继续保留独立任务入口。独立方案的历史记录、现有引用和管理接口继续保留，未删除或迁移已有业务数据。
- Compose 的仓库文件、上传/编辑正文、非密钥 YAML 配置及上游产物共用后端服务解析。仓库绑定运行固定 Commit；配置正文按固定修订读取；本次上游产物在部署前解析并固定实际正文，后续重启及重建不重新读取分支头。单文件产物直接解析，归档通过安全相对路径读取。
- 文件服务预览只返回服务名与预览 Commit，不返回配置正文、变量值或基础设施错误；上传不执行。所有来源在实际部署时再次校验，动态来源未生成时只说明解析时机。
- 自定义部署仅读取用户手动关联的精确容器名，不枚举同主机其他容器。关联、重启与重建命令进入成功部署的运行快照；未关联时继续作为纯脚本部署，不显示 Docker 服务。
- Docker 状态读取保留创建时间、重启次数、镜像、日志及终端。重启、停止、重建分别鉴权，确认绑定精确容器 ID、命令及配置修订；已被其他应用声明的容器不能重复接管。
- 自定义命令在原部署主机非交互执行；动作实际影响取决于用户保存的脚本。重启或重建必须核验实际容器代次变化，不能仅凭脚本退出码宣称容器已重启。内置 docker-compose 因配置变化需要重建时，确认并复核重建权限；自定义部署始终执行用户指定的对应命令，容器环境更新由其重建命令处理。
- 取消独立方案前置不改变既有运行实例的身份。当前应用只按自身工作流任务、成功部署记录及实际运行时身份展示实例，未运行草稿不覆盖实例所用参数。

## 本轮验证记录

- 自动化覆盖内联任务保存与快照、必填镜像仓库、路径越界、归档成员、多个命名产物、Compose 来源、当前实例、容器权限和跨应用拒绝，包含竞争检测。
- 页面验收使用明确标识的本地合成数据，覆盖新构建字段、产物与缓存、Compose 来源和服务选择、手动关联字段及问号说明；不作为真实主机发布结果。
- GitHub CI、镜像仓库外部推拉及远程主机发布不属于本轮执行范围。
