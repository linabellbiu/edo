# Compose 镜像与执行日志验收

新运行的 Compose `image` 只进行用户变量插值，保留填写的 Tag 或 Digest，不自动把 Tag 替换为摘要。日志展示实际镜像引用、目标、拉取操作及完整的 Compose 命令；凭据、配置正文和密钥不输出。

| ID | 前置与角色 | 操作 | 预期 |
| --- | --- | --- | --- |
| LOG-01 | 有流水线执行权限，镜像含 `${EDO_IMAGE_TAG}` | 从 Git Tag 或分支解析 Compose | Tag 变量分别为 Git Tag 或短 Commit SHA；完整 image 保留 `名称:Tag`，不额外访问仓库解析摘要 |
| LOG-02 | 已保存私有仓库认证，目标已有同名 Tag | 拉取并准备镜像 | 使用所选范围的认证按原始 Tag 拉取；不因本地已有缓存跳过更新，不向其他仓库发送凭据 |
| LOG-03 | 自定义项目、目录、env 文件及服务范围 | 执行部署脚本 | 日志记录真实目录、生成文件以及完整命令与参数；命令替换的 stdout 不被日志污染 |
| LOG-04 | 正常、拉取失败、启动失败及回滚场景 | 执行部署并读取任务日志 | 命令只在真正执行时输出；保留退出状态、错误详情、回滚实际命令与身份校验，不泄露秘密 |
| LOG-05 | 历史运行或成功实例 | 恢复执行上下文 | 历史冻结镜像语义保留；新 Tag 部署回滚使用原容器镜像身份，不被已更新的同名 Tag 替换 |

复用现有 compose-go 插值、Distribution reference 校验与 Docker 官方 SDK，无新增依赖。真实 Docker 验证使用独立项目及精确清理，不触发业务流水线。
