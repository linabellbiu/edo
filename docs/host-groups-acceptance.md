# 主机组与部署目标验收

使用独立本地 EDO、SQLite、Redis 及专用 PostgreSQL / MySQL 实例，不操作生产主机。

| ID | 角色与前置 | 操作 | 预期 | 当前结果 |
| --- | --- | --- | --- | --- |
| HG-01 | 管理员，已有部署方案 | 打开流水线任务，修改任务名称后保存回读 | 不显示只读部署方式；新任务默认名称为部署方式，旧自定义名称保留 | 前端回归通过 |
| HG-02 | 管理员，原主机及分组 | 从主机页创建顶层及下级分组，改名、移动并回读 | 名称与层级持久化，原 UUID、主机和部署关联保留 | 服务及 HTTP 通过，真实页面已创建并回读顶层组 |
| HG-03 | 管理员，两个项目 | 重名创建或改名，选择自身、下级或其他项目父组，删除有下级的组 | 稳定中文提示，拒绝非法改动，不泄露其他项目详情 | 服务及 HTTP 通过 |
| HG-04 | 管理员，旧库及独立新库 | SQLite、PostgreSQL、MySQL 建库、升级、重复迁移、继续写入；旧重名数据升级 | UUID/成员不变，名称全局唯一；重名时阻断并保留数据，修正后可重试 | 三种数据库真实测试通过 |
| HG-05 | 有部署权限，组内多主机 | 选择组、默认全选，取消部分主机后保存并运行 | 只执行勾选主机，每台结果可追踪；多组成员关系保留 | 待实现多主机执行 |

首批验证：1770 条前端测试与生产构建通过；数据库、主机、分组服务、相关 HTTP、流水线目标和应用分组回归通过，Go 测试启用 race。主机包首次在沙箱内因本机监听被拒绝而失败，允许隔离监听后重跑通过。MySQL 首次缺时区表，专用实例载入系统时区后真实迁移通过。
