# 镜像上下文一致性检查

只检查构建、部署和实例操作之间的名称、版本及冻结语义，不修改业务仓库，不触发业务流水线，不扩展到其他基础设施能力。

| ID | 前置与角色 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| IC-01 | 旧显式构建 Tag；部署引用仅位于 Tag 引用字段或 Docker 方案脚本 | 解析部署变量 | 使用本次实际产物 Tag，不退回 Git Tag | 已复现并修复；SQLite/MySQL 通过 |
| IC-02 | 配置参数使用 Compose 默认值、必填值或省略 latest | 固定所选来源镜像 | 使用 Compose 官方插值语义，固定到所选 Digest；无效必填值失败且不泄露内容 | 已复现并修复；覆盖未设置、空值、默认值、必填及 latest，SQLite/MySQL 通过 |
| IC-03 | 仅部署或自定义构建；绑定自定义容器操作 | 执行重启和重建 | 内置 Git Tag、短 Commit 和镜像 Tag 与首次部署一致 | 已复现并修复；正常控制入口及确认重复拒绝通过，SQLite/MySQL 通过 |
| IC-04 | 独立部署运行后续阶段、同阶段或其他项目生成不同镜像 | 操作此前已部署实例 | 只取该部署前序阶段已成功/跳过的实际产物，后续与其他项目不改变版本 | 已复现并修复；阶段、项目、状态和构建类型过滤及多 Tag 不回退通过，MySQL 回归通过 |
| IC-05 | Compose 环境引用版本；包含旧 `${RELEASE_TAG}` 别名 | 重建服务 | 内置变量可用；引用转换为合法环境变量名，仍使用成功部署的服务、参数和镜像身份 | 已修复；新旧模式经正常重建入口及主机环境校验通过，MySQL 回归通过 |
| IC-06 | 默认/自定义镜像名称、多镜像、独立部署和旧运行 | 回归既有用例 | 名称冻结、权限、实际产物 Tag、不同 Tag 不猜测及部署解耦保持 | SQLite 完整回归及旧文件输入定向回归通过，MySQL 回归通过 |

新增复现分别在修复前出现 Tag 错取、Digest 未固定和操作环境缺少版本的失败；修复后原失败用例通过。容器状态由隔离 Docker HTTP 替身提供，主机命令使用执行替身，不冒充真实业务容器重启。权限、运行锁及确认通过正常服务入口验证，测试使用独立数据库并保留 `-race`。

旧版显式 OCI 绑定继续读取该绑定；文件制品输入不被误认为镜像绑定。新版独立部署按冻结阶段限定镜像上下文，不自动关联镜像，不读取后续阶段，不把多个不同版本悄悄替换成 Git 版本。

复用 Compose 官方 `compose-go/template`、现有 GORM 查询、运行快照及操作鉴权；不增加依赖，不实现另一套 Shell 或 Compose 插值器。
