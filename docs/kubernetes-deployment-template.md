# Kubernetes 内置部署模板

Kubernetes 部署阶段提供“内置标准模板”，首次创建 Deployment；旧配置继续提供“更新已有 Deployment 镜像”，不会自动转换。实现复用项目现有 Kubernetes 官方 client-go v0.36.2 的类型、数量解析、资源权限、服务端 dry-run 和带对象身份的写入，不引入另一个安装器、Helm、Shell 或新增常驻组件。

新任务命名空间和 Deployment 默认应用名，按 Kubernetes 名称规则转为小写和短横线。容器名使用选定 Dockerfile 构建的镜像名称末段；未配置镜像名称时沿用应用名。仅填写空字段，用户修改后保持原值。多个上游镜像必须先明确选择。

默认 1 个副本，请求 CPU 200m、内存 300Mi，限制 CPU 1 核、内存 1Gi。HTTP 8080 和 TCP 8888 均关闭，不创建 Service；开启后使用同名 ClusterIP Service。NodePort 独立开关，默认关闭，开启后由集群分配节点端口，也可填写默认合法范围 30000–32767 内的端口。HTTP 用 TCP 传输并标记 appProtocol=http；不自动添加 Ingress、域名、外部负载均衡或 hostNetwork。关闭全部端口时，已有模板 Service 取消对 Pod 的匹配，不删除资源。

配置提交检查当前项目工作负载修改权限；端口和 NodePort 的非默认配置另需服务与网络修改权限。执行使用运行快照中的授权人，分别核对命名空间、Deployment、Service 的读取与实际创建/更新权限。受限集群继续通过原 Kubernetes RBAC 和原生 API 凭据权限校验。私有仓库凭据只在执行时写入当前目标拥有的镜像拉取 Secret，不进入快照或日志；该步骤另需密钥权限。

同一流水线出现重复的集群、命名空间、Deployment 目标时不能执行。检查与执行前读取真实资源；同名资源不属于当前应用、项目或准确部署目标时拒绝接管。写入携带 UID 和 resourceVersion，创建竞争和更新冲突保留失败，不删除现场。命名空间允许按权限复用。模板、端口、资源和目标均进入不可变运行快照；成功须等待实际工作负载就绪。

| 用例 | 角色与前置 | 操作与预期 |
| --- | --- | --- |
| KT-01 | 可修改流水线与工作负载 | 选择标准模板，默认应用名、镜像容器名及资源正确；手动更改不被覆盖 |
| KT-02 | 可修改网络 | 分别开启 HTTP、TCP、NodePort，保存、重开准确回显；关闭默认不暴露端口 |
| KT-03 | 无相应权限或个人拒绝 | 控件禁用，直接提交及撤权后执行被拒绝 |
| KT-04 | 首次发布、专用 API 测试服务 | 创建命名空间及 Deployment，真实资源请求正确；端口关闭时不创建 Service |
| KT-05 | 当前目标已部署 | 再次发布保持对象身份，配置更新并等待就绪 |
| KT-06 | 其他应用拥有同名 Deployment 或 Service | 只读检查及执行失败，不能覆盖或产生其他写入 |
| KT-07 | 同流程两个相同目标或重复端口 | 检查失败，不能生成有效运行 |
| KT-08 | 本地已登录用户 | 独立窗口查看标准模板；不保存或部署，不覆盖原窗口未发布草稿 |

测试中的 Kubernetes API 服务用于接口与业务回归，不代表已在真实集群完成部署验收。
