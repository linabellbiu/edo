# Kubernetes 发布的构建平台

独立接入的 Kubernetes 集群无需关联 SSH 主机。先前创建流水线运行时统一读取部署目标主机架构，导致此类集群无法发布；给集群虚构一台主机也不能代表实际节点平台。

新建运行时，Kubernetes 部署目标通过已有的官方 client-go 连接分页读取 Node 的 `status.nodeInfo.architecture` 和 `status.nodeInfo.operatingSystem`，完成全部分页后，冻结去重、排序的 Linux AMD64 / ARM64 架构。即使部署目标保留旧的主机关联，也不会将该主机或构建机架构作为回退值。

集群无节点、节点平台信息不完整、包含不支持的平台或没有节点读取权限时，创建运行失败并提供安全的中文提示。不会用标签覆盖真实状态，不会用部分分页结果继续构建。集群项目归属和启用状态在读取节点前校验，现有请求项目范围及集群凭据的 Kubernetes RBAC 继续生效。详细故障只进入操作日志。

多个架构复用现有 BuildKit 多平台构建：Dockerfile 构建必须关联镜像仓库，以便推送多平台清单。后续构建使用本次运行快照，不会在执行过程中重新解释已冻结的节点架构。Docker 与主机脚本部署继续使用其实际目标主机架构。

快照新增可选 `architectures` 数组，并保留原来的 `architecture` 单架构字段。读取旧运行时仍可识别原字段；多架构运行不会在旧字段中冒充单一架构。此变更不修改数据库结构，不迁移、不改写历史运行或现有集群连接。

实现复用了项目已采用的官方 client-go、现有主机架构归一化函数和流水线多平台构建逻辑，没有新增第三方依赖或独立集群探测组件。
