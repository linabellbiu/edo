# ZRT 数据库迁移

ZRT 默认使用 SQLite。数据量、并发写入或高可用需求增长后，超级管理员可在“系统设置 → 数据库迁移”中将数据复制到 MySQL 或 PostgreSQL。

## 行为变化

- 迁移是 SQLite 的一致性快照复制，不删除或改写源 SQLite 数据库。
- 目标库必须是空库；上一次失败只留下空 ZRT 表结构时可以重试。系统不会自动清空已有数据。
- 启动前必须实际测试连接和空库状态，测试凭据 10 分钟内有效且只能使用一次。
- 存在待执行或运行中任务时拒绝启动迁移。迁移前仍应主动停止新的发布、调度和配置修改。
- 目标 DSN 只保留在当前请求和后台迁移协程的内存中，不写入 ZRT 数据库、审计元数据或 API 响应。

## 切换步骤

1. 停止新的发布和配置修改，确认任务中心无待执行或运行中任务。
2. 在系统设置中选择 MySQL 或 PostgreSQL，输入目标 DSN 并点击“测试连接”。
3. 输入 `MIGRATE` 后启动迁移，等待状态变为“已完成”。
4. 立即停止当前 ZRT 服务，避免快照完成后 SQLite 继续产生新写入。
5. 设置 `ZRT_DATABASE_DRIVER=mysql` 或 `ZRT_DATABASE_DRIVER=postgres`，并把同一目标库 DSN 写入受控的 `ZRT_DATABASE_DSN` 运行配置。
6. 执行 `zrt migrate` 做幂等的结构校验，然后启动 `zrt server`。
7. 验证登录、任务、日志、流水线和发布记录后，再恢复自动触发。

## 兼容性与回退

迁移复用项目已引入的 GORM 和官方 MySQL/PostgreSQL 驱动，不增加外部迁移运行时。源 SQLite 文件原样保留，在新库尚未产生新写入前可以通过恢复原环境变量回退。一旦新库已对外提供写入，不得直接切回旧 SQLite；应先停机并按新的一致性快照重新制定回退方案。
