# EDO 数据库迁移

EDO 默认使用 SQLite。数据量、并发写入或高可用需求增长后，超级管理员可在“系统设置 → 数据库迁移”中将数据复制到 MySQL 或 PostgreSQL。

## 行为变化

- 迁移是 SQLite 的一致性快照复制，不删除或改写源 SQLite 数据库。
- 目标数据库名默认是 `edo`。测试连接时，如果目标库不存在且账号具有创建数据库权限，EDO 会自动创建；目标库已存在时必须为空库。上一次失败只留下空 EDO 表结构时可以重试，系统不会自动清空已有数据。
- 启动前必须实际测试连接和空库状态，测试凭据 10 分钟内有效且只能使用一次。
- 存在待执行或运行中任务时拒绝启动迁移。迁移前仍应主动停止新的发布、调度和配置修改。
- 页面使用地址、端口、用户名、密码和数据库名生成目标连接；MySQL 默认端口为 `3306`，PostgreSQL 默认端口为 `5432`。
- MySQL 和 PostgreSQL 目标连接会话统一使用 `Asia/Shanghai` 时区；PostgreSQL 容器也应设置 `TZ=Asia/Shanghai` 和 `PGTZ=Asia/Shanghai`。
- 目标 DSN 和密码只保留在当前请求、页面及后台迁移协程的内存中，不写入 EDO 数据库、审计元数据或 API 响应。

## 切换步骤

1. 停止新的发布和配置修改，确认任务中心无待执行或运行中任务。
2. 在系统设置中选择 MySQL 或 PostgreSQL，填写目标库地址、端口、用户名、密码和数据库名，并点击“测试连接”。目标库不存在时会在此步骤自动创建。
3. 点击“开始迁移”，在中文确认弹窗中确认目标数据库后启动迁移，等待状态变为“已完成”。
4. 立即停止当前 EDO 服务，避免快照完成后 SQLite 继续产生新写入。
5. 设置 `EDO_DATABASE_DRIVER=mysql` 或 `EDO_DATABASE_DRIVER=postgres`，并把同一目标库 DSN 写入受控的 `EDO_DATABASE_DSN` 运行配置。
6. 执行 `edo migrate` 做幂等的结构校验，然后启动 `edo server`。
7. 验证登录、任务、日志、流水线和发布记录后，再恢复自动触发。

## 兼容性与回退

迁移复用项目已引入的 GORM 和官方 MySQL/PostgreSQL 驱动，不增加外部迁移运行时。源 SQLite 文件原样保留，在新库尚未产生新写入前可以通过恢复原环境变量回退。一旦新库已对外提供写入，不得直接切回旧 SQLite；应先停机并按新的一致性快照重新制定回退方案。
