# 部署主机树与 Compose 默认折叠验收

| 用例 | 角色、前提与操作 | 预期与结果 |
| --- | --- | --- |
| DHT-01 | 编辑用户，打开方案库与流水线内配置 | 单个紧凑树形下拉展示组层级及主机，去掉主机组问号和常驻勾选面板；真实组件页面通过 |
| DHT-02 | 已保存同组两台主机，取消一台并保存、重新打开 | 父组半选，摘要显示 1 台；正常接口只保存 `prod / [a]`，回读保留；通过 |
| DHT-03 | 切换至另一个组，组内包含一台共用主机 | 默认选中新组主机，保存集合为 `staging / [a,c]`，不混入旧组的 b；通过 |
| DHT-04 | 原单主机、部分勾选、全不选、失效主机、只读、未加载和 Kubernetes | 不扩大发布范围，失效项保留提示；只读和加载中不补写；Kubernetes 仅选组，纯组织节点不作为空执行范围；前端回归通过 |
| DHT-05 | 打开部署 Compose 定义，展开与全屏往返 | 初始收起，展开/全屏可读取完整正文；方案库、详情、只读预览及流水线内入口均使用显式折叠参数，不改变其他 YAML 编辑器；通过 |
| DHT-06 | 深色主题、390px 窄屏 | 树形下拉与摘要紧凑可读，页面无横向溢出、浏览器无运行错误；通过 |

验证：Node 24 前端全套 1779 通过、0 失败；最后主机选择、方案编辑与保存定向回归 51 通过；生产构建与 `git diff --check` 通过。
