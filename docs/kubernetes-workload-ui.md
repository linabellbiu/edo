# Kubernetes 工作区与工作负载详情

本次调整以用户指定的 [Kuboard Prometheus Deployment 详情页](https://super-k3s.mxgent.cn/k8s/1tNy8CMoLjG/apps/v1/namespaces/monitoring/deployments/prometheus) 为只读参考，修正旧版大卡片和嵌套标签页造成的信息层级差异。保留 EDO 抽屉、现有权限及操作确认，不复制生产资源数据或引入新的运行组件。

## 行为变化

- 标题、集群上下文和操作合并到同一紧凑头部，页签与整体框架保持在窗口内。上方资料与事件摘要、下方历史版本/Pod/运行区分别限制高度，长内容在所属模块内独立滚动；展开标签、策略或趋势不会撑高整页。其他页签由当前内容面板滚动。模块支持键盘聚焦和滚动，窄屏按剩余空间重新分配分栏。

- 上方并排显示紧凑元数据与四列事件表，长标签、注解和事件可查看完整内容；策略默认折叠，不再占用独立大卡片。
- 下方以历史版本、对应 Pod、事件与运行状态三栏联动。版本依然按控制器 UID 关联 Pod，日志和终端按明确容器选择；旧 Pod 或跨集群的迟到回调不替换操作目标。
- 右栏按 Pod 事件、CPU/内存趋势、容器组资料、健康状态和容器卡组织。容器名只在对应卡片呈现，直接点击卡片标题切换；状态下方提供该容器的日志、终端和新窗口入口，不设置独立容器下拉或重复操作栏。事件与趋势按需展开，健康条件在宽屏双列、窄屏单列呈现。普通、Init、临时容器均保留，已退出容器可查看日志；终端沿用现有策略，仅允许运行中且有权限的普通或临时容器。异常事件首次出现时展开，同一 Pod 后续刷新不强制打断用户的折叠选择；读取失败仍有明确提示和局部重试。
- 模板改为左侧容器分类、右侧配置。关联资源返回后恢复模板分区和容器选择；选择失效时明确提示，不悄悄选中其他容器。
- Pod 详情复用同一运行容器区；关联 Pod 表格使用容器按钮直接切换，保留当前行。单容器自动定位，多容器直接点选；失效目标保留原选择并阻止日志和终端，不自动切到别的容器。
- 历史版本与对应 Pod 各占约四分之一，运行区保留约一半宽度；Pod 列与容器组资料使用浅中性背景，容器正文保持白底。
- 未变更数据库结构、已有资源或权限码，不需要数据迁移。
- 副本集选中用森林绿 `--workload-revision-selected`，Pod 选中用青绿色 `--workload-pod-selected`。两种底色均配白字，明暗主题分别检查对比度。普通项与悬停继续使用品牌靛蓝的浅色填充，运行状态由独立标签表达。元数据、事件、版本与 Pod 卡片、运行区和容器卡片以冷灰列标题、白色内容和留白建立层次。
- 事件表表头使用浅冷灰 `--workload-header`（#f8f9fb）与次要色 12px 文字。容器组标题栏使用浅靛蓝底 `--workload-bar`（#e2e9fb）配深靛蓝文字。选中版本的同色指针指向对应容器组，表头保留吸顶与分隔线。概览面板底色 `--workload-page` 沿用全站 #f5f6f8，深色主题取值同步全站暗色（#0f1014 / #17181d）。
- 状态色对齐应用与流水线：成功 #16845b、警告 #a76809、失败 #d74354（深色 #49c89c / #edb752 / #ff8490）；浅色底纹下正文略加深到 #127a52 / #96600a / #c23a4d 以满足 AA。CPU 趋势线与成功色同族，内存趋势线使用品牌蓝。
- 版本卡在参考页的「名称 + 版本号 + 三个副本数」之外，补一行镜像摘要（首个镜像的仓库名:标签，多镜像折成 +N，悬停看全部）和一条 4px 就绪进度条：就绪满为绿色、部分就绪为琥珀、全部不可用为红色、缩容到 0 时隐藏填充。Pod 卡在累计重启大于 0 时显示「重启 N」徽标（含所有容器），便于在版本列直接发现不稳定副本。所选版本已缩容到 0 时，Pod 列显示「该版本已缩容到 0，没有运行中的容器组」，而不是笼统的空列表。
- 列表的状态与就绪数量标签统一为 24px 高。「Pod 与日志」复用中蓝实底、白字的主按钮样式。
- 工作负载名称使用 17px 粗体，分区标题使用 14px 半粗体，正文与辅助信息分别使用 13px 和 12px。详情头部的镜像调整和编辑用品牌蓝，滚动重启用暖色，删除用浅红，YAML 和关联应用用中性色。副本按钮同时显示真实的就绪与期望数量。
- 卡片与容器边角统一放宽：面板 12px、版本／Pod／容器组卡 10px、条件行与操作按钮 8px，表头圆角交由卡片裁切，避免内外两层圆角出现白边。
- Pod 健康状态改为参考页的单列信息行：绿色对勾、条件名与时间同一行，行间以浅灰／白交替区分；容器组卡片正文回到白底，未选容器用浅灰底、选中容器标题保持浅青。容器组标题补充真实年龄，长名称换行时不挤压状态与操作。
- 版本副本数按三列对齐，Pod 时间、地址与节点合并为紧凑信息行；位置使用中性网络/节点图标，不用彩色 C/H 方块。事件区按实际内容自适应并限制最大高度，正常计数并入标题，加载与错误提示仍保留；少量事件不再撑出空白底板。容器正文保持白底，健康条件在浅底分区内以无描边的紧凑信息行呈现；容器选中标题和日志、终端操作使用浅色填充，不增加嵌套蓝色线框。
- 深色主题保留相同层级与低亮度面板；CPU 趋势青绿、内存趋势蓝色保持线条对比度。健康色只取决于真实状态，不因选中或悬停改变，未知或缺失数据不伪装成健康。选中、悬停与真实健康状态分别定义，参考布局不改变全站样式。

## 局部视觉与交互基线

按 `ui-ux-pro-max` 的高密度运维仪表盘建议，只统一 Kubernetes 总览、节点、工作负载、配置、存储与网络，不改变登录页、主侧栏或全站主题。正文与辅助信息保持 12–14px，以对齐、浅中性分区和细边界建立层次，而不是缩小文字、加粗装饰边框或堆叠说明。

- 分区、表头、普通行、选中行与悬停分别使用 K8s 局部令牌；状态标签、关联链接和激活页签在深浅主题下分别核对对比度。
- 长版本、Pod 名称可换行，事件行支持键盘与触控展开完整原因、时间和消息；标签注解保留展开入口。
- 历史版本与 Pod 使用正确列表语义，列内键盘焦点避开吸顶标题；恢复关联选择时只定位原目标，不换选对象或抢夺焦点。窄屏将历史版本与 Pod 并排放在上方，运行区占据下方；各模块仍独立滚动，保持页头与页签可见。
- 节点、服务、Ingress、存储等详情表可通过键盘聚焦横向滚动区域，并有区域名称与列头；范围树使用真实三态全选，禁用状态不响应悬停操作。
- 状态、节点时间范围与每页条数这些有限单选使用带统一内收箭头的原生控件，保留字符串／数字原类型；不以操作内部 DOM 的方式修补第三方组件。通用列表只新增可选分页插槽，其他业务页面继续使用原有分页和样式。

## 编辑面板的键盘焦点

资源编辑器仍是右侧满高面板，表单、底部操作和草稿确认不变。外壳复用已有 Ant Design Vue 的公开 Modal：它提供 Tab / Shift+Tab 循环和关闭后的焦点恢复，避免键盘进入被遮挡的列表分页。样式仅作用于 `kube-resource-editor-modal`，不改变其他弹窗或全站主题。

此处不新增焦点库、不维护自制通用焦点循环，也不嵌套两套弹层。原生 `dialog` 会阻断现有传送到页面根部的选择框及确认框，暂不采用。仍需用真实浏览器检查下拉框、确认框、草稿、焦点恢复、深浅主题及窄屏；组件桩测试不能代替键盘验收。该修改不代表已打开编辑器的撤权处理已经完成。

## 网络表单安全修复

Ingress 从实际后端读取数字或命名端口，只提交用户修改的字段，保留其他路径、规则、TLS 和未编辑字段。NetworkPolicy 仅在当前表单能够无损表达时编辑规则；多条规则、Egress 或复杂选择器等情况明确只读，仍允许修改标签，但不携带 `spec`。没有配置变更时不提交默认网络规则。

上述行为保留原权限、新鲜对象核对、UID/resourceVersion、防重复提交、服务端 dry-run、确认与离开草稿提醒，不涉及数据库迁移。

## 指标边界

现有 Pod 指标接口不提供历史序列。折线只累计本页实际收到的新鲜采样，最多 60 个；不补历史、不插值、不补零。缺失、过期、权限不足和请求失败分别提示，恢复后的真实点与故障前断线，不增加虚假失败采样；历史采样不能冒充当前用量。等待中或已退出容器的旧实例指标不显示为当前实例用量。

当前用量、请求与限制可在每张趋势图下展开核对；CPU 使用 m，容量使用 MiB / GiB。该能力不新增数据库表或后台采集任务。

## 验证方法

```sh
node --test web/tests/*.test.mjs
npm run build --prefix web
```

无真实登录态时可用开发服务器显式打开 `/tests/fixtures/workload-reference.html`，对照桌面、窄屏、深色、版本与容器切换。加 `?theme=dark` 查看深色。夹具使用实际 Vue 组件和单独标注的测试数据，拦截全部接口，不接入集群；它不进入应用路由或生产构建入口，也不能替代真实隔离集群的登录、日志、关联返回及权限验收。

完整工作区本地预览是 `/tests/fixtures/kubernetes-workspace.html`，支持 `?view=workloads`、`?view=nodes`、`?view=config`、`?view=storage`、`?view=network`，可叠加 `&theme=dark`。它挂载实际 `KubernetesView`，仅在内存中提供测试资源；全部 HTTP 写操作被拒绝，Watch 与 WebSocket 不连接真实后端。预览中的日志、终端及保存不能作为真实操作成功的证据。

验收分层保持如下：

| 范围 | 本地自动测试／浏览器预览 | 真实隔离集群 |
| --- | --- | --- |
| 六类页面、筛选、类型导航与分页 | 真实组件与测试数据验证 | 发布前复验 |
| 版本、Pod、容器联动与失效选择 | 行为回归与本地浏览器验证 | 发布前复验关联返回 |
| 数字／命名端口、复杂策略保护 | 生产 helper 和组件请求行为回归 | 未提交真实网络修改 |
| 权限、UID、新鲜度与迟到响应 | 前端允许／拒绝及失败边界回归 | 未替代真实账号与后端鉴权验收 |
| 深浅主题、焦点、长内容与窄屏 | 浏览器与局部 axe 检查 | 以真实资源继续验证 |

生产参考站只读比较，不填写、保存或执行资源操作。发布前仍需在 EDO 真实隔离集群检查列表范围、筛选排序、详情、关联返回、编辑与日志入口，不能仅凭脚本桩或夹具截图宣布已发布。
