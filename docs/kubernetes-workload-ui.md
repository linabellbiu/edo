# Kubernetes 工作区与工作负载详情

本次调整以指定的 Kuboard Deployment 详情页为只读参考，修正旧版大卡片和嵌套标签页造成的信息层级差异。保留 EDO 抽屉、现有权限及操作确认，不复制生产资源数据或引入新的运行组件。

## 行为变化

- 上方并排显示紧凑元数据与四列事件表，长标签、注解和事件可查看完整内容；策略默认折叠，不再占用独立大卡片。
- 下方以历史版本、对应 Pod、事件与运行状态三栏联动。版本依然按控制器 UID 关联 Pod，日志和终端按明确容器选择；旧 Pod 或跨集群的迟到回调不替换操作目标。
- 右栏顶部固定呈现所选 Pod 名称、唯一容器选择以及日志、终端入口，事件和 CPU/内存趋势按需展开，健康条件和容器状态原地查看。普通、Init、临时容器均保留，已退出容器可查看日志；终端沿用现有策略，仅允许运行中且有权限的普通或临时容器。异常事件首次出现时展开，同一 Pod 后续刷新不强制打断用户的折叠选择；读取失败仍有明确提示和局部重试。
- 模板改为左侧容器分类、右侧配置。关联资源返回后恢复模板分区和容器选择；选择失效时明确提示，不悄悄选中其他容器。
- 未变更数据库结构、已有资源或权限码，不需要数据迁移。
- 保持 EDO 原有全站风格，只在工作负载局部建立紧凑、中性的控制台层次：标题、表头、正文和次要信息分别分级，普通卡片白底，选中浅蓝 `#edf3fc`，只强调名称及 2px 选中锚点，正文和数据不整块染蓝。悬停采用中性浅灰，不把绿色同时当成交互色和健康色。列间仍是 1px 细线，不增加全站粗装饰框。
- 版本副本数按三列对齐，Pod 时间、地址与节点合并为紧凑信息行；位置使用中性网络/节点图标，不用彩色 C/H 方块。事件区按实际内容自适应并限制最大高度，正常计数并入标题，加载与错误提示仍保留；少量事件不再撑出空白底板。容器正文保持白底，健康条件使用连续信息行，不逐行堆叠灰色小卡。
- 深色主题保留相同层级与低亮度面板；CPU 趋势青绿、内存趋势蓝色保持线条对比度。健康色只取决于真实状态，不因选中或悬停改变，未知或缺失数据不伪装成健康。以上为当前候选设计，不代表用户已确认定稿或已发布。

## 局部视觉与交互基线

按 `ui-ux-pro-max` 的高密度运维仪表盘建议，只统一 Kubernetes 总览、节点、工作负载、配置、存储与网络，不改变登录页、主侧栏或全站主题。正文与辅助信息保持 12–14px，以对齐、浅中性分区和细边界建立层次，而不是缩小文字、加粗装饰边框或堆叠说明。

- 分区、表头、普通行、选中行与悬停分别使用 K8s 局部令牌；状态标签、关联链接和激活页签在深浅主题下分别核对对比度。
- 长版本、Pod 名称可换行，事件行支持键盘与触控展开完整原因、时间和消息；标签注解保留展开入口。
- 历史版本与 Pod 使用正确列表语义，列内键盘焦点避开吸顶标题；恢复关联选择时只定位原目标，不换选对象或抢夺焦点。窄屏取消版本与 Pod 列内纵向滚动，保留抽屉主滚动。
- 节点、服务、Ingress、存储等详情表可通过键盘聚焦横向滚动区域，并有区域名称与列头；范围树使用真实三态全选，禁用状态不响应悬停操作。
- 状态、容器、节点时间范围与每页条数这些有限单选使用带统一内收箭头的原生控件，保留字符串／数字原类型；不以操作内部 DOM 的方式修补第三方组件。通用列表只新增可选分页插槽，其他业务页面继续使用原有分页和样式。

## 网络表单安全修复

Ingress 从实际后端读取数字或命名端口，只提交用户修改的字段，保留其他路径、规则、TLS 和未编辑字段。NetworkPolicy 仅在当前表单能够无损表达时编辑规则；多条规则、Egress 或复杂选择器等情况明确只读，仍允许修改标签，但不携带 `spec`。没有配置变更时不提交默认网络规则。

上述行为保留原权限、新鲜对象核对、UID/resourceVersion、防重复提交、服务端 dry-run、确认与离开草稿提醒，不涉及数据库迁移。

## 指标边界

现有 Pod 指标接口不提供历史序列。折线只累计本页实际收到的新鲜采样，最多 60 个；不补历史、不插值、不补零。缺失、过期、权限不足和请求失败分别提示，恢复后的真实点与故障前断线，不增加虚假失败采样；历史采样不能冒充当前用量。等待中或已退出容器的旧实例指标不显示为当前实例用量。

当前用量、请求与限制可在每张趋势图下展开核对；CPU 使用 m，容量使用 MiB / GiB。该能力不新增数据库表或后台采集任务。

## 验证方法

```sh
node --test web/tests/*.test.mjs
npm run build --prefix web
```

无真实登录态时可用开发服务器显式打开 `/tests/fixtures/workload-reference.html`，对照桌面、窄屏、深色、版本与容器切换。加 `?theme=dark` 查看深色。夹具使用实际 Vue 组件和单独标注的测试数据，拦截全部接口，不接入集群；它不进入应用路由或生产构建入口，也不能替代真实隔离集群的登录、日志、关联返回及权限验收。

完整工作区本地预览是 `/tests/fixtures/kubernetes-workspace.html`，支持 `?view=workloads`、`?view=nodes`、`?view=config`、`?view=storage`、`?view=network`，可叠加 `&theme=dark`。它挂载实际 `KubernetesView`，仅在内存中提供测试资源；全部 HTTP 写操作被拒绝，Watch 与 WebSocket 不连接真实后端。预览中的日志、终端及保存不能作为真实操作成功的证据。

验收分层保持如下：

| 范围 | 本地自动测试／浏览器预览 | 真实隔离集群 |
| --- | --- | --- |
| 六类页面、筛选、类型导航与分页 | 真实组件与测试数据验证 | 发布前复验 |
| 版本、Pod、容器联动与失效选择 | 行为回归与本地浏览器验证 | 发布前复验关联返回 |
| 数字／命名端口、复杂策略保护 | 生产 helper 和组件请求行为回归 | 未提交真实网络修改 |
| 权限、UID、新鲜度与迟到响应 | 前端允许／拒绝及失败边界回归 | 未替代真实账号与后端鉴权验收 |
| 深浅主题、焦点、长内容与窄屏 | 浏览器与局部 axe 检查 | 以真实资源继续验证 |

生产参考站只读比较，不填写、保存或执行资源操作。发布前仍需在 EDO 真实隔离集群检查列表范围、筛选排序、详情、关联返回、编辑与日志入口，不能仅凭脚本桩或夹具截图宣布已发布。
