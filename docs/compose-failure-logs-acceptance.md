# Compose 失败详情日志验收

此前 Compose 输出只保留在执行主机的 `compose.log`，流水线仅显示失败摘要，无法直接排查镜像拉取错误。本次在失败时回传最近 80 行，最多读取文件末尾 64 KiB，并丢弃截断产生的不完整首行；保留原失败及恢复规则。详细内容继续经过流水线已有日志脱敏、任务归属、持久化、分页与 WebSocket 通道。

复用已有 POSIX Shell 工具及 EDO 日志写入器，不引入日志框架、依赖或常驻组件。Registry 密码和 Basic 认证值加入脱敏，所选配置、敏感环境变量及多行密钥继续受保护。接口仍返回稳定中文摘要，详细诊断只进入受权限控制的任务日志。

| 编号 | 角色与前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| CL-01 | 有流水线日志查看权限；镜像拉取失败 | 查看对应部署任务日志 | 直接显示镜像准备及拉取诊断，CLI 错误保留退出码；不执行后续 up | 通过：SQLite/MySQL 下镜像准备诊断及拉取失败注入；正常任务日志读取，未继续执行 up |
| CL-02 | 配置校验、启动或健康检查失败；包括恢复失败 | 执行隔离失败场景并查看日志 | 失败分支均回传详情；原失败及恢复状态不变 | 通过：配置、启动、健康及恢复失败注入；原镜像保持/恢复用例继续通过 |
| CL-03 | 配置、Registry 和多行凭据混入输出，且日志较长 | 读取截断后的失败日志 | 已知敏感内容脱敏，输出有界，尾部错误仍可见 | 通过：Registry 密码及 Basic 值、映射/列表环境变量和多行片段脱敏；长行截断，末尾错误保留；原运行配额与跨分块用例通过 |
| CL-04 | 真实 Docker Compose CLI；临时缺失文件 | 通过正常本地脚本执行器执行配置检查 | 原始 Compose 诊断进入流水线持久日志，可按任务读取 | 通过：真实 Docker Compose CLI 缺失 ENV 文件错误经正常本地脚本执行器进入任务持久日志；未拉取镜像或启动容器 |
| CL-05 | 已有日志查询与订阅权限 | 读取 HTTP/WebSocket 历史及任务日志 | 沿用原权限、范围及分页，不串入其他任务 | 通过：SQLite/MySQL 的正常 HTTP/WebSocket 任务过滤、分页及历史读取回归 |

所有故障注入使用独立数据和目录，不触发用户业务流水线，不修改业务仓库或执行主机。历史失败记录不伪造补全；脚本调整在后续使用新版本的运行中生效。

相关后端回归均使用 -race，通过 SQLite/MySQL 独立数据验证；不涉及表结构变更。拉取、启动和恢复故障为受控注入，真实 CLI 验证只执行配置失败流程，不将其冒充真实业务发布。
