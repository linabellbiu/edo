# 内置镜像 Tag 验收

> 最新规则：`${EDO_IMAGE_TAG}` 只表示 Tag，部署不需要关联构建任务。版本自动使用 Git Tag 或 12 位短 Commit SHA；镜像名称由用户配置。详见[镜像 Tag 语义修正验收](image-tag-only-acceptance.md)。历史运行继续按原快照执行。

构建不再提供镜像 Tag 输入框。新运行在服务端自动冻结版本规则：Git Tag 优先，否则取本次完整 Commit 的前 12 位。`${EDO_IMAGE_TAG}` 在构建脚本及 Dockerfile 构建参数中可直接引用；部署继续读取本次上游产物的实际 Tag。名称独立处理，用户填写时使用该名称，留空采用应用名，并在运行创建时冻结最终名称。旧运行及已有显式版本不改写。

复用 Compose、distribution/reference 和现有流水线变量及制品实现，不引入依赖，不自动关联或改写部署的 image。

| ID | 前置与角色 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| IT-01 | 有流水线编辑权限 | 打开内联/库镜像构建、自定义构建及 Compose 快捷构建 | 构建没有 Tag 输入；部署 Tag 引用入口、镜像名称高级设置与保存继续可用；只打开不产生草稿修改 | 通过：组件渲染、交互与保存测试；前端 1829 项测试及生产构建通过，实际页面随本地发布回执记录 |
| IT-02 | 有执行权限；未填写 Tag | 从 Git Tag、分支创建运行，覆盖默认名与自定义名 | 服务端自动生成正确版本，注册仓库与本地构建引用一致；完整 Commit 保留 | 通过：SQLite/MySQL 创建真实运行快照，覆盖默认名、手动名及名称中的应用变量 |
| IT-03 | 已生成运行；应用名称后续变化 | 读取原快照，再创建下一次运行 | 原运行保留已冻结的最终镜像名称；新运行采用新配置 | 通过：先冻结名称，再改变应用名称输入，新旧运行分别使用各自名称 |
| IT-04 | 构建脚本或 Dockerfile 参数使用内置变量 | 从正常工作区脚本执行并读取构建参数 | `${EDO_IMAGE_TAG}` 与实际镜像版本一致，用户变量不能覆盖；不执行用户命令替换 | 通过：真实独立工作区 Shell、构建参数解析与保留变量校验；Tag/分支均覆盖 |

以上数据库回归保留 `-race`，使用独立 SQLite/MySQL 数据。镜像引用规则检查不冒充真实外部仓库推送或业务发布；工作区脚本为真实执行，文件来源和用户命令不执行额外展开。

用户最新运行的实际构建为 `api:v0.0.2`、`web:v0.0.2`，错误请求为 `edo-demo-api:v0.0.2`，是名称不一致而非 Tag 不一致。本次不修改业务仓库或自动重跑业务流水线，真实业务部署结果单独验收。
