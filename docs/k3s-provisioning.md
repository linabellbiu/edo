# 创建 K3s 集群与添加节点

在“基础设施 → 主机与集群 → 集群”点击“创建集群”，选择已保存的 SSH 主机。已有集群仍通过“接入集群”导入 kubeconfig。

## 创建集群

先选择安装模式，默认使用原生 K3s。已有请求未携带 `mode` 时继续按原生模式处理，不改变已有安装计划的含义。

| 模式 | 运行位置 | 安装前提 | 适用范围 |
| --- | --- | --- | --- |
| 原生 K3s | Linux 主机的 systemd/OpenRC 系统服务 | SSH、root/sudo、所需资源与网络 | 默认方式，可跨物理主机安装控制平面和工作节点 |
| k3d | 单台 Linux SSH 宿主机的 Docker 容器 | 已运行的本机 Docker、所需资源、明确的 API 绑定 IPv4 与空闲端口 | 隔离测试，1 个控制平面容器及 0–8 个工作节点容器；不代表物理机高可用 |

两种模式切换后必须重新生成并确认计划；只有 k3d 需要先完成安装前检测。k3d 不接收原生 Server、Agent、安装器及 YAML 覆盖参数，不会自动转换已有集群或迁移工作负载与数据。

### 原生 K3s

1. 填写集群名称，选择一台控制平面主机。另一输入框为空时会自动回填同一台主机，先选择工作节点也可补齐空的控制平面。回填后两侧独立保存，手动改为不同主机时不再互相覆盖，清空工作节点也不会清空控制平面；可再增加其他工作节点主机。同一台只安装一次 K3s Server，自带 Agent 运行工作负载，其他主机才安装 Agent。自定义安装明确设置 `disable-agent: true` 时，控制平面不再显示为工作节点。
2. API 地址留空时，根据控制平面主机地址和最终的 HTTPS 监听端口生成；填写自定义地址时，需确保 EDO 和新节点均可访问。
3. 选择 SQLite 或内嵌 etcd，以及“默认安装”或“自定义安装”，点击“生成安装计划”。原生流程没有“安装前检测”步骤。SQLite 适合单控制平面，etcd 支持多控制平面，高可用通常需 3 或 5 台。
4. 确认准确主机、最终配置、安装命令和影响，再点击“开始安装”。生成计划不会执行安装。
5. EDO 在后台调用官方安装器，读取并加密保存 kubeconfig，接入集群并关联身份核验通过的 Ready 节点。关闭抽屉不影响执行，不需要人工登录主机补命令。
6. 官方安装器负责服务安装与启动；脚本完成后，EDO 仍需验证精确版本、API、节点与已启用核心组件就绪，全部通过才显示成功。

原生安装目标需为已启用、配置登录凭据、核对过 SSH 指纹且连接正常的 Linux 主机。非 root 账号需在主机凭据中启用 sudo。创建集群需要主机读取权限，以及 `cluster.create`、`cluster.execute`、`cluster.update`；原生安装会注册节点时，还需 `kubernetes.node.create`，在预览前就核对，不等安装后才报权限不足。k3d 及不注册任何节点的纯控制面不额外要求此节点权限。

原生安装不额外探测发行版、系统依赖、sudo 或网络，不自动安装基础依赖。EDO 使用已保存的 SSH/提权配置执行官方脚本，实际失败保留现场并显示任务失败。

在主机编辑页勾选“使用 sudo 执行 Docker / 安装操作”，测试通过后保存。仅有 SSH 能力的主机也可设置，不需要额外启用 Docker；测试会实际验证 root 权限。密码认证复用已保存的登录密码；私钥认证可填写独立的 sudo 密码，也可留空使用已有的免密 sudo；EDO 不会修改服务器的 sudo 配置。sudo 密码随 SSH 凭据加密保存且不回显；已有主机保持“保留凭据”时不会替换密码，要修改须明确选择“更换”并重新填写、测试整套凭据。关闭 sudo、切换认证方式或关闭表单会清除尚未保存的 sudo 密码。复用已有凭据重测时继续核对原 SSH 指纹；此设置不会让 SSH 部署脚本自动提权。

执行时仍核对操作者权限、项目、主机和配置快照，拒绝重复提交及覆盖已存在的 K3s 配置；这些保护不会运行系统环境预检。

安装复用 [K3s 官方快速入门](https://docs.k3s.io/zh/quick-start)的原版安装器，以固定版本及计划内参数安装系统服务，不通过 Docker/k3d 容器安装。配置保存在 `/etc/rancher/k3s/config.yaml`，安装完成后读取 `/etc/rancher/k3s/k3s.yaml` 接入 EDO；凭据不进入日志。

EDO 只包装主机选择、权限与配置传递、后台任务和结果验收，不自行实现 K3s 安装器。下载官方脚本后再执行，与快速入门使用同一安装器；不会改成自行创建 K3s 二进制或系统服务。需要明确的精确版本，不能只指定一个会变化的频道后把未知版本安装视为成功。

### 安装下载源与系统镜像源

新建及添加节点表单默认使用国内源（K3s 官方文档推荐），仍可手动选择官方下载源；系统镜像使用 K3s 默认镜像，不需要填写镜像仓库，也不预填第三方仓库。下载器使用主机已有的 curl 或 wget；官方安装器处理 K3s 的下载、校验、systemd/OpenRC 服务以及适用系统的 SELinux 策略包。EDO 不另行安装基础依赖，不检查下载端点或仓库的 HTTPS 连通性。

默认安装与自定义安装均默认选择官方文档推荐国内源，并可改为官方下载源，切换安装方式不覆盖已选下载源。系统镜像来源仅在自定义安装中按需展开。显式选择国内源时仍执行官方文档推荐的原版脚本；自定义系统镜像来源只通过 K3s 的 `system-default-registry` 传递，不修改宿主机、Docker 镜像源或代理。添加节点继承原集群的系统镜像配置，不改变整个集群。

来源进入确认计划和运行快照。切换来源后必须重新确认，已有计划和集群不被默认值改写。实际安装和组件就绪验证仍可能失败，失败不被标记为成功。

### k3d

选择当前项目的本地主机或一台 SSH 宿主机、工作节点容器数量（默认 1）、API 绑定 IPv4 与端口（默认 `16443`，允许 `1024–65535`）。SSH 模式的绑定地址必须是目标机器实际可用、EDO 可访问的 IPv4，不能填写 `0.0.0.0`、回环地址，或把公网 SSH 转发地址误当成 NAS 的本机 IP。本地模式根据已配置 Docker 连接回填绑定与 API 连接主机；允许回环或通配绑定，API 连接地址仍必须是 EDO 实际可访问的明确主机名或 IP。k3d v5.9.0 的 API 端口参数不支持 IPv6，本模式会提前拒绝；不影响原生 K3s。预检会核对本机 Linux Docker Engine（至少 `20.10.5`）、绑定地址、端口及总资源；不会自动关闭防火墙、安装 Docker 或重启 daemon。

平台调用固定版本的官方 k3d CLI，不自行拼装 Docker 集群。工具独立保存在 `/var/lib/edo/k3d/v5.9.0/`，核对官方发布的 SHA-256，不覆盖全局 k3d。集群使用本次安装 UUID 生成独立名称，不覆盖宿主机默认 kubeconfig 或切换其默认 context，也不接管已有同名集群。预览会显示最终版本与真实命令。

K3s 本地主机依据当前项目可见性、启用状态和 Docker 能力提供选择；实际连接、架构、版本及容量由 Docker 服务端读取，不依赖主机名称、固定 IP 或架构白名单。本地连接复用 EDO 的 Docker 配置，包括 Compose 下的隔离 Docker 构建器，不要求 SSH、root 或 sudo；原生安装仍不接受本地主机。Unix Socket 的本地二进制默认回环地址，容器环境会检测 Docker 宿主访问名称，无法自动确认时由用户填写 EDO 可访问的 API 连接主机。

本地平台的官方工具从固定版本的 GitHub Release 发布清单解析，使用官方 API 的 SHA-256 摘要校验；未发布当前平台或缺少摘要时明确阻止，不预设支持平台表。只读检测不下载工具或创建集群，确认执行后才写应用私有缓存，不写系统目录或默认 kubeconfig。预检读取 Docker 的总 CPU、内存和 runc 版本，无法确认的空闲内存、磁盘或运行时版本保留为警告，不伪装成已通过。已有 k3d 集群或 Docker 发布端口会阻止重复创建。

本地 Docker 配置摘要与 daemon 身份进入加密任务快照。操作前核对当前权限和连接身份，配置、证书或目标改变后旧计划失效。节点创建仍由官方 CLI 执行，随后只对已核对安装标签、集群标签和不可变 ID 的容器设置并验证资源限制，保存真实 Docker 拉取与 K3s 启动输出。安装失败保留现场，不自动删除、重建或接管已有资源。一次任务共用受控 Docker CLI 会话，逐节点操作不反复查询 SQL；任务期间继续复核授权和配置。

镜像提供“国内源 / Docker Hub / 手动填写”，默认国内源。国内源采用 [docker.aityp.com 对应的实际同步仓库](https://docker.aityp.com/image/docker.io/rancher/k3s%3Av1.37.1-k3s1) `swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/rancher/k3s`，从 Registry API 读取实际稳定标签与平台清单；Docker Hub 从官方标签 API 批量读取近期稳定版本与平台，不把 `latest`、预发布或未确认架构列为可安装版本。国内独立架构标签保留完整后缀。列表按主机架构筛选；没有匹配版本、目录读取失败或当前选择不匹配时明确提示，不自动改用另一来源或固定旧版本。

目录只读、不拉镜像层、不操作主机；每个来源缓存 5 分钟并合并并发请求，每次读取仍校验项目和当前身份。国内目录最多保留 100 个最新稳定标签，Docker Hub 最多读取 3 页各 100 条标签并在已取得至少 60 个稳定版本后停止；需要其他版本时可手动填写完整镜像地址。手动地址必须带明确标签或 SHA-256 摘要，不填写 `https://` 或登录凭据；EDO 不根据手动地址向任意服务发起目录请求。镜像须适用于 k3d，是否能启动由实际官方创建和就绪结果确认。

镜像来源和完整地址进入预检签名、确认计划、加密任务快照及官方 `--image` 参数，版本从所选镜像标签解析，不再固定为一个版本。修改镜像需要重新检测和确认，切换来源保留各自草稿。历史计划缺少镜像字段时仍使用当时固定的官方镜像，不能因新表单默认值而改变；k3d CLI 版本继续独立固定，镜像源选择不改变工具下载或原生 K3s 安装流程。

Server、Worker 的 CPU 和内存可分别配置，Worker 配置作用于每个工作节点容器。默认 Server 为 2 核、2048 MiB，Worker 每个为 1 核、1024 MiB。CPU 支持最多三位小数，内存使用整数 MiB；容器资源最低接受 0.01 核和 6 MiB，实际能否启动 K3s 仍取决于工作负载与官方要求。预检按所选节点数累计 CPU、内存，并为宿主保留 512 MiB；修改资源后须重新检测和确认。配置进入计划和任务快照，执行时使用已确认的值。旧任务缺少资源字段时仍按旧默认值执行。

官方 CLI 通过 `--servers-memory`、`--agents-memory` 设置创建时内存，创建后为本次集群的准确容器设置 CPU 和禁用额外 Swap，再核对 Docker 实际资源限制。k3d v5.9.0 不提供创建时 CPU 限额，因此容器启动到补充限制之间存在短暂窗口；不承诺创建全过程已有 CPU 硬限制。限制设置失败时任务不会按成功接入，残留资源保留用于检查，不自动删除存储卷。

k3d 连接作为独立集群保存，安装任务记录宿主机，但容器节点不会被冒充为 SSH 物理主机进行自动关联。现有“添加节点”仍是原生 K3s 安装，不用于扩容 k3d 容器。

## k3d 检测与独立诊断

k3d 保留“安装前检测 → 生成计划 → 开始安装”流程，按其官方要求核对 Docker、runc、累计资源、绑定地址和端口。检测只读，不安装依赖或自动修复；配置变化后重新检测。

K3s 容器镜像来源与 k3d CLI 工具下载分别处理。CLI 仍读取固定版本的官方 GitHub 发布资产并按已登记 SHA-256 校验；国内容器镜像不代表 CLI 下载已切换来源。工具缺失时，预检只发送 HEAD 请求，连接等待 5 秒、单次最多 15 秒，仅对域名解析、连接失败和超时重试一次；单主机检测总时限 65 秒。已有工具则只核对文件、摘要及版本。失败分别显示超时、DNS、连接、安全连接、访问拒绝、文件不存在、请求限流、重定向或本地文件校验原因；检测报告保留原因、退出码及 HTTP 状态，可展开查看实际 curl 命令目标和经脱敏的终端错误；不自动覆盖现有工具。

`POST /api/v1/kubernetes/k3s/preflight` 仍提供独立只读诊断，沿用项目、主机及动作权限，不创建计划、安装任务、锁或加入凭据。原生创建及添加节点的正常页面和后台安装均不调用此接口或依赖其报告。

## 原生模式的默认与自定义安装

创建集群的默认安装使用参数目录对应的固定 K3s 版本和 K3s 默认设置，部署为系统服务。给已有集群添加节点时，默认安装版本跟随目标 K3s 集群的实际版本。EDO 会加入节点识别标签、API 证书名称和连接所需配置，并将 kubeconfig 文件权限固定为 `0600`。

自定义安装提供分组搜索和类型化控件，包含 Server、Agent 和安装器选项。选项目录固定于 `v1.37.1+k3s1`，来自该版本的官方 CLI 和安装器源码；切换其他版本或安装频道时，需要核对参数兼容性。连接凭据、配置文件位置以及与创建运行中集群不兼容的恢复或安装器生命周期参数会标明适用限制。

覆盖框接受以下三个范围，优先级高于表单选择。布尔值 `false` 和空列表 `[]` 会保留，`null` 表示去掉该项并恢复 K3s 默认行为。同一个列表会整体替换，不会自动追加。

```yaml
server:
  https-listen-port: 7443
  cluster-cidr: 10.52.0.0/16
  service-cidr: 10.53.0.0/16
  cluster-dns: 10.53.0.10
  disable:
    - traefik
  secrets-encryption: true
agent:
  node-label:
    - workload=batch
installer:
  version: v1.37.1+k3s1
```

覆盖框还可填写参数目录之外的原生配置键，预览会标明未收录的选项，由实际安装版本校验。参数名使用小写字母、数字和连字符；值限标量或同类型标量列表。EDO 管理的连接和凭据字段仍由安装计划生成。

## 添加节点

进入目标集群的“集群节点”，点击“添加节点”，选择 Master 或 Worker 和新的 SSH 主机。Worker 使用 Agent 选项，可一次选择最多 20 台；Master 使用 Server 选项，每个计划只加入 1 台，同一集群连接的加入任务串行执行。预览确认后安装，等待节点就绪并建立主机关联。两种方式均需要 `kubernetes.node.create`、`cluster.execute`、`cluster.update` 和主机读取权限；启用集群 RBAC 映射时还需相应的集群级节点创建授权。

安装计划会显示最终安装版本和目标集群版本。未指定版本时使用目标集群的精确版本；自定义安装也需使用固定版本，并校验与目标集群的版本偏差。执行前若目标版本发生变化，需要重新预览。参数目录的版本仅表示选项来源，不会让旧集群默认安装更新的 Agent。版本范围依据 [Kubernetes 版本偏差策略](https://kubernetes.io/releases/version-skew-policy/)。

Master 必须显式输入完整安全格式的 Server Token。EDO 使用严格 CA 与令牌校验实时核对目标 K3s 控制平面、嵌入式 etcd 成员和关键配置，不额外从主机探测 etcd 网络。仅放行验证通过的嵌入式 etcd 集群；SQLite 不会被自动转换，外置或未知数据存储会被阻断。Server Token 与独立 Agent Token 不通用；无法读取目标关键配置时不能继续。

Master 的安装版本必须与目标集群精确一致，关键配置由已验证的目标配置继承。初始化、重置、拆分控制平面以及未经核验的原始 etcd/控制组件参数不能用于加入 Master。预览后目标版本、成员或关键配置变化，需要重新预览；开始执行前仍核对快照，成功需确认节点 Ready、Master 与 etcd 角色，并验证原成员保留且新增成员对应当前主机。两成员集群会提示仲裁风险，建议规划最终为 3 或 5 个控制平面成员。

Master 同样直接执行官方安装脚本，传递已确认的目标版本和加入配置。二进制下载、校验和 SELinux 策略由官方安装器处理，EDO 不再自行暂存二进制或要求预装策略包。

Server Token 仅保存在加密计划快照，预览、日志和返回对象不回显；安装通过标准输入传输，在目标主机以受限文件权限写入配置。EDO 不从现有主机读取长期 Server Token。角色切换、关闭或项目变化会清理表单中的凭据。

“生成加入命令”保留原有的手动 K3s/kubeadm 加入方式。Worker 自动安装继续使用本次操作的短期加入令牌，完成或失败后撤销。原有 `agent_host_ids` 请求仍兼容 Worker；新接口统一使用 `join_role`、`join_host_ids`，Master 另需 `server_token`。

## 任务与失败处理

模式、目标主机及配置保存在安装计划与任务快照中。k3d 的 CLI、所选镜像和可解析的 K3s 精确版本随计划固定；CLI 支持版本变化时，旧计划须重新预览，不静默换版本执行。已有历史记录缺少模式时显示原生 K3s；模式选择不是对既有集群的原地切换。替换集群前需单独确认准确目标，盘点工作负载和存储并备份，再安排卸载与重建；本功能不会自动删除旧 k3d、原生 K3s 或其卷。

安装任务和脱敏进度保存在数据库中，关闭抽屉后仍继续执行。再次打开创建或节点安装入口，可在“最近安装任务”查看进度和结果。任务通过主机锁和执行租约避免同一台主机被重复安装；进程中断后会标记结果，需检查主机实际状态后重新操作。

卸载结果页只展示主机、结果、总耗时和日志，删除任务编号、起止时间、任务详情和历史区块，不重复主机卡片、阶段耗时或最近反馈。日志可滚动和键盘浏览。“卸载记录”只在返回后的来源选择视图提供。运行中仍显示当前真实阶段与后台执行提示，失败和结果未确认原因直接显示。

安装和添加节点按真实反馈展示检查、下载与校验、配置、官方安装器、系统服务、API、节点及组件验收等阶段，并显示总耗时和当前阶段耗时。仅识别已登记的 EDO 阶段与官方安装器固定状态行，不透传远端原文；长阶段每 30 秒记录仍在等待的状态，不据此声称健康或完成，不估算百分比。日志按完整行保留最近 64 KiB，截断时保留标记。查看日志不会强制滚动，可用“查看最新”定位末尾；网络中断按有上限的退避重新读取，任务不依赖页面轮询继续运行。

整体后台任务沿用 45 分钟上限，不另外设置服务启动阶段时限，不增加瞬时服务或看门狗，不接管官方脚本的安装与服务启动。任务连接超时或中断会记录失败并保留现场，不能据此声称远端安装命令或 K3s 服务已经停止；重试前须核对实际状态，不自动清锁、重启或卸载。数据库进度无法可靠保存时中断执行，不把未记录的结果冒充成功。已完成、失败或等待其他主机的阶段停止计时。

“移除节点”只删除通过安全检查的 Kubernetes Node 记录，按同步请求显示提交中、失败原因或最终成功结果，并保留既有操作审计；不会卸载 K3s 或清理主机磁盘。当前没有从集群列表删除连接并自动卸载 K3s 的功能。

一台主机只能属于一个集群。原生 K3s 与 k3d 创建、节点加入、集群关联及主机编辑均拒绝覆盖已有的其他集群归属；检测/预览、执行前及保存事务重新核对 EDO 记录，不额外操作远程主机。同一集群的控制平面仍可兼任 Worker，一个集群可有多台主机。官方卸载成功解除归属后可再次安装。

## 官方卸载

在主机操作菜单选择“卸载 K3s”，选择该主机对应的原生安装记录，再预览卸载计划。安装失败但已生成官方脚本的主机也需要走这条独立流程；不自动把失败记录当作可以安全删除的依据。k3d 不使用原生 K3s 的卸载脚本。

卸载直接使用 [K3s 官方卸载说明](https://docs.k3s.io/zh/installation/uninstall) 中由安装器生成的 Server 或 Agent 脚本。默认脚本分别为 `/usr/local/bin/k3s-uninstall.sh` 和 `/usr/local/bin/k3s-agent-uninstall.sh`。EDO 不另写停止服务、解除挂载、清理网络或删除数据的流程，不覆盖卸载脚本的环境，也不把旧计划的数据目录注入脚本。

EDO 只核对来源安装记录、所选主机和默认脚本目标，并冻结该主机上卸载脚本及其官方 killall 脚本的文件身份，确认后发生变化须重新预览。仅接受 root 所有、无符号链接和非组/其他用户可写的普通脚本文件，不因官方脚本版本更新而要求匹配旧版本的全文件摘要。EDO 的安装任务锁仍避免与安装并行。

正常 Pod 挂载、CNI、iptables、Docker 和 Tailscale 都由用户与官方脚本管理，EDO 不增加对应探测或拦截；用户安装后对 K3s 配置、代理环境和系统服务的正常修改也不作为卸载阻断项。OpenRC 不再被 EDO 的 systemd 检查排除，服务管理交给官方脚本。当前入口仍需可核对的 EDO 原生安装记录及默认脚本目录；自定义脚本目录或无法定位准确脚本的安装不会猜测目标。

运行官方卸载脚本会停止该主机上的 K3s 和 Pod，永久删除本地集群数据与本地持久卷数据。外部存储不由该流程删除。操作前应自行确认业务、存储及备份；删除 EDO 连接记录或 Kubernetes Node 记录不等于卸载，官方卸载成功并验证后，自动移除该主机的 EDO 集群关联；没有其他关联主机时同时移除集群连接及该连接的本地授权映射。其他节点仍有关联时保留连接。安装与卸载历史、主机记录及 SSH/Docker 能力均保留，不访问集群 API 清理资源。卸载或验证失败时不移除连接；记录清理失败单独提示，无需再次运行卸载。

该入口需要独立项目权限 `kubernetes.k3s.uninstall` 以及 `cluster.read`，普通安装、节点创建、连接测试和内置项目角色模板不会自动获得此能力。管理员需在角色权限中明确授权；个人拒绝、项目及部门边界继续生效。助手不提供卸载或其他删除工具。

预览核对源安装记录、目标主机、Server/Agent 角色、安装时的服务与数据目录，以及当前官方脚本身份，随后进入二次确认。页面展示“官方卸载会停止 K3s 和本机 Pod，永久删除本地集群数据、本地持久化卷及相关工具。”以及“卸载成功后移除此主机的集群关联；没有其他关联主机时移除集群连接。请先确认备份；外部存储的数据不在此卸载范围内。”用户必须手动输入精确的“我已确认卸载”后才能点击“确认卸载”；旧口令“确认”、空值、前后空格或其他字词均不能代替，前后端均校验。计划限时有效，执行前和后台阶段重新检查当前权限、主机连接及脚本身份，变化后必须重新预览；不能通过安装接口绕过卸载确认。

提交后在后台原样执行选定的官方卸载脚本，抽屉显示阶段、安全日志和结果。脚本必须正常退出，EDO 再只读核对准确目标的卸载脚本已移除；不会要求所有主机进程、服务和目录消失，更不会为验收补执行清理命令。进入卸载执行阶段后发生超时、断连、撤权或结果未确认，保留主机任务锁并明确显示结果未确认；尚未执行的检查失败不会冒称执行过卸载。不自动重放、不清除不明任务锁，也不运行补救命令。

## k3d 主机失联时的手动卸载

在“主机与集群 → 集群”中，打开对应集群的更多菜单，选择“k3d 手动卸载指引”。此入口只读取 EDO 保存的安装记录，不连接旧 IP，不要求 Kubernetes API 可用。需要 `cluster.read` 和独立的 `kubernetes.k3s.uninstall` 权限。

指引显示原安装主机、安装时地址和实际 k3d 名称。登录原主机的新地址，在安装时使用的 Docker 环境中先运行 `k3d cluster list` 核对名称；本地隔离 Docker 的集群需进入对应 Docker 环境，不能使用另一个 Docker 实例。存在安装时 Docker ID 的记录还会显示其身份及核对命令。

输入精确的“我已确认卸载”后，可复制由该安装记录生成的官方 `k3d cluster delete '<实际名称>'` 命令。主机须能运行 k3d CLI，且当前账号具有 Docker 操作权限；找不到 CLI 时可通过弹窗中的官方安装链接安装。不会生成 `--all`、`docker rm` 或自制清理脚本，也不依据用户可修改的集群显示名称猜测资源名。

官方命令会停止并删除该集群的容器、专用网络及本地卷数据。宿主机挂载目录和外部存储不由此指引清理。获取或复制命令不会执行卸载、创建后台任务、解除主机占用或自动移除 EDO 连接，手动执行也不会被 EDO 自动记为卸载成功。

只读接口：`GET /api/v1/kubernetes/k3s/manual-uninstall-guide?cluster_id=<连接 ID>`。连接不存在、属于其他项目或无法唯一核对 k3d 安装快照时不返回删除命令。官方依据：[k3d cluster delete](https://k3d.io/stable/usage/commands/k3d_cluster_delete/)。

## 安装结果验收

原生新建集群的成功条件包括：官方安装器正常退出、实际二进制与 API 的版本符合安装计划、systemd 服务处于 active/running 且 enabled（OpenRC 则须运行并加入默认运行级别）、所有本次节点 Ready 且身份正确，以及应启用的 CoreDNS、metrics-server、local-path-provisioner 完成 Deployment 就绪检查。明确禁用的组件不纳入等待；添加节点不以既有集群的全部系统组件状态作为本次新建门槛。组件启动允许在有界时限内等待，权限撤销或资源身份变化立即终止。

任何必要步骤失败、超时或进度无法可靠保存，都必须标记任务失败并保留现场。不能因为 API 可连接、某个节点 Ready 或人工补命令后恢复，就把原失败任务改称成功。阶段状态独立保存，日志区展示经脱敏的真实执行输出：原生安装保留官方脚本的标准输出、标准错误及 systemd 启动日志；k3d 使用官方 `--verbose` 输出镜像分层拉取进度，并读取本次容器的启动日志。读取前核对安装及集群标签，再按不可变容器 ID 执行 `docker logs`，不额外拉取镜像或管理服务生命周期。日志读取中断会提示，不能替代真实安装验收。

执行日志每 500 毫秒批量保存，任务保留最近 2 MiB 完整行，超长单行省略；关闭、刷新后从任务恢复。日志保留真实下载、启动与错误文本，过滤内部控制帧、终端控制符和密码、令牌、私钥及 kubeconfig 认证内容。浏览到旧行时追加日志不改变阅读位置，可通过“查看最新”恢复跟随。原生服务管理器没有 journalctl 时继续展示官方安装器输出。

若控制平面已经接入、后续工作节点失败，保留已创建的集群和成功节点，可进入该集群处理剩余节点。失败处理不会自动卸载或清除主机上的 Kubernetes 数据。

安装计划十分钟内有效，执行前会重查当前账户权限、主机连接和集群配置。安装命令、预览、日志及 API 响应会隐藏登录密码、令牌、kubeconfig 和配置中的敏感值。

官方参数来源：[Server](https://github.com/k3s-io/k3s/blob/v1.37.1%2Bk3s1/pkg/cli/cmds/server.go)、[Agent](https://github.com/k3s-io/k3s/blob/v1.37.1%2Bk3s1/pkg/cli/cmds/agent.go)、[安装器](https://github.com/k3s-io/k3s/blob/v1.37.1%2Bk3s1/install.sh)。

## 上一次失败日志与新建状态

创建集群和添加节点抽屉不再提供“最近安装任务”列表，只在配置页默认收起展示“上一次安装失败日志”。服务端先按当前项目、操作者、动作及目标集群筛选失败记录，再按自增 ID 取最新一条；不会用最近十条任务中是否包含失败来推断。历史只显示有界纯文本日志，不带入当前步骤、状态、配置或管理入口。

本次任务结束后关闭重开会返回安装配置；本次真实运行中的安装仍可关闭后继续查看。已移除集群的历史 UUID 保留用于追溯，接口不再据此生成管理链接。历史任务、日志及审计记录均保留。

原生 K3s 表单不再展示同机 Worker 的重复说明、默认配置介绍卡片、containerd 与安装版本小字，以及确认后执行官方脚本的重复文案。实际版本仍可在自定义配置中选择，并在安装确认计划中核对。
