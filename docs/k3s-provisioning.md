# 创建 K3s 集群与添加节点

在“基础设施 → 主机与集群 → 集群”点击“创建集群”，选择已保存的 SSH 主机。已有集群仍通过“接入集群”导入 kubeconfig。

## 创建集群

先选择安装模式，默认使用原生 K3s。已有请求未携带 `mode` 时继续按原生模式处理，不改变已有安装计划的含义。

| 模式 | 运行位置 | 安装前提 | 适用范围 |
| --- | --- | --- | --- |
| 原生 K3s | Linux 主机的 systemd/OpenRC 系统服务 | SSH、root/sudo、所需资源与网络 | 默认方式，可跨物理主机安装控制平面和工作节点 |
| k3d | 单台 Linux SSH 宿主机的 Docker 容器 | 已运行的本机 Docker、所需资源、明确的 API 绑定 IPv4 与空闲端口 | 隔离测试，1 个控制平面容器及 0–8 个工作节点容器；不代表物理机高可用 |

两种模式切换后必须重新检查、预览。k3d 不接收原生 Server、Agent、安装器及 YAML 覆盖参数，不会自动转换已有集群或迁移工作负载与数据。

### 原生 K3s

1. 填写集群名称，选择一台控制平面主机，可同时选择多台工作节点主机。
2. API 地址留空时，根据控制平面主机地址和最终的 HTTPS 监听端口生成；填写自定义地址时，需确保 EDO 和新节点均可访问。
3. 选择安装下载源与系统镜像源，再选择“默认安装”或“自定义安装”，点击“检查并预览安装计划”。
4. 检查逐台主机的前置检查报告、最终配置、安装命令和影响，再点击“开始安装”。
5. EDO 在后台调用官方安装器，读取并加密保存 kubeconfig，接入集群并关联身份核验通过的 Ready 节点。关闭抽屉不影响执行，不需要人工登录主机补命令。
6. 安装完成还需通过精确版本、系统服务运行与开机启动、API 连接及已启用核心组件的就绪验证，全部通过才显示成功。

目标需为已启用、配置登录凭据、核对过 SSH 指纹且连接正常的 Linux 主机。非 root 账号需在主机凭据中启用 sudo。创建集群需要主机读取权限，以及 `cluster.create`、`cluster.execute`、`cluster.update`；原生安装会注册节点时，还需 `kubernetes.node.create`，在预览前就核对，不等安装后才报权限不足。k3d 及不注册任何节点的纯控制面不额外要求此节点权限。

在主机编辑页勾选“安装操作使用 sudo”，测试通过后保存。仅有 SSH 能力的主机也可设置，不需要额外启用 Docker；测试会实际验证 root 权限。密码认证复用已保存的登录密码，私钥认证需要免密 sudo。复用已有凭据重测时继续核对原 SSH 指纹；此设置不会让 SSH 部署脚本自动提权。

安装前会检查全部目标，安装前再次检查当前主机。已有 Kubernetes 安装、配置或服务的主机应通过接入方式管理。预加载 K3s 二进制的安装方式会核对指定版本，并继续检查已有配置和服务。

安装复用 [K3s 官方快速入门](https://docs.k3s.io/zh/quick-start)的原版安装器，以固定版本及计划内参数安装系统服务，不通过 Docker/k3d 容器安装。配置保存在 `/etc/rancher/k3s/config.yaml`，安装完成后读取 `/etc/rancher/k3s/k3s.yaml` 接入 EDO；凭据不进入日志。

EDO 只包装主机选择、权限与配置传递、后台任务和结果验收，不自行实现 K3s 安装器。下载官方脚本后再执行，与快速入门使用同一安装器；不会改成自行创建 K3s 二进制或系统服务。需要明确的精确版本，不能只指定一个会变化的频道后把未知版本安装视为成功。

### 安装下载源与系统镜像源

原生 K3s 的默认安装和自定义安装都可选择来源，创建集群与添加节点使用相同的下载源规则。两类来源相互独立：

- 安装下载源默认使用 `https://get.k3s.io` 和官方 GitHub 发布制品。国内选项使用官方快速入门推荐的 `https://rancher-mirror.rancher.cn/k3s/k3s-install.sh`，向未修改的脚本传入 `INSTALL_K3S_MIRROR=cn` 与带 HTTPS 的镜像站地址。固定版本的校验文件和二进制也从该站下载，失败不会偷偷回退到另一来源。
- 系统镜像源默认使用 K3s 自身的默认值。国内选项使用 Rancher 中文社区提供的 `registry.cn-hangzhou.aliyuncs.com`，也可填写无协议、无账号密码的自定义仓库前缀。该值通过 K3s 官方 `system-default-registry` 配置影响 Pause、DNS、存储、指标等系统镜像，不会把应用镜像改为这个仓库，也不修改 Docker 的镜像源或宿主机代理。

仅切换下载源不能解决 Docker Hub 的 Pod 镜像拉取超时。国内资源也可能同步延迟或缺少某些版本，不能把国内选项描述成保证成功。预检会检查所选下载源和系统镜像仓库的 HTTPS 连通性；仓库返回认证挑战仅代表可访问，不代表登录成功，也不证明全部镜像 Tag、平台和数据层可拉取。最终仍以实际服务、节点和系统组件就绪为准。

加入现有集群时只选择新节点的安装下载源，系统镜像仓库由原控制平面继承，不在添加节点时改变整个集群。创建时若上方系统镜像源与高级配置中的同一字段不一致，会拒绝计划；国内下载源不接受中国安装器不支持的自定义制品下载地址。

确认计划与安装记录展示本次实际采用的来源，来源改变后须重新预检。旧记录未保存来源时显示未记录，不根据当前表单猜测历史来源。既有集群换源属于单独维护操作，不能因此把原失败安装任务改成成功。

来源与行为参考：[官方快速入门](https://docs.k3s.io/zh/quick-start)、[Rancher 中文国内资源教程](https://forums.rancher.cn/t/k3s/3314)、[K3s 系统镜像参数](https://docs.rancher.cn/docs/k3s/installation/install-options/server-config/)。

### k3d

选择一台 SSH 宿主机、工作节点容器数量（默认 1）、API 绑定 IPv4 与端口（默认 `16443`，允许 `1024–65535`）。绑定地址必须是目标机器实际可用、EDO 可访问的 IPv4，不能填写 `0.0.0.0`、回环地址，或把公网 SSH 转发地址误当成 NAS 的本机 IP。k3d v5.9.0 的 API 端口参数不支持 IPv6，本模式会提前拒绝；不影响原生 K3s。预检会核对本机 Linux Docker Engine（至少 `20.10.5`）、绑定地址、端口及总资源；不会自动关闭防火墙、安装 Docker 或重启 daemon。

平台调用固定版本的官方 k3d CLI，不自行拼装 Docker 集群。工具独立保存在 `/var/lib/edo/k3d/v5.9.0/`，核对官方发布的 SHA-256，不覆盖全局 k3d。集群使用本次安装 UUID 生成独立名称，不覆盖宿主机默认 kubeconfig 或切换其默认 context，也不接管已有同名集群。预览会显示最终版本与真实命令。

控制平面容器内存限制为 2 GiB，工作节点每个为 1 GiB；创建后为本次集群的准确容器补充 CPU 限制（控制平面 2 核、工作节点 1 核）和禁用额外 Swap。官方 CLI 不提供创建时 CPU 限额，因此容器启动到补充限制之间存在短暂窗口；不承诺创建全过程已有 CPU 硬限制。限制设置失败时任务不会按成功接入，残留资源保留用于检查，不自动删除存储卷。

k3d 连接作为独立集群保存，安装任务记录宿主机，但容器节点不会被冒充为 SSH 物理主机进行自动关联。现有“添加节点”仍是原生 K3s 安装，不用于扩容 k3d 容器。

## 前置检查

创建或添加控制平面（Master）和安装工作节点（Worker）共用实时预检流程。预览通过固定指纹的 SSH 连接执行只读检查；阻断项未通过时，不保存可执行计划、不创建加入令牌，也不安装或自动修复主机。报告按集群和主机展示通过、提示、阻断及原因，修改配置后必须重新检查。

原生模式检查 Linux 与支持的 CPU 架构、root/sudo 权限、基础命令、运行中的 systemd/OpenRC、内存 cgroup、角色所需 CPU 和内存、数据盘可用空间与只读挂载、现有 Kubernetes 配置/服务/进程及安装锁、最终配置需要的本地 TCP 端口、安装源 HTTPS 访问，以及新节点到目标 API 的可信 HTTPS 连接。目标集群 CA 每次从当前集群连接读取，证书检查不通过会阻断。创建集群时尚不存在的 API 会标记待检查，在工作节点安装前完成验证。k3d 使用上文单宿主机 Docker、累计资源及地址检查，不要求宿主机安装原生 K3s 系统服务。

主机身份比较复用主机关联验证：硬件 UUID、启动 ID、Machine ID 和有效地址依次用于排除同一机器的重复记录及已有集群成员；同时检查真实节点名称、自定义 `node-name` 和同批重名。目标成员列表在 SSH 检查完成后通过 Kubernetes API 实时分页读取，不使用 Watch 缓存；无法读取完整节点列表时阻断添加节点。

原生模式的资源与网络要求参考 [K3s 官方安装要求](https://docs.k3s.io/installation/requirements)。EDO 当前按控制平面至少 2 核、2 GiB 内存，工作节点至少 1 核、512 MiB 内存检查。数据目录空闲空间采用 EDO 安装策略：控制平面至少 5 GiB，工作节点至少 2 GiB；低于建议的 10/5 GiB 时提示另行评估工作负载。Swap、SELinux 和防火墙会提示核对，不会自动关闭；UDP/CNI 双向连通性不作为已验证结果。

内置 containerd 默认使用 OverlayFS。预检只读识别最终数据目录所在的文件系统，发现 OverlayFS、网络文件系统等明确不兼容的后端时阻断安装，避免服务长期停在启动中。NAS 根目录可能本身就是 OverlayFS；这时应在自定义安装中将 `data-dir` 设为兼容的数据卷目录，或明确选择适用的快照方式，EDO 不会静默改配置。无法识别的文件系统、外部运行时和非默认快照方式显示待核验提示，不把配置值存在当成运行成功。文件系统类型检查不替代最终服务、API、节点和组件验收。参数与限制参考 [K3s Agent 配置](https://docs.k3s.io/cli/agent)及[官方项目关于 OverlayFS 数据目录的说明](https://github.com/k3s-io/k3s/discussions/12680)。

安装任务启动后重新检查全部候选主机，每台主机安装前再检查一次。下载完成后、写配置之前继续复查已有安装及锁，防止预览后环境变化覆盖现有配置。旧版本生成、缺少本次预检记录的计划需要重新预览。

## 原生模式的默认与自定义安装

创建集群的默认安装使用参数目录对应的固定 K3s 版本和 K3s 默认设置，部署为系统服务。给已有集群添加节点时，默认安装版本跟随目标 K3s 集群的实际版本。EDO 会加入节点识别标签、API 证书名称和连接所需配置，并将 kubeconfig 文件权限固定为 `0600`。

自定义安装提供分组搜索和类型化控件，包含 Server、Agent 和安装器选项。选项目录固定于 `v1.37.1+k3s1`，来自该版本的官方 CLI 和安装器源码；切换其他版本或安装频道时，需要核对参数兼容性。连接凭据、配置文件位置以及与创建运行中集群不兼容的恢复或安装器生命周期参数会标明适用限制。

覆盖框接受以下三个范围，优先级高于表单选择。布尔值 `false` 和空列表 `[]` 会保留，`null` 表示去掉该项并恢复 K3s 默认行为。同一个列表会整体替换，不会自动追加。

```yaml
server:
  https-listen-port: 7443
  cluster-cidr: 10.52.0.0/16
  service-cidr: 10.53.0.0/16
  cluster-dns: 10.53.0.10
  disable:
    - traefik
  secrets-encryption: true
agent:
  node-label:
    - workload=batch
installer:
  version: v1.37.1+k3s1
```

覆盖框还可填写参数目录之外的原生配置键，预览会标明未收录的选项，由实际安装版本校验。参数名使用小写字母、数字和连字符；值限标量或同类型标量列表。EDO 管理的连接和凭据字段仍由安装计划生成。

## 添加节点

进入目标集群的“集群节点”，点击“添加节点”，选择 Master 或 Worker 和新的 SSH 主机。Worker 使用 Agent 选项，可一次选择最多 20 台；Master 使用 Server 选项，每个计划只加入 1 台，同一集群连接的加入任务串行执行。预览确认后安装，等待节点就绪并建立主机关联。两种方式均需要 `kubernetes.node.create`、`cluster.execute`、`cluster.update` 和主机读取权限；启用集群 RBAC 映射时还需相应的集群级节点创建授权。

安装计划会显示最终安装版本和目标集群版本。未指定版本时使用目标集群的精确版本；自定义安装也需使用固定版本，并校验与目标集群的版本偏差。执行前若目标版本发生变化，需要重新预览。参数目录的版本仅表示选项来源，不会让旧集群默认安装更新的 Agent。版本范围依据 [Kubernetes 版本偏差策略](https://kubernetes.io/releases/version-skew-policy/)。

Master 必须显式输入完整安全格式的 Server Token。EDO 使用严格 CA 与令牌校验实时核对目标 K3s 控制平面、嵌入式 etcd 成员和关键配置，检查新节点的 etcd 网络连通性。仅放行验证通过的嵌入式 etcd 集群；SQLite 不会被自动转换，外置或未知数据存储会被阻断。Server Token 与独立 Agent Token 不通用；无法读取目标关键配置时不能继续。

Master 的安装版本必须与目标集群精确一致，关键配置由已验证的目标配置继承。初始化、重置、拆分控制平面以及未经核验的原始 etcd/控制组件参数不能用于加入 Master。预览后目标版本、成员或关键配置变化，需要重新预览；下载脚本后也重新核对，成功需确认节点 Ready、Master 与 etcd 角色，并验证原成员保留且新增成员对应当前主机。两成员集群会提示仲裁风险，建议规划最终为 3 或 5 个控制平面成员。

Master 的官方安装脚本与精确版本二进制会先暂存并核对校验和及版本，下载完成后再检查目标和主机，最后才写安装配置；不会覆盖期间出现的既有二进制或配置。已启用 SELinux 的主机须预先安装 K3s SELinux 策略，缺失时阻断，不会自动安装策略包或关闭 SELinux。

Server Token 仅保存在加密计划快照，预览、日志和返回对象不回显；安装通过标准输入传输，在目标主机以受限文件权限写入配置。EDO 不从现有主机读取长期 Server Token。角色切换、关闭或项目变化会清理表单中的凭据。

“生成加入命令”保留原有的手动 K3s/kubeadm 加入方式。Worker 自动安装继续使用本次操作的短期加入令牌，完成或失败后撤销。原有 `agent_host_ids` 请求仍兼容 Worker；新接口统一使用 `join_role`、`join_host_ids`，Master 另需 `server_token`。

## 任务与失败处理

模式、目标主机及配置保存在安装计划与任务快照中。k3d 的 CLI 与 K3s 精确版本也随计划固定，EDO 升级后若支持版本发生变化，旧计划须重新预览，不静默换版本执行。已有历史记录缺少模式时显示原生 K3s；模式选择不是对既有集群的原地切换。替换集群前需单独确认准确目标，盘点工作负载和存储并备份，再安排卸载与重建；本功能不会自动删除旧 k3d、原生 K3s 或其卷。

安装任务和脱敏进度保存在数据库中，关闭抽屉后仍继续执行。再次打开创建或节点安装入口，可在“最近安装任务”查看进度和结果。任务通过主机锁和执行租约避免同一台主机被重复安装；进程中断后会标记结果，需检查主机实际状态后重新操作。

原生新建集群的成功条件包括：官方安装器正常退出、实际二进制与 API 的版本符合安装计划、systemd 服务处于 active/running 且 enabled（OpenRC 则须运行并加入默认运行级别）、所有本次节点 Ready 且身份正确，以及应启用的 CoreDNS、metrics-server、local-path-provisioner 完成 Deployment 就绪检查。明确禁用的组件不纳入等待；添加节点不以既有集群的全部系统组件状态作为本次新建门槛。组件启动允许在有界时限内等待，权限撤销或资源身份变化立即终止。

任何必要步骤失败、超时或进度无法可靠保存，都必须标记任务失败并保留现场。不能因为 API 可连接、某个节点 Ready 或人工补命令后恢复，就把原失败任务改称成功。任务只保留固定中文阶段及数值退出码等安全诊断，不保存可能带令牌的安装器原始输出。

若控制平面已经接入、后续工作节点失败，保留已创建的集群和成功节点，可进入该集群处理剩余节点。失败处理不会自动卸载或清除主机上的 Kubernetes 数据。

安装计划十分钟内有效，执行前会重查当前账户权限、主机连接和集群配置。安装命令、预览、日志及 API 响应会隐藏登录密码、令牌、kubeconfig 和配置中的敏感值。

官方参数来源：[Server](https://github.com/k3s-io/k3s/blob/v1.37.1%2Bk3s1/pkg/cli/cmds/server.go)、[Agent](https://github.com/k3s-io/k3s/blob/v1.37.1%2Bk3s1/pkg/cli/cmds/agent.go)、[安装器](https://github.com/k3s-io/k3s/blob/v1.37.1%2Bk3s1/install.sh)。
