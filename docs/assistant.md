# EDO 助手

助手先解决两类日常问题：在当前项目中查应用、流水线和运行资源；根据真实运行记录解释失败原因，并让用户在看清影响后决定是否重试或停止流水线。

当前覆盖排障、草稿规划、受控部署、说明与历史检索。创建、启用、部署分别确认。目前没有真实模型 API Key；业务服务测试和模拟对话不代表真实模型已联调。

助手默认关闭，管理员可在“系统设置 → 助手设置”启用。Agent 助手处于开发测试阶段，请勿过于相信 AI；回答和操作内容需要自己核对。

点击页面右下角的对话气泡打开助手，页面仍可正常操作。最小化后保留对话和未发送的输入，切换页面可以继续使用；切换项目后重新加载该项目的会话。管理员可在“系统设置 → 助手设置”关闭助手，保存后隐藏入口并关闭当前对话窗口。

## 本次范围：V1

### 配置模型

管理员在系统设置中填写兼容 OpenAI 接口的服务地址、模型 ID 和 API Key。Eino ADK 用于组织对话与工具调用，模型通过独立适配层接入，业务权限和操作确认由 EDO 自己处理。使用 Eino 不表示必须使用某一家模型，也不表示所有声称兼容 OpenAI 的服务都已通过验证。

可以先保存地址和模型作为草稿，之后再由管理员填写 API Key。没有 Key 或尚未启用时，助手明确显示未配置或未启用，禁用发送消息，不返回预设的排障结论。

API Key 复用 EDO 的加密存储，不回显原文；编辑其他字段时保留已有密钥，替换和清除必须是明确操作。普通项目成员不能读取或修改平台模型配置。连接测试使用当前填写的配置向真实模型服务发起请求，成功和失败均以真实响应为准；失败时对外显示安全的中文原因，原始错误只进入脱敏系统日志。连接测试不等于工具能力已经验收，正式启用仍需确认目标模型支持本次使用的流式响应和工具调用。

### 对话与查询

会话按用户和项目隔离。切换项目不会把原项目的历史消息、工具结果或待确认操作带入新项目；其他用户不能靠会话 ID 访问历史，即使拥有同项目的业务权限。服务端使用 SSE 推送工具状态、确认卡片和经过脱敏的回复片段，断线不能继续触发新的操作。为避免密钥恰好跨越模型输出片段而泄露，当前可能在收齐一整段回复并脱敏后才显示，不承诺逐 token 输出。

V1 的查询工具只读取当前用户有权访问的内容：

- 按名称或 ID 定位应用、主机、集群和域名，查看启用状态及主机能力。域名登记不等于 DNS 已检查。
- 当前项目最近的流水线运行，可按应用筛选；读取运行状态、固定版本和有限长度的执行日志。
- 应用的部署记录、当前实例状态，以及对应 Docker / Compose 容器最近的日志；读取前核对容器身份，不接受模型指定任意容器 ID。脚本部署不调用可能执行检查命令的状态入口。
- Kubernetes 的工作负载、节点、配置、存储及网络状态、资源事件、Service 端点和 Deployment 版本；Pod 日志支持当前容器和上次退出的容器。先核对集群、命名空间、Pod UID 和容器名，不读取 Secret 或配置内容，也不开放终端。
- 后台任务的状态、尝试次数和脱敏错误，不读取任务参数。
- EDO 自身的运行指标及当前进程内有限的脱敏系统日志。此入口同时要求 `monitor.read` 和独立的平台权限 `assistant.platform.read`，项目角色不能授予后者。系统日志不冒充应用日志。

用户可以直接描述“应用打不开”“发布卡住”“Pod 一直重启”“存储未绑定”等现象。目标不明确时助手先询问，再关联查询；回答区分已查到的事实、可能原因和下一步建议，注明资源、日志或事件的来源。没有读取到的数据明确留空，日志被截断或指标不可用时不补结论。排障不会自动重启服务、修改配置或删除资源，处理建议不表示问题已经修复。

日志每次最多请求最近 100 行，读取上限为 64 KiB，再脱敏并保留至多 8 KiB 发给模型；不持续监听。单次诊断有超时，关联资源也限制数量。没有 Key 时上述工具不会通过对话调用，真实模型的工具选择与排障质量需要配置后单独验收。

工具不接收模型指定的用户身份，也不因为模型给出另一个项目 ID 就切换范围。每次调用都重新检查登录状态、项目成员资格、动作权限和目标归属。运行中的长连接同样复核权限，撤销成员或权限后不得继续返回新数据。空结果、权限不足、数据过期和读取失败应分别表达，不能用猜测补齐状态。

模型回答是对这些结果的解释，不是执行结果。界面保留工具来源和调用状态，便于用户区分真实查询、助手推断和尚未验证的建议。

### 重试与停止流水线

V1 只允许准备“重试这次失败运行”和“停止这次未结束运行”两种操作。模型只能提出操作建议和生成待确认项，不能执行确认接口，也不能把用户在聊天里说“确认”当作最终授权。

确认卡片需要展示应用、流水线、原运行、固定版本、操作内容和影响。重试会创建新运行，不覆盖原记录；沿用原运行固定的 Ref 和 Commit，并由现有流水线规则处理本次有效配置、审核和任务。停止只停止流水线后续推进，不等于停止已部署应用，也不会自动撤销已经提交到目标环境的操作。

只有用户明确点击卡片上的确认按钮，浏览器才提交确认 ID。后端必须执行以下检查，不能以系统提示词或前端按钮状态代替：

1. 确认记录绑定发起用户、项目、会话、允许的动作、目标运行、参数、相关快照和有效期；不接受客户端在确认时替换动作或参数。
2. 确认前重新检查用户身份、项目成员资格、执行权限、目标归属及最新运行状态。运行或相关配置发生影响操作的变化时，旧确认失效，重新展示影响。
3. 用数据库条件更新原子领取待确认项，阻止重复点击、并发确认和过期重放。确认结果单独保存；网络断开后重查状态，不能盲目再次执行。
4. 复用现有流水线服务、NATS 任务、并发保护及审计，不建立由模型直接执行的旁路。失败不自动扩大操作范围，也不自动改成另一个目标。

审计区分建议、用户确认、后端受理和最终执行结果，记录操作者及项目、运行和确认记录的关联信息。接受停止请求不能显示为已经停止，创建重试运行也不能显示为发布成功。

## 不开放的能力

删除需求会提供对应管理页的站内链接和操作指引，由用户在页面中核对资源并确认。链接只导航，不预选资源、不提交删除，也不绕过权限、引用检查或保护规则。Kubernetes 需要核对集群和命名空间；存储资源还需先检查绑定及回收策略。未知页面、外部网址和带自动操作参数的链接不会作为可点击入口。

所有阶段都不向助手提供任意 Shell、SQL 或 kubectl 执行；不提供清库、删除存储、强制删除资源、修改 RBAC 或读取密钥原文。用户拥有管理员身份也不使这些工具自动出现。

限制落在工具白名单、参数校验、后端授权及执行服务中。日志、仓库文件、资源注释和模型输出都按不可信内容处理，其中出现的指令不能改变工具权限，也不能生成可自动执行的命令。

## 数据与模型隐私

自托管 EDO 不等于对话不出网。配置外部模型后，用户消息、需要的历史上下文和所调用工具的必要结果可能发送到该模型服务。管理员应先确认服务商的数据留存、训练使用政策和网络可达范围；涉及敏感项目时应选择组织允许的服务或自建兼容接口。

不主动发送全量业务数据、全量日志或整份配置。API Key、Git 凭据、kubeconfig、Secret 内容和其他明文密钥不得进入提示词、工具结果、审计或访问日志。日志和用户输入也可能包含误贴的秘密，不能仅依赖字段名称脱敏；上线前应使用脱敏样本验证，并提醒用户不要在对话中粘贴凭据。

会话、消息和确认记录保存在 EDO 数据库中，备份时同样按业务数据保护。模型服务的留存与本地记录的留存是两件事，本地记录的清理不代表外部服务已经删除对应数据；不要在尚未实现保留策略时承诺自动到期清理。

## V2：草稿、校验与部署

用户可以直接说“给这个仓库创建测试发布流水线”或“部署这个应用”。助手先读取能力目录、当前项目资源和内置模板。仓库、环境、代码版本不明确时继续追问，不按名字猜 ID，也不任取第一个资源。

- 创建：组合已有方案和服务端内置模板；需要时可新建应用、Dockerfile 构建方案、Docker 或 Kubernetes 部署方案。整个计划在事务中校验，预览回滚试写；确认后原子创建，流水线仍为未启用草稿。语言模板要求对应运行镜像已经准备好。
- 启用：重新检查流水线、构建和部署配置，单独确认。启用后匹配的代码事件可能触发任务；启用动作本身不发起部署。
- 部署：必须明确应用、流水线，以及查到的完整 Ref 和 Commit，或当前流水线可用的已有制品。复用原有任务、快照、审核和审计，不跳过审核。受理后提供真实运行记录，不把受理写成部署成功。
- Kubernetes 流水线更新已有 Deployment 的镜像，不直接新建工作负载；需要新建时到 Kubernetes 页面操作，助手不能把创建部署方案说成已经创建集群资源。
- YAML：对单个现有资源检查格式、重复字段、UID、resourceVersion 和集群服务端 dry-run，再展示只读预览。Secret、RBAC、节点和多文档不在此入口处理，不提供直接应用 YAML 的确认按钮。

计划在右侧抽屉展示目标、步骤、参数、检查和影响。五分钟内有效，确认时重查权限和配置；发生变化时必须重新生成。领取记录使用条件更新，重复确认不会重复创建或部署。

重启、停止实例与扩缩容暂未接入助手，避免未经授权中断服务。应用页面已有操作不受影响。助手仍不接受任意脚本、SQL、kubectl、环境变量密钥或宿主机挂载。已有方案中的任务按 EDO 原规则执行，助手不改写为临时命令。

## V3：说明和历史检索

检索来源包括内置 EDO 操作说明、当前项目的应用与方案说明、本人有权查看的历史回复，以及历史失败运行摘要。结果保留来源和时间；旧故障只作对照，排障结论仍要核查实时日志和状态。撤销权限后，历史检索也不再返回对应内容。

当前是有界关键词检索，不是外部知识平台。尚不支持导入文件、网页或向量知识库；需要这些能力时，助手必须明确说明目前还没有这个功能。

## V4：跨资源交付流程

助手可在一个对话中衔接仓库、应用、构建、部署环境、镜像仓库和流水线，安排内置测试、构建、审核及最多五个顺序部署任务。每步根据真实资源和上一步结果继续，不另建模型专用的部署通道。

创建、启用、部署三个确认项相互独立。后续步骤通过确认记录和真实运行查询继续；不会因用户一句“继续”代替按钮确认，也不会在当前请求结束后假装持续监控。已有制品、Kubernetes 发布前提和默认配置仍服从 EDO 的原有校验。

新模型配置默认最多 12 步，可在系统设置中调整到 1–20 步；单次请求最多 40 次工具调用，并继续受超时和输出大小限制。已保存的步骤设置不自动覆盖。

能力清单同时展示可用、缺少权限或服务、不支持的情况。没有的功能必须说明“目前还没有这个功能”，不能编造成功结果或生成命令绕过。新的外部系统接入、外部知识库、任意 YAML 应用和运行实例控制不在当前执行白名单中。

模型选择和版本升级独立进行。候选服务必须分别验证中文排障、流式输出、工具调用、超时取消、数据政策和实际成本；没有真实 Key 时只保留待验证项，不承诺某个模型已经兼容。

## 验收清单

以下是验收项目，不是已经完成的测试结论：

- [ ] 无 Key 可以保存草稿；页面明确显示未配置，不能发送消息，后端同样拒绝发起模型请求。
- [ ] API Key 加密保存且不回显；保留、替换、清除的行为明确；日志和异常响应不泄露密钥。
- [ ] 使用真实 Key 和指定模型完成连接测试、SSE 对话和工具调用；网络错误、模型拒绝、限流及断线取消能安全结束。
- [ ] 不同用户、同部门不同项目、被移除成员和权限撤销场景不能访问越界会话、消息、工具结果或确认记录。
- [ ] 每个查询工具都有真实数据、空结果、无权限、目标越界和后端失败测试；日志受行数和体积限制，Secret 原文不进入模型上下文。
- [ ] 待确认项绑定完整上下文；未点击、跨用户、跨项目、过期、状态变化和参数篡改均不执行。
- [ ] 并发确认或重复请求至多受理一次；重试生成新记录，停止过程显示真实状态，任务和审计可追溯。
- [ ] 提示注入不能获得额外工具、读取凭据或绕过确认；拒绝所有不在白名单内的动作。
- [ ] SQLite、PostgreSQL、MySQL 均完成真实空库迁移、重复迁移和升级验证；涉及会话、消息与确认的数据完整保留。
- [ ] 浅色、深色及窄屏完成页面验收，确认弹窗有提交状态，错误后保留上下文，切换项目不会串会话。

无真实 Key 时可以验证配置保存、加密、权限隔离、确认并发和受控执行等本地行为，也可以通过测试替身覆盖异常分支；这些证据不能替代真实模型的连接、流式协议、工具选择和回答质量验收。

数据库迁移使用 [测试文档](testing.md) 中的独立测试库入口。外部数据库测试会修改表结构并模拟升级，不能指向开发或生产业务库。新增模型同时核查项目范围、项目删除保护，避免只建表而遗漏隔离或结构升级。

## V1 本地验证

本次在只包含助手改动的干净副本中执行 `go test -p 1 ./...`；助手服务、HTTP、权限与流水线增加了配置、隔离、脱敏、撤权、确认并发和重试指纹测试。真实 Eino 与官方模型适配器连接的是本地模拟接口，不是真实模型服务。

SQLite、独立 PostgreSQL 和 MySQL 空库均验证了最终表结构、升级、重复迁移与数据保留。前端 196 项测试和生产构建通过，另以模拟接口检查了浅色、深色、窄屏、英文及抽屉交互。真实 Key 的连接、工具选择和回答质量仍待联调。

只读排障扩展在独立副本完成后端全量测试、相关工具竞争检测、219 项前端测试和生产构建。新增用例覆盖资源定位、部署关联、容器和 Pod 身份核对、日志限长与脱敏、读取期间退出登录、平台排障单独授权，以及 Eino 调用工具后依据日志回复的流程。模型仍为测试替身，不代表真实模型的判断质量已经验收。
