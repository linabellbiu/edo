# Kubernetes

在“基础设施 → 主机与集群 → 集群”中接入集群，通过菜单查看总览、节点、工作负载、配置与存储、服务与网络。集群跟随当前项目空间，切换项目后不会显示其他项目的连接。

## 创建 K3s 集群

点击“创建集群”，选择 SSH 主机及默认或自定义安装方式，预览最终配置后执行安装。支持完整版本参数目录和 YAML 覆盖配置，集群节点页可继续安装工作节点。用法与适用范围见[创建 K3s 集群与添加节点](k3s-provisioning.md)。

## 接入集群

点击“添加集群”，填写名称、默认命名空间，粘贴或导入 kubeconfig，测试连接后保存。关联主机可以留空。EDO 所在机器必须能访问 kubeconfig 中的 API 地址。

kubeconfig 加密保存，不接受 exec 插件、外部证书文件、代理、身份模拟或跳过 TLS 校验。证书和密钥需要直接包含在 kubeconfig 中。不要为了接入 EDO 开放匿名访问。

生产集群建议使用专用 ServiceAccount，按实际需要分配 Kubernetes RBAC。EDO 中的项目角色只控制控制台操作，不能替代集群自身的 RBAC。

## 关联主机

集群可独立接入，关联主机为可选项。每台远程主机可关联一个集群，同一集群可关联多台主机；关联到其他集群时会替换原有关系。内置本地主机不参与关联。

`POST /api/v1/kubernetes/clusters` 可传 `host_ids`，集群与关联关系在同一事务中保存。`PUT /api/v1/kubernetes/clusters/:id/hosts` 使用完整的 `host_ids` 列表替换关联，传空数组解除全部关联，省略字段会返回参数错误。修改关联需要 `cluster.update` 权限，主机和集群必须属于同一项目和部门。

保存关联前，EDO 读取集群节点信息，与主机地址及经 SSH 读取的主机身份核对。不匹配或无法完成核对时拒绝保存，并保留原有关联；创建集群时校验失败也不会留下新集群记录。更换 kubeconfig 时，会重新核对已有的主机关联。只有集群、没有主机时可正常接入。

关联不会自动安装、迁移 Kubernetes 或移动工作负载。解除关联不会删除集群、修改 kubeconfig 或清除主机的 SSH、Docker 能力。集群列表的 `hosts` 提供主机名称、地址和启用状态；未关联主机时返回空数组，没有主机读取权限时返回 `null`。

## 管理入口

| 入口 | 资源与操作 |
| --- | --- |
| 集群总览 | 资源数量、节点就绪情况、CPU 和内存使用环图、Pod 状态分布；点击数量进入资源列表 |
| 集群节点 | 查看条件、地址、版本、可分配资源和实际用量；修改标签和污点；停止、恢复调度；生成加入命令、移除离线工作节点 |
| 工作负载 | Deployment、StatefulSet、DaemonSet、Job、CronJob、Pod；创建、更新镜像、删除；扩缩容、滚动重启、暂停定时任务；Pod 日志和终端 |
| 配置与存储 | Namespace、ConfigMap、Secret、PVC、PV、StorageClass；配置和 PVC 使用表单；PV、StorageClass 提供查看和删除 |
| 服务与网络 | Service、Ingress、NetworkPolicy；配置服务端口、路由和入站策略 |

列表默认每页 10 条，可选 20、50、100 条。详情在抽屉中打开，包含状态条件、容器、配置和最近事件。资源变化通过 Watch 通知页面，约 500 毫秒合并一次列表和详情刷新；总览事件刷新最多每 5 秒一次。连接正常时每 30 秒校准，上游 Watch 不可用时恢复每 5 秒查询。打开详情时暂停列表刷新，编辑表单期间保留变更通知，退出编辑后刷新。

每次最多读取 500 条资源，超过后点击“加载更多”。搜索只针对已加载的记录。事件最多显示 200 条。

总览每 30 秒更新，统计按资源类型分页读取，最多 10,000 条；超过时以 `+` 标出，不把部分数据当成完整数量。资源数量按选中的命名空间统计，节点和节点用量覆盖整个集群。没有权限的资源不显示；读取失败显示“暂不可用”，不显示为零。

CPU、内存用量来自 Kubernetes Metrics API，需安装 Metrics Server 并授予相应读取权限。优先查询 `metrics.k8s.io/v1`，不存在时使用 `v1beta1`。缺少或超过两分钟的采样不计入环图；节点、Pod 行中显示 `—`。这些是当前用量，不是 requests、limits 或历史曲线。

节点列表的“资源使用”列显示 CPU、内存、Pod 三条用量条，每条同时显示百分比和“已用 / 可分配量”。CPU 使用核心数，内存统一为 GiB。悬停或键盘聚焦可查看完整数值、统计范围和采样时间；数值更新不会让列表闪动。

Pod 用量按节点统计全部命名空间的已分配记录，包含已结束但尚未删除的 Pod，不含尚未分配节点的 Pod；不受当前命名空间筛选影响。需要工作负载查看权限和集群全部命名空间的 Pod 读取权限。统计失败、分页未完成或缺少容量时显示 `—`，只有完整统计确认为空时才显示 `0`。

## 添加与移除节点

在“集群节点”点击“添加节点”，选择 K3s 或 kubeadm，填写新机器能访问的 HTTPS API 地址，生成 5–60 分钟有效的加入命令。新机器需要先安装匹配版本的运行组件。K3s 命令启动前台 Agent，长期运行请按官方说明配置服务。EDO 不会远程登录机器安装软件，也不会创建空的 Node 记录。

加入命令包含凭据，只交给集群管理员。关闭抽屉后不再显示；可以在关闭前撤销，也会在到期后失效。EDO 只创建自己的短期 Bootstrap Token，不读取或轮换已有 server/agent token。托管集群通过云平台增加节点，不适用此命令。

移除前先停止调度、迁走普通 Pod，并在该节点停止 Agent。节点必须处于非 Ready 状态，且最后心跳早于两分钟前；服务端仍会检查普通 Pod 和另一个可用节点。控制平面不允许移除，不提供自动驱逐或强制删除。离线节点上的 DaemonSet Pod 可随 Node 删除。

确认时输入节点名称并勾选 Agent 已停止。删除只移除 Kubernetes Node 记录，不卸载软件、不清除磁盘；再次启动 Agent 可能重新注册。

## 创建 Pod

“工作负载 → Pod → 新建 Pod”支持容器镜像、端口、环境变量、重启策略和节点标签选择。独立 Pod 不会在删除或退出后自动补建；常驻应用建议创建 Deployment。删除由 Deployment 等控制器管理的 Pod 后，控制器可能立即创建替代 Pod。

Job 和 Pod 不提供原地编辑。NetworkPolicy 表单用于新建简单入站规则；复杂策略在集群中维护，控制台可查看和删除。Service 编辑表单修改第一个端口，其余端口不变；Ingress 修改第一条路由，其余路由和 TLS 配置不变。

## 部署应用

第一次部署可以在“工作负载 → Deployment”中点击新建，填写名称、镜像、端口和副本数。新增工作负载使用 `app=<资源名称>` 标签，可在 Service 的目标 Pod 标签中填写相同值。

更新镜像后，Deployment 按自己的更新策略发布。状态列显示就绪副本数，详情中可以查看 Pod、事件、日志和终端。镜像拉取失败时先检查镜像地址、仓库凭据和集群网络。

已有流水线可以继续选择 Kubernetes 部署方案，通过镜像摘要更新 Deployment。先在“主机与集群”中为主机关联 Kubernetes 能力，再将主机关联到发布环境；部署方案选择对应环境、集群、命名空间、Deployment 和容器。构建方案需要把镜像推送到集群可访问的镜像仓库。

停止节点调度不会驱逐已运行的 Pod。控制台不提供节点卸载、自动驱逐、强制删除 Pod 或清空卷数据操作。

## 权限与密钥

节点、工作负载、配置、存储和网络各自分配读写权限。重启、扩缩容和暂停任务使用工作负载执行权限；Pod 终端另需终端权限。

生成、撤销节点加入凭据使用“创建集群节点”权限，移除使用“删除集群节点”权限；两者均记录审计，不把命令或令牌写进审计。已有角色不会自动获得这两个新权限。

节点加入复用与 client-go 同版的官方 `k8s.io/cluster-bootstrap`（Apache-2.0），负责令牌生成和标准字段；K3s CA 指纹按官方实现处理，kubeadm 使用公钥 SHA-256。没有引入完整 kubeadm 或 K3s 服务端依赖。图表复用现有 ECharts；统计、权限与删除检查由 EDO 维护，不额外部署监控平台。

Secret 列表和普通详情只显示类型、键名，不返回值。查看内容需要单独的“查看集群密钥内容”权限，并记录审计。编辑 Secret 时，已有键留空保留原值，移除一行才删除该键。

更新和删除都校验 UID 与资源版本。同名资源被重建、配置被他人修改时，需要刷新后重新操作。普通状态更新不会覆盖配置。

删除命名空间会删除其内部资源；删除 PVC、PV 可能丢失数据，请先确认备份和回收策略。`default` 和 `kube-*` 命名空间不能在控制台删除。

## 测试集群

测试环境使用 [K3d](https://k3d.io/stable/) 在 Docker 中运行 K3s，与已有项目使用不同的容器、网络和数据卷。Kubernetes API 绑定服务器本机或指定内网地址，通过 EDO 或 SSH 隧道访问，不直接开放公网控制面端口。

后端复用项目已有的官方 [client-go](https://github.com/kubernetes/client-go)，没有引入额外的集群管理服务。

## 查询同步与一致性

资源列表、总览与节点采样复用 client-go SharedIndexInformer，通过初始分页 List 和持续 Watch 同步，按集群连接版本、资源类型和命名空间共享。页面通过带会话和项目鉴权的 SSE 接收资源身份通知；通知不包含配置、Secret 值或加入凭据。每条事件重新检查权限，连接空闲时也定期检查授权与集群状态。

缓存命中仍会检查项目归属和集群启用状态，并通过官方 metadata 客户端读取当前集合版本，与 informer store 已处理的版本比较。尚未同步、版本落后、无法比较版本、不支持 metadata、Watch 断开或缓存达到上限时，查询直接回到 API Server。Watch 与版本检查不能代替关键操作的实时校验：详情、编辑前读取、UID/resourceVersion 检查、节点移除和部署就绪检查始终直查；常规资源代理写入成功后停止并废弃受影响的观察器，重新完成 List 同步后才能使用缓存。手动和写后刷新使用 `fresh=1` 绕过展示缓存。

公共资源列表保留 Kubernetes 原生分页与 continue token；完整统计和节点采样可读取已同步的完整快照。每个观察器最多保留 10,000 个对象，服务最多同时建立 256 个观察器、复用 64 个集群连接，闲置观察器在五分钟后回收。超过限制时仍可通过原生分页查询。资源投影在进入缓存前脱敏，Secret 明文和日志、终端不进入资源缓存。

Metrics API 不依赖 Watch，复用两秒采样缓存与并发请求合并，保留原始采样时间；失败不缓存。权限不足、分页不完整和指标过期继续显示原有不可用状态，不把缺失或失败当作零。Kubernetes 凭据需要原有 get/list 权限；具有对应 watch 权限时启用持续同步，没有 watch 权限时自动使用实时查询。

## 节点角色与拓扑

主机列表、关联主机和节点详情显示 Master（控制平面）或 Worker（工作节点）。角色来自 Kubernetes Node 标签，主机经过真实身份匹配后才显示对应角色；未匹配或无权限时显示“—”。

进入“节点”，切换“列表 / 拓扑”。拓扑按控制平面和工作节点分组，显示 Ready 状态、IP、CPU、内存、Pod 数量和关联主机。点击节点查看详情，支持按名称、IP、主机和角色筛选。连线表示节点所属集群。

CPU、内存来自 Metrics API；缺失、过期或读取失败显示“—”。Pod 数量需要工作负载读取权限。开启自动刷新后每 30 秒刷新一次。
