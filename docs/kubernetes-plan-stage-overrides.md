# Kubernetes 通用部署方案与阶段覆盖

Kubernetes 部署方案本身就是用户可配置的通用模板，直接展示工作负载、服务与网络、启动与发布、健康检查等配置，不再提供额外的“部署模板”选择。通用部署方案保存可复用的默认规则。流水线部署阶段选择方案，绑定自己的集群、命名空间、Deployment、容器，并在部署阶段确认或更换镜像仓库，选择镜像与 Tag，调整本阶段配置。修改阶段不修改共享方案；“修改方案”入口编辑方案库，“恢复初始参数”只移除参数差异，保留本阶段目标与镜像仓库绑定。已有方案保存的镜像配置保留兼容，不因隐藏字段被清空。

选用方案时，流水线保存完整的初始配置快照，阶段另行保存字段差异。显式 false、空参数数组和删除可选探针分别保留；端口数组整体替换。未覆盖字段使用选用时的配置，之后修改库方案不影响已保存流水线，新运行固定最终配置与来源方案，已生成的运行不重新合并当前方案。执行身份和目标按任务隔离；同一方案供多个任务使用时不能串改参数或实例。固定方案已发布的目标，仅调整参数时保持原实例身份，内部环境审批和变量范围继续生效。

新增阶段覆盖复用现有 `gopkg.in/evanphx/json-patch.v4` 的 RFC 7396 实现，配合模型字段白名单及最终配置校验；不增加新依赖或组件。工作负载、网络、集群目标与镜像仓库继续检查当前权限、项目范围和准确身份。已保存开启网络的阶段在撤权后直接删除覆盖或切换来源，同样不能绕过网络修改权限。

方案库保留默认镜像仓库选择，镜像名称和 Tag 只在流水线部署阶段配置；阶段可继承或更换仓库，通用方案可不绑定具体镜像直接保存。不再提供构建制品来源或上游镜像选择。Tag 可填写实际版本或变量引用；执行时解析并固定本次准确镜像，旧运行不受当前配置变化影响。

本批提供的常用参数：

| 分区 | 可配置内容 | 未设置时 |
| --- | --- | --- |
| 目标 | 集群、命名空间、Deployment、容器、镜像仓库、镜像与 Tag | 应用名与配置镜像补空字段，集群需明确选择 |
| 工作负载 | 副本、CPU/内存申请和限制 | 沿用方案默认 |
| 服务与网络 | ClusterIP / NodePort / LoadBalancer / ExternalName；可增删端口、名称、TCP/UDP/SCTP、服务端口、容器端口及节点端口 | 默认 ClusterIP；仅名称为 http 的 8080 示例且关闭，名称可改、整行可删除 |
| 启动与发布 | 命令和参数数组、容器工作目录、镜像拉取策略、终止宽限期、滚动或重建策略、额外/不可用副本 | 沿用镜像与 Kubernetes 默认 |
| 健康检查 | readiness、liveness、startup 的 HTTP/TCP 检测和等待/间隔/超时/失败阈值 | 默认关闭 |
| 标签与注解 | 自定义工作负载和 Pod 标签、注解 | 不覆盖 EDO 资源身份和选择器 |
| 环境变量 | 直接值、同命名空间 ConfigMap/Secret 的指定键 | 不读取密钥原文 |
| 存储挂载 | 已有 PVC、ConfigMap、Secret、emptyDir、挂载路径、subPath 与只读 | 不自动创建或删除依赖资源 |
| 调度 | 节点标签、污点容忍 | 沿用集群调度 |
| 发布选项 | 镜像拉取 Secret、最短就绪时间、历史版本保留数、进度截止时间 | 沿用 Kubernetes 默认 |
| 执行 | 部署超时 | 沿用方案默认 |

参考用户提供的生产 Kuboard 部署表单：基本信息、发布策略、容器和存储分区，端口使用可重复行与添加/删除入口；参考过程中没有填写或提交生产资源。EDO 保留浅色细分隔与部署阶段固定操作区，不在产品增加“只读”装饰文字。

ConfigMap、Secret、PVC 与镜像拉取 Secret 只引用目标命名空间内已有资源，部署前检查存在性与有效读取权限，Secret 仅核对普通详情允许的元数据和键名。新参数进入真实 Deployment/Pod 配置与运行快照；清除配置时仅移除之前由 EDO 管理的字段，不删除依赖资源。Ingress 与 ServiceAccount 本批尚未加入；没有增加 hostPath、宿主机网络或特权参数。

| KP-04 | 两任务引用同一通用方案 | 不同目标和覆盖独立；重复目标阻断 |

| KP-06 | 网络权限撤销或个人拒绝 | 开关、直接删除覆盖、切换来源及共享方案恢复默认均不能绕过权限 |

| KP-10 | 工作负载与网络修改权限 | 添加自定义名称和协议的端口、删除全部并重新添加；重复名称、映射与节点端口阻断，旧端口不被默认值改写 |
| KP-11 | 工作负载修改权限 | 环境值、引用、挂载、节点标签及容忍保存重开准确回显；无权限不接受事件，错误草稿阻止保存 |
| KP-12 | 引用目标资源可读 | 同命名空间依赖存在/键名/权限核验；缺少或撤权明确失败，不展开Secret正文 |
| KP-13 | 隔离 Kubernetes API fixture | 最终 Deployment/Pod 字段与参数一致，清空恢复默认只移除原EDO字段，不删除PVC/Secret或覆盖外部metadata |

Kubernetes API fixture 及数据库集成回归不冒充真实集群部署验收。

服务类型直接参考 Kuboard Service 基本配置的四个选项，不再使用单独的 NodePort 开关。NodePort 和 LoadBalancer 显示节点端口；ExternalName 只配置 DNS 别名，不转发到本 Deployment，隐藏端口草稿并保留供切回使用。LoadBalancer 需要集群提供对应的负载均衡实现。旧 `node_port` 配置按原语义读取，显式 `service_type` 优先，不在打开时改写方案或历史运行。服务类型和外部域名属于网络权限范围，阶段覆盖、恢复初始参数和切换来源均复核。

切换类型复用原 Service 的 UID 与版本并经过 Kubernetes dry-run，不自动删除或重建。原生 API 不接受的不可变地址变更明确失败；已有 ExternalName 无端口时切回普通服务，需要至少启用一个端口，不能捏造端口或自动删服务。ExternalName 的 DNS 字段和普通服务的端口字段只在对应类型生效。

| ID | 前置与角色 | 操作与预期 |
| --- | --- | --- |
| KP-14 | 方案和阶段网络修改权限 | 四种服务类型保存重开准确回显，默认 ClusterIP；ExternalName 域名与端口草稿切换不丢，共享方案不被反写 |
| KP-15 | 旧 NodePort 方案及撤权 | 无显式类型时按旧布尔值回显，显式类型优先；类型或 DNS 覆盖恢复、删除及来源切换不能绕过网络权限 |
| KP-16 | 隔离 Kubernetes API fixture | 四种真实 Service 请求及跨类型清理正确，ExternalName 无选择器或端口；UID/版本和上游拒绝继续生效 |

选用方案是便捷填入部署阶段的初始配置，不是持续跟随方案库的动态绑定。已有引用第一次保存会固定完整配置；修改库方案前，服务端会在同一事务中给尚未固定的旧引用保留原配置，既不改参数也不推进流水线版本。新任务选用方案取得当前默认值。已有阶段修改不反写方案库，恢复初始参数回到原快照，运行继续冻结本次有效配置。来源可用性、项目和执行权限仍实时复核，不把配置隔离当成权限豁免。

端口名称由用户填写，`http` 仅是可编辑的默认示例；分组标题使用端口序号。名称不决定网络或应用协议，也不作为 Service 名称；实际服务与容器声明使用用户保存的名称和协议。
