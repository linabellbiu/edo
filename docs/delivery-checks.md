# 流水线检查与发布保护

普通发布仍然是连接仓库、选择触发条件、配置任务，然后运行。下面这些能力按需要添加。

## 项目边界

EDO 的交付流程以项目空间为单位。应用、代码仓库、流水线、构建方案、部署方案、环境、变量与密钥、发布计划和运行记录都归属当前项目。配置引用只能指向同一项目的资源；不同项目可以各自配置同名变量，彼此独立。切换项目后重新加载该项目的数据和有效权限，未选项目时不能操作业务配置。

查看、创建、修改、删除和使用分别检查当前项目的有效权限；其他项目的角色或平台角色不自动授予本项目业务权限。配置写入前和任务执行前会重新核对项目成员、角色和个人拒绝，已撤销的授权不能继续生效。后台任务始终使用运行快照记录的项目，不能随操作者之后切换项目而变化。

构建、脚本和流水线部署在检出代码、恢复已有制品或操作运行资源前，检查快照授权者在运行所属项目的执行权限；使用变量还须具备该项目的变量使用权限。项目、成员、账号或授权失效会使待执行任务失败，不再自动重试。独立发布与回滚按记录所属项目和当前发起人的对应权限检查。

这次调整不移动已有配置或改写运行快照。缺少冻结项目、部门或明确授权者的旧待执行记录会被拒绝，不能猜测其所属项目或借用管理员授权继续执行；请从有权访问的项目重新创建运行。已有历史记录继续保留。

## 变量与密钥

先选择项目，再在「应用与代码 → 变量与密钥」中添加变量，选择构建用途或部署用途，在任务中引用名称。可以限定到本项目的某个应用、环境和分支。“项目共享”仅表示当前项目内共用，应用和环境范围中的同名变量优先。

密钥加密保存，列表和编辑表单不回显。每次运行固定引用的版本；修改变量只影响之后的运行，停用或删除会阻止尚未执行的引用。任务开始前会重新检查授权人的账号和使用权限。自动触发采用流水线最后修改人的授权，手动触发采用操作者的授权。

- Shell 任务和脚本构建：普通变量进入环境，文件变量指向隔离容器中的只读文件。
- Dockerfile 构建：普通变量作为构建参数；密钥和文件变量通过 BuildKit Secret 传入。例如 `RUN --mount=type=secret,id=NPM_TOKEN ...`。
- 部署任务：环境变量传给 Docker、Compose、主机部署脚本或 Kubernetes。Kubernetes 生成不可变 Secret，再由容器引用。原有构建文件变量只用于构建和检查；部署专用的 env 文件配置仅用于 Compose。

添加部署变量默认使用「输入 env 文本（environment）」，可切换「挂载 env 文本（env_file）」或原有「逐条添加」。文本按物理行输入 `KEY=value`，关闭自动换行，长行横向滚动；等号后的内容原样保存，不执行引号解析、变量插值或多行拼接。允许空行和整行 `#` 注释，重复名称、系统变量及不完整行会被拒绝并提示行号。两种文本配置默认勾选密钥加密保存；编辑密钥时仅在明确替换后提交正文。

文本模式填写配置名称，例如 `PROD_ENV`；文件模式填写不含目录的文件名，例如 `.prod.env`。同名配置可分别绑定测试和生产环境，任务继续按名称显式引用当前项目变量。单独保存变量不会触发部署。多个文本配置含同名键时拒绝执行；同时引用的逐条变量优先于文本中的同名键。

Compose 文本模式自动向所有服务合并 `environment`，不要求 YAML 预先声明，同名键以本次变量为准。文件模式自动生成文件并添加 `env_file`，保留 YAML 原有引用；使用官方 `format: raw` 保护字面内容，需要 Docker Compose 2.30 或更新版本。既有 YAML 的 `environment` 仍按 Compose 官方规则优先于 `env_file`，由配置者自行决定两者内容。多镜像方式在目标部署目录的 EDO 私有运行目录中保存权限为 `0600` 的文件，各运行隔离并保留上一版本引用；单镜像方式使用本次命令的临时文件，命令结束清理。文件正文不写入发布脚本、运行快照或普通报告。

EDO 根据注入密钥的实际值脱敏输出。不要在脚本中主动编码、拆分或上传密钥，也不要把密钥写入制品、依赖缓存或镜像层。发布记录和运行快照只保存配置或版本引用，不保存注入的密钥明文。

## 并行任务与制品

同一阶段的独立任务同时执行，全部成功后才进入下一阶段。审核和人工放行会暂停后续批次。构建与部署存在制品依赖时，先完成构建再部署；一个批次有多个构建时，部署任务必须明确选择制品来源。

每个任务使用独立检出目录、构建上下文、认证目录和镜像标签。任务失败会停止阶段推进并取消其它待执行任务；停止流水线会通知所有执行中的任务。已经提交的外部操作不会自动撤销。

版本 2 运行使用逐任务记录。已启动的运行继续使用自身快照，升级不会重写它们。

## 测试、覆盖率与检查报告

在 Shell 任务或脚本构建的高级配置中添加报告路径，支持 JUnit、Cobertura、LCOV 和 SARIF。路径相对于仓库根目录，填写具体文件，可配置多个路径。

勾选「报告必须存在」后，报告缺失或格式错误会导致任务失败。JUnit 失败用例、最低覆盖率和 SARIF 严重级别都可以阻止后续发布。命令失败后仍收集报告，运行详情展示用例、问题文件和行号；单次最多收集 16 MiB，展示最多 2000 条明细，门槛按全部问题计算。

Dockerfile 构建沿用镜像层缓存。需要收集检查报告时，在构建前添加独立 Shell 任务。

## SQL 与安全检查

在 Shell 任务的「任务用途」中选择：

| 用途 | 工具 | 配置 |
| --- | --- | --- |
| SQL 质量检查 | SQLFluff 4.4.0 | SQL 方言、目录或文件、可选规则文件 |
| 漏洞与配置扫描 | Trivy 0.76.1 | 仓库内的扫描路径 |
| 密钥泄漏扫描 | Gitleaks 8.30.1 | 扫描路径、可选规则文件 |

检查工具使用固定版本的隔离容器，按需拉取镜像，不增加常驻服务。Trivy 首次执行需要下载漏洞数据库。SQLFluff 检查 SQL 语法和规则；它不能代替目标库上的执行计划、锁等待评估和数据库变更审核。Gitleaks 报告只保留位置和规则，不保存匹配到的密钥内容。

## 应用数据库变更

在「应用与代码 → 应用数据库」中选择应用和环境，填写 PostgreSQL 或 MySQL 连接并测试。密码加密保存，编辑时留空保留。数据库类型、地址、端口和库名保存后固定，避免换库后沿用另一套执行历史；账号、密码、证书校验和显示名称可以更新。

在流水线中添加 Shell 任务，将用途设为「数据库变更」，选择连接和迁移目录。目录只放 Goose 格式的 SQL 文件，例如：

```sql
-- +goose Up
CREATE TABLE example (id BIGINT PRIMARY KEY, name VARCHAR(128) NOT NULL);

-- +goose Down
DROP TABLE example;
```

文件名以递增版本号开头，例如 `00001_create_example.sql`。任务只执行向上迁移，不自动执行 Down。开始前需要其他成员审核，执行时按实际目标加锁。EDO 保存 Commit、脚本摘要和执行历史，相同内容不会重复执行，已执行文件不能修改，后续调整写到新的迁移文件中。

任务中断、执行失败或结果不确定时，必须先核对目标库和变更记录。EDO 不自动重放这类任务。应用数据库只执行用户明确提交的迁移，不用于迁移 EDO 自身数据。

## 环境保护

环境启停和环境保护规则是两件事。启用已绑定目标的部署方案、启用流水线或开始新执行时，会检查目标环境是否启用且属于同一项目和部门。没有绑定目标的通用方案可以先启用；环境不可用的流水线仍可保存为停用草稿。停用环境不会自动停止已部署服务，也不会改写已有运行的配置。

在「环境保护」中选择环境，再显式启用允许 Ref、审核成员、通过人数和发布时间窗口。窗口使用上海时区，支持跨午夜。默认没有限制，不根据环境名称推断规则。

启用后，运行快照中增加可见的审核节点，申请人不能自审。实际发布前再次检查规则版本、分支和窗口；配置变化后需要重新运行。审核人仍需拥有流水线审核权限。

## 依赖缓存与仓库回写

依赖缓存用于未纳入 Git 管理的 `node_modules`、`.cache`、`.gradle`、`.m2` 等目录。缓存按项目、仓库、架构、镜像、名称和锁文件内容隔离，不覆盖源码；单项最多 256 MiB，整体最多 2 GiB，保存 7 天。清除构建目录也会清除依赖缓存，不删除运行历史。

在代码源中勾选「回写 Commit / PR 检查结果」后，EDO 向 GitHub、GitLab、Gitea 或 Gitee 回写状态。需要仓库平台 API 令牌；SSH 私钥不会用于 HTTP 认证。回写异步进行，最多尝试 4 次，权限和配置错误直接结束；回写故障不改变已完成的构建或发布结果。运行详情显示投递结果，较早的状态不会覆盖同一流水线更新的运行。

## 升级

备份 EDO 数据库和加密密钥，使用新程序执行 `edo migrate`，再启动服务。本次新增变量修订、节点记录、报告、环境保护、应用数据库变更和仓库回写表，并把审核记录改为按运行、节点和审核人去重。各表使用数据库自增行号排序，关联继续使用 UUID；已有运行和业务资源不会重绑定。
