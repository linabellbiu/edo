# 部署参数与仓库 ENV 文件验收

用户在 2026-11-12 明确纠正：`--env-file .env` 可以引用代码文件，不能要求先选择生成 EDO 配置。前一版“未选择生成文件就拒绝保存”的规则已取消。

普通相对路径在部署工作目录解析；EDO 从本次固定 Commit 只准备明确引用的仓库文件，通过现有校验摘要、0600 权限及原子写入的文件通道传输。仓库没有该文件时保留主机工作目录用法，由 Compose 检查文件存在性。显式 `${EDO_APP_CONFIG_PATH}/相对路径` 使用已冻结的应用配置目录；所选生成配置保留同名相对路径简写。多次 `--env-file` 按顺序覆盖，流水线环境优先。文件只用于 Compose 插值，不把其中所有变量额外注入每个容器。重启不重新检出分支；重建复用已成功发布的参数及文件位置。

参数解析继续复用 `mvdan.cc/sh/v3`，ENV 正文采用项目已有的 Compose 官方 `compose-go/v2/dotenv`，遵循官方引号、插值和覆盖规则，不写入 EDO 进程环境，不引入新依赖或常驻组件。文件正文不进入运行快照、命令、审计和普通日志；解析错误可能含正文，因此只记录安全的失败分类。

| 编号 | 角色与前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| DP-ENV-01 | 有流水线编辑权限；未选择任何配置文件 | 保存 `--env-file .env` 并启用，重新读取 | 接受参数，仓库、Compose 路径及启用状态准确回显；保存不创建运行 | 通过：SQLite/MySQL 正常保存接口，启用及重新读取；未创建流水线运行 |
| DP-ENV-02 | 运行已固定 Commit；分支随后修改 `.env` | 准备参数文件，经正常本地执行通道传输，再运行 Compose config | 使用原 Commit 文件，目标工作目录可读取；0600；Compose 正确插值 | 通过：SQLite/MySQL 下真实本地 Git 检出、正常文件传输及 Docker Compose config；原 Commit 内容和 0600 正确 |
| DP-ENV-03 | 仓库文件、生成配置和多个参数混用 | 依次读取文件并预览命令 | 后文件覆盖前文件，流水线变量优先；仓库路径不强加配置目录前缀 | 通过：官方 dotenv 插值与顺序覆盖回归；前端预览区分工作目录、配置目录和旧派生列表 |
| DP-ENV-04 | 已成功部署的配置快照 | 生成服务重建脚本 | 同时保留仓库相对路径、冻结配置目录与 force-recreate 参数 | 通过：冻结目录回读、重建脚本参数及 sh -n；未实际重建业务容器 |
| DP-ENV-05 | 仓库没有引用文件，或未选择生成配置 | 保存与准备参数 | 保存不检查主机文件；不报“必须添加配置文件”，不伪造文件存在 | 通过：未选配置正常保存，仓库缺文件保留主机文件用法的准备回归 |
| DP-ENV-06 | 越界路径、链接、目录、超限正文、错误 ENV、命令替换或无执行授权 | 保存或准备文件 | 按对应边界拒绝，错误安全，未授权不检出；失败保存不改原流水线 | 通过：原 Shell 参数安全用例、路径与文件边界、授权前不检出、SQLite/MySQL 无效保存原配置不变 |
| DP-ENV-07 | 独立真实前端组件页面 | 输入仓库 `.env` 和非法路径后修正 | 仓库文件不误报缺少配置，非法路径提示靠近输入框且可清除 | 通过：真实组件合成页面，仓库 .env 无错误，非法路径即时提示，恢复后清除；无写请求 |

验收均使用独立合成页面、SQLite/MySQL 测试数据库及本地临时 Git 仓库；不修改业务仓库或用户未保存草稿，不触发用户流水线。真实 Compose 检查仅执行 config，不能冒充真实应用发布或容器重建成功。本次不更新 127.0.0.1:18080 的运行实例。

后端相关测试在 SQLite/MySQL 下使用 `-race` 通过。前端完整 1,829 项通过；最后补充当前文件来源优先级后，相关 24 项及类型检查、生产构建再次通过。复用成熟库及传输通道，未新增依赖或数据库结构。
