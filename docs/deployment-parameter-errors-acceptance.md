# 部署参数错误提示验收

用户草稿填写了 `--env-file .env`，但未在“部署前下载上游产出文件或制品到主机”中选择生成 `.env`。该配置应被拒绝；问题是校验原因在部署输入、方案及流水线的转换中被覆盖为“部署方案配置无效”。本次保留具体、安全的参数错误，并在输入框旁即时提示缺失文件及修正方式。继续复用现有 Shell 解析库，不执行参数，不扩大文件读取范围，不引入依赖。

| 编号 | 角色与前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| DP-ERR-01 | 有流水线编辑权限；Compose 参数为 `--env-file .env`，无文件来源 | 输入参数并保存、启用 | 参数框指出缺失的 `.env`；正常保存接口返回具体原因；原已启用流水线不变 | 通过：真实组件隔离页面；SQLite/MySQL HTTP 回归核对原版本、启用状态、代码源及阶段不变 |
| DP-ERR-02 | 同上 | 从正常“添加文件来源”入口选择配置，生成路径填 `.env` | 错误立即消失，参数及其他草稿保留；配置名称不要求是 `.env` | 通过：浏览器选择“生产环境配置”并填写 `.env`；前后端覆盖补充文件后的校验 |
| DP-ERR-03 | 同上 | 删除无效参数，保存并重新读取 | 允许不使用配置文件；保存后仓库、Compose 路径和启用状态准确回显 | 通过：SQLite/MySQL 正常 HTTP 保存和回读；浏览器空参数清除提示 |
| DP-ERR-04 | 版本 1 输入中仍有旧派生文件列表 | 移除文件来源，或只填路径而未选择配置 | 旧列表及空配置项不能清除缺失文件提示 | 通过：前端状态回归；后端继续以当前文件来源为准 |
| DP-ERR-05 | 引用未选择的绝对路径、未知参数或 Shell 表达式 | 校验参数 | 不提示添加任意主机文件，不执行参数或命令；既有路径和安全边界不变 | 通过：配置文件参数安全回归及非法路径错误分类 |
| DP-ERR-06 | 仓库或编辑器 Compose 来源；新版或旧版输入结构 | 校验缺失文件与补齐后的配置 | 各方案转换保留具体错误；正确配置通过 | 通过：四种组合的后端回归 |
| DP-ERR-07 | 浅色、深色及 390px 窄屏 | 查看错误、补齐文件或移除参数 | 错误靠近输入框并自然换行；输入关联错误提示，状态恢复正常 | 通过：真实组件合成页面截图及 DOM；提示为 alert，输入有 aria-invalid / aria-describedby，窄屏无横向溢出 |

验证使用隔离数据：页面入口为 `web/tests/fixtures/deployment-parameter-error.html`，不连接真实 EDO；HTTP 用例走正常鉴权及保存接口，使用独立 SQLite/MySQL。检查保存和拒绝均未创建流水线运行，页面也没有写请求。后端相关回归使用 `-race` 通过；前端相关 24 项、完整 1,829 项、类型检查及生产构建通过。
