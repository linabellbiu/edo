# 仓库 Compose 路径自动检测验收

仅在仓库路径为空且可编辑时自动填写草稿，保存和部署沿用原流程。按当前已使用版本 `compose-spec/compose-go/v2@v2.16.2/cli.DefaultFileNames` 核对官方优先级：`compose.yaml`、`compose.yml`、`docker-compose.yml`、`docker-compose.yaml`。用 Go 标准库只读取检出根目录的文件元数据，不采用官方 CLI 向父目录继续搜索的完整流程，不读取或返回 Compose 正文。已评估复用官方 `cli` 包：该包会连带引入完整项目加载器、YAML v4、JSON Schema 等新增依赖，仅为四个文件名扩大依赖范围不合适，因此使用同样的固定文件名顺序和标准库检测，不引入新依赖。维护风险是官方默认文件名未来变化，升级 Compose 依赖时需复核此列表。

| 编号 | 角色与前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| CF-01 | 可编辑流水线且有仓库查看权限；根目录有常用 Compose 文件 | 选择仓库来源或打开空路径任务 | 按官方优先级自动填入真实文件名，可继续编辑；无自动保存或执行 | 通过：真实组件隔离页面与前端回归；新建任务路径留空并自动填写，仍需原保存操作 |
| CF-02 | 同上；只有子目录文件、符号链接或没有 Compose 文件 | 自动检测后手动输入路径 | 不递归，不跟随链接；明确未找到并允许手填 | 通过：SQLite/MySQL 根目录文件检测，覆盖子目录、override 文件、符号链接与空结果；前端可手填 |
| CF-03 | 同上；已有路径或检测期间输入 | 打开任务、输入/清空路径及等待结果 | 已有路径保留，迟到结果不覆盖用户草稿 | 通过：已有路径、手动输入/清空及迟到结果的前端回归 |
| CF-04 | 可编辑用户；切换项目/应用/任务/分支/来源、撤权或关闭 | 检测未返回时改变上下文 | 旧请求取消，旧结果不回填；只读不发检测或改写 | 通过：项目、应用、任务、分支、来源、撤权、只读和关闭的前端回归 |
| CF-05 | 无仓库权限或其他项目用户 | 调用检测接口 | 正常权限和项目隔离有效，不读取其他项目仓库；错误安全且有日志 | 通过：SQLite/MySQL 正常 HTTP 角色及项目隔离；无授权不检出，错误不返回原始诊断 |
| CF-06 | 代码源为分支、Tag 或通配规则 | 检测后预览/保存 | 精确引用解析，通配按应用默认分支；运行仍按固定 Commit 和保存路径读取 | 通过：分支、Tag、通配规则的固定版本回归；真实本地 Git 检出后自动发现并复用服务预览解析 |


验证范围：后端新增用例及原 Compose 服务预览在 SQLite/MySQL 下使用 `-race` 通过。前端完整 1,826 项通过；之后补充的新建任务空路径修改及相关编辑器/自动检测 31 项通过，类型检查与生产构建通过。页面使用真实 `PipelineDeployFields` 配隔离接口确认自动填入 `docker-compose.yaml` 后仍可手动修改。Git 联调使用临时本地 Git 仓库与真实 Go Git 客户端，未读取用户业务仓库、未触发流水线或部署；HTTP 和数据库用例也均为隔离数据。

本次只提交代码，用户当前 `127.0.0.1:18080` 运行实例未更新。已保存方案中的明确路径（包括现有模板配置）保持原值，自动检测适用于空路径。
