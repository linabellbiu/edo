# Kubernetes 发布就绪判定

EDO 发布仍使用 Kubernetes 官方 client-go 更新已有 Deployment 的指定容器镜像，再等待本次滚动更新完成；不创建另一条绕过应用、流水线和部署方案的发布通道。

本次收紧完成条件，防止把旧副本的可用数量算成本次镜像已经全部就绪：控制器必须已观察本次 generation，全部期望副本已经更新，旧副本全部退出，全部新副本可用。数量要求精确一致，不把异常的超额计数当作成功。期望副本为零时，更新和现存副本都清空才完成；这表示工作负载已缩容，不表示应用正在提供服务。

等待期间同时复验更新响应的对象 UID、generation、目标容器镜像及 `edo.io/deployment-id`。同名对象被重建、后续发布覆盖或其他模板变更会终止本次等待，不能被当作本次成功。控制器已观察本次版本后，如报告 `ProgressDeadlineExceeded`，立即返回明确的发布进度失败；不继续耗尽部署方案的等待时间。旧版本残留的进度条件不会在本次 generation 尚未被观察时误判失败。

父任务取消、父任务期限、发布就绪等待期限、持续状态读取失败和目标变化分别处理。短暂的读取故障允许继续观察，权限丢失和目标删除及时终止。更新完成后的任一种失败均保留实际发布前的镜像，供既有人工确认回滚使用；本次调整不增加自动回滚，不改写失败的流水线历史。对外提示为固定中文，集群原始诊断仅进入日志。

该变更只改变新执行的等待和失败语义，无表结构或历史数据迁移；已经保存的发布成功记录不反推或改写。

实现复用现有 client-go v0.36.2；完成判断参考同版本 Kubernetes 官方 [kubectl DeploymentStatusViewer](https://github.com/kubernetes/kubectl/blob/v0.36.2/pkg/polymorphichelpers/rollout_status.go)，并额外冻结本次更新身份与精确数量。没有为几项业务判断引入整个 kubectl 命令行依赖；后续 Kubernetes 升级需继续对照控制器状态语义，并保留真实 client-go HTTP 编解码的状态、取消、读取故障和零副本回归测试。

验收证据须区分真实控制器状态与防御性不一致输入。K3s 实际观察到的旧新混合状态中不可用副本为 1，原判定也会继续等待，不能据此声称已在真实集群复现提前成功；不可用计数缺失的混合状态属于防御性测试。
