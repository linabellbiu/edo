# Compose 项目名自动确定

项目名不再作为部署表单字段或方案输入保存，不迁移、不回退读取旧 `project_name`。

部署读取实际 Compose 来源（编辑、上传、仓库、配置或上游产物），优先采用顶层 `name:`，支持本次部署的非密钥变量；没有名称时按应用 UUID 与部署目标 UUID 生成稳定的 `edo-…` 名称。同一应用和目标的重复发布保持身份一致，不同应用或目标不复用自动名称。

解析结果以 `resolved_project_name` 写入运行快照，部署命令、容器标签校验、应用服务查看、重启与重建共用该结果。重启和重建不重新读取当前方案来猜测项目名。旧运行中只有手填值的快照不补兼容别名；现有容器不会因编辑方案被自动改名或重新部署。

## 解析库选型

复用 Compose 官方维护的 `github.com/compose-spec/compose-go/v2/template`，固定 v2.16.2（2026-10-21 发布，Apache-2.0，要求 Go 1.24，项目当前工具链满足）。只引入模板子包处理 `${VAR:-default}`、必填变量及转义，不自行重写变量语法，不加载整个 Compose loader、文件来源或主机环境。该子包仅使用 Go 标准库及项目已有的 logrus；依赖要求将 logrus 从 1.9.4 更新到 1.10.1，无新增原生或常驻组件，适用于 Linux/macOS。

保留现有 YAML 解析器，不引入完整 loader 及其配置文件、网络或挂载解析范围。EDO 自行维护应用/目标隔离、长度约束、密钥保护与运行快照规则；替换模板库时由独立项目名测试约束插值行为。库默认警告已关闭，模板错误不携带正文或密钥返回；只在业务边界记录运行及节点上下文和安全错误。

2026-11-09 以准确模块名和固定版本查询公开 OSV 数据，compose-go v2.16.2 与 logrus v1.10.1 未返回已登记漏洞；该查询仅作为依赖选型记录，不替代项目安全测试。

## 验收用例

| ID | 前置与操作 | 预期 |
| --- | --- | --- |
| CPN-01 | 上传或编辑含 `name:` 的 Compose | 不出现项目名输入，部署使用 YAML 名称。 |
| CPN-02 | 无 `name:`，对同一应用/目标重复解析 | 自动名称稳定；更换应用或目标后名称不同。 |
| CPN-03 | 仓库、配置、上游产物作为来源 | 实际来源解析后冻结名称，与内联正文使用同一规则。 |
| CPN-04 | 缺少必填变量、非法名称或名称引用密钥 | 部署前阻断，提示安全中文，不输出正文或密钥。 |
| CPN-05 | 保存旧 `project_name` 或客户端伪造运行结果 | 不作为命名输入；不执行旧值回退或迁移。 |
| CPN-06 | 已成功部署后修改方案，再查看或重建 | 仍定位该次运行快照中的项目；不能扩大到其他应用。 |

以上用例由定向后端/前端回归及隔离页面验收核对；真实业务发布不属于本批验收，不触发已导入应用的部署。

自动验证结果：前端全套 1781 项通过，生产构建通过；composeconfig、pipeline、deployment 三个后端模块完整 `-race` 通过，最终项目名调整的定向 `-race` 通过；Compose 相关 HTTP API 回归、完整 API 编译及差异空白检查通过。接口草稿测试同时修正为校验“必须显式选择并保存部署仓库”的现行规则，继续检查未授权拒绝及创建草稿不触发任务，不通过推断上游仓库放宽产品约束。
