# 组织与项目权限

EDO 采用单公司模型。公司下设置部门，每个普通用户属于一个部门；部门内可以建立多个独立项目空间。部门层级不继承权限，项目之间不共享业务资源。

## 配置顺序

1. 超级管理员在「组织与部门」填写公司资料、创建部门并设置上级部门。
2. 在「用户」创建账号，选择所属部门。平台角色用于账号、组织、审计和系统设置等平台操作。
3. 在「项目空间」创建项目，打开详情添加本部门成员，选择项目角色。创建人自动成为该项目管理员。
4. 从顶部项目选择器或项目行的「进入项目」切换工作空间，再创建仓库、应用、流水线、构建和部署资源。

项目详情可查看成员角色与当前账户的有效权限。内置项目角色包括管理员、开发成员和只读成员；只读成员不包含终端、密钥查看或执行权限。需要自定义角色时，在「角色与权限」按资源勾选动作，再到项目成员中分配。项目角色只能包含项目内权限。

平台角色不会给任何项目授予业务权限，包括初始的默认项目。没有成员资格的用户不能通过项目 ID、资源 ID 或请求头访问项目。超级管理员保留跨部门恢复入口，但业务列表仍只展示当前选择项目的资源。个人 Git 凭据始终按所有者隔离，超级管理员也不能读取他人的明文。

## 授权规则

- 查看、创建、修改、删除和执行分别授权。菜单由页面的查看权限决定，按钮与接口检查对应动作。
- 应用、流水线、构建方案、镜像仓库、部署方案、发布计划、流水线运行与制品各自授权，不使用 `delivery.*` 聚合权限。
- 同一用户可以在多个本部门项目拥有不同角色。项目角色不授予用户、公司、部门、平台角色或系统配置管理权限。
- 用户级允许用于少量例外，显式拒绝始终优先；例外不绕过项目成员资格。
- 普通管理员不能修改自己的角色，也不能授予超过自身有效权限的角色。项目委派在数据库事务中重新检查，不能依靠尚未同步的策略缓存越权。
- 调动部门使旧会话失效。原项目成员关系不会变成新部门的访问权，已有资源也不会随人员调动而迁移。

权限由现有 Casbin 引擎执行，项目 ID 作为角色域；角色、项目成员和个人例外仍以 GORM 事务表为准。复用当前 Casbin 与 Redis Watcher，不新增身份服务或授权服务，不引入新的常驻组件和依赖。Casbin 的域角色与优先拒绝语义负责通用授权，EDO 自身负责组织规则、成员资格、数据范围、委派和审计。

## 接口与后台

业务接口必须携带 `X-EDO-Project-ID`，WebSocket 使用 `project_id` 查询参数。服务端先验证项目可用性和成员资格，再检查动作权限；数据库查询、更新和删除继续强制按部门、项目过滤。遗漏项目范围会直接拒绝，不推断一个默认工作空间。

后台流水线、构建、制品、发布、通知与任务继承父资源的项目。实时状态只订阅当前项目，日志、终端和容器日志连接持续复核身份、成员资格及动作权限。移除成员或撤销权限后，已有连接也不能继续访问。

空的非默认项目可以删除；有业务资源或运行历史时拒绝删除。部门删除先检查下级、成员、项目和业务资源。删除用户同时清理其项目成员关系，不删除共享角色和业务历史。

## 新模型边界

本次按新模型初始化和使用，不做旧权限码转换、旧角色继承或历史资源自动分配。旧聚合权限不作为有效授权接受。已有开发数据不会被自动转入项目，也不会由本次变更清空；需要重新配置的测试环境应使用独立新库，原库保留。

相关接口会记录操作审计；错误日志保留诊断上下文，对外只返回安全的中文提示。策略同步失败时对受影响普通账户安全停用，避免继续沿用已撤销的权限；超级管理员的项目成员变更不影响其恢复身份。
