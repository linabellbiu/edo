# 组织与项目权限

一个 EDO 实例管理一家公司。公司下有部门，每个普通用户属于一个部门；部门内可以建立多个项目。上下级部门不共享权限，项目之间也不共享业务资源。

## 配置顺序

1. 超级管理员在「组织与部门」填写公司资料、创建部门并设置上级部门。
2. 在「用户」创建账号，选择所属部门。平台角色用于账号、组织、审计和系统设置等平台操作。
3. 在「项目空间」创建项目，打开详情添加本部门成员，选择项目角色。创建人自动成为该项目管理员。
4. 从顶部项目选择器或项目行的「进入项目」切换工作空间，再创建仓库、应用、流水线、构建和部署资源。

项目详情可查看成员角色与当前账户的有效权限。内置项目角色包括管理员、开发成员和只读成员；只读成员不包含终端、密钥查看或执行权限。需要自定义角色时，在「角色与权限」按资源勾选动作，再到项目成员中分配。项目角色只能包含项目内权限。

平台角色不会给任何项目授予业务权限，包括初始的默认项目。没有成员资格的用户不能通过项目 ID、资源 ID 或请求头访问项目。超级管理员可以管理所有部门，但业务列表仍只展示当前项目的资源。个人 Git 凭据始终按所有者隔离，超级管理员也不能读取他人的明文。

## 授权规则

- 查看、创建、修改、删除和执行分别授权。菜单由页面的查看权限决定，按钮与接口检查对应动作。
- 应用、流水线、构建方案、镜像仓库、部署方案、发布计划、流水线运行与制品各自授权，不使用 `delivery.*` 聚合权限。
- 同一用户可以在多个本部门项目拥有不同角色。项目角色不授予用户、公司、部门、平台角色或系统配置管理权限。
- 可为用户单独添加允许项或拒绝项，拒绝项优先。用户仍需加入项目才能访问。
- 普通管理员不能修改自己的角色，也不能授予超过自身有效权限的角色。保存时会重新检查当前权限，防止使用尚未更新的缓存越权授权。
- 项目成员管理不能通过移除成员或换角色，移走最后一名有效的内置项目管理员；移交时先指定新管理员，再调整原管理员。保留的管理员必须是本部门已启用、仍有成员分配权限的账号。超级管理员保留恢复入口；这项检查只针对成员角色变更，不会自动为现有项目补分管理员。
- 调动部门使旧会话失效。调动后不能再访问原部门的项目，已有资源仍留在原部门。

Casbin 负责权限判断，项目 ID 用作角色域。角色、成员关系和用户单独配置的权限保存在数据库中，变更通过 Redis Watcher 通知其他实例。不需要额外部署身份或权限服务。

当前身份接口 `/auth/me` 只返回 Casbin 授权与当前数据库授权的交集，不能把尚未重载的旧权限重新交给页面，也不能仅凭数据库新记录扩大授权。复核包含账户启停、认证版本、部门、项目可用性、成员资格及个人拒绝；有效超级管理员保留跨部门恢复入口，但停用项目仍不能执行业务操作。

角色与个人拒绝在一致只读快照中读取。MySQL、PostgreSQL 使用显式 `Repeatable Read`；SQLite 沿用连接的 WAL 读快照。该入口从根数据库创建事务，不复用无法升级隔离级别的已有事务；任何读取或提交失败均不返回权限，并将诊断保留在内部日志。依据：[PostgreSQL 隔离级别](https://www.postgresql.org/docs/current/transaction-iso.html)、[MySQL 一致性读取](https://dev.mysql.com/doc/refman/8.4/en/innodb-consistent-read.html)、[SQLite 隔离](https://www.sqlite.org/isolation.html)。

页面另有仅属于当前登录会话的 `/auth/events/ws` 授权通知，不依赖业务读取权限，也不被已经移除的项目阻断。通知只有“重新核验”信号，不下发角色、权限、用户列表或业务内容；角色与成员变更、个人拒绝、账户及密码变更、单设备退出均使相应会话重新核验。会话绝对到期单独计时，不等待业务页面请求。

收到变更或通知连接中断时，页面先暂停受保护内容和操作，丢弃旧授权下的在途响应，再通过正常身份接口核验。基础设施故障显示暂不可用并允许重试，不假称用户已撤权；确认会话失效才退出登录。审计页在核验期间清空已加载正文并关闭详情，权限未变时恢复原浏览位置，不自动重放写操作。

通知复用现有 Redis 和 go-redis，不增加常驻服务或依赖。频道按实例前缀、Redis DB、用户和会话摘要隔离；订阅全部确认后再次核验身份，重连首帧要求重读。Pub/Sub 不是持久消息，不能承诺进程崩溃或消息丢失时仍绝对即时；订阅读取错误会断开通知连接，心跳和读取期限检测失联，同时保留焦点、可见性、请求拒绝及 60 秒身份校准。依据：[Redis Pub/Sub 的传递与范围语义](https://redis.io/docs/latest/develop/pubsub/)。源码及隔离测试不代表已有运行实例已更新，真实页面验收应单独记录。

## 接口与后台

业务接口必须携带 `X-EDO-Project-ID`，WebSocket 使用 `project_id` 查询参数。服务端先验证项目可用性和成员资格，再检查动作权限；数据库查询、更新和删除继续强制按部门、项目过滤。未携带项目 ID 的业务请求会被拒绝。

后台流水线、构建、制品、发布、通知与任务继承父资源的项目。实时状态只订阅当前项目，日志、终端和容器日志连接持续复核身份、成员资格及动作权限。移除成员或撤销权限后，已有连接也不能继续访问。

空的非默认项目可以删除；有业务资源或运行历史时拒绝删除。部门删除先检查下级、成员、项目和业务资源。删除用户同时清理其项目成员关系，不删除共享角色和业务历史。

## 初始化

使用新库初始化，不转换旧权限、不继承旧角色，也不自动分配历史资源。原开发库可以保留作为备份。

授权操作会记录审计日志。如果权限同步失败，会停用受影响的普通账户，防止旧权限继续生效；超级管理员仍可登录处理。
