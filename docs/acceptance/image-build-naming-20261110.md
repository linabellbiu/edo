# 内置镜像构建命名验收

最终规则：镜像名称可选，留空使用应用名；内置镜像构建不配置 Docker target，不自动展开多 target，按 Dockerfile 默认最终阶段构建。复杂的目标选择由自定义构建脚本处理。通用构建方案与流水线二选一的交互继续保留。

| ID | 前提与操作 | 预期 | 结果 |
| --- | --- | --- | --- |
| IBN-01 | 同一应用分别留空或填写 frontend、backend 镜像名 | 输出仓库地址/命名空间/应用名或指定镜像名:Tag | 通过 |
| IBN-02 | 打开内联、库构建及通用方案编辑 | 流水线内联/引用构建均显示可选镜像名，三种构建表单均无 Docker target | 通过 |
| IBN-03 | 旧方案存在 target 列表，创建新运行 | 不展开任务，新运行不使用 target；读取不改写旧方案和历史快照 | 通过 |
| IBN-04 | 构建与部署的关联规则 | 单独按用户最终确认处理 | 待确认范围 |
| IBN-05 | 保存构建配置后重新打开 | 指定镜像名、通用方案关联与变量引用继续保留 | 通过 |

本批不触发业务流水线，不推送镜像、不部署应用。复用已有 Docker 构建器和 distribution/reference 标准镜像引用库，无新增依赖、数据库结构或数据清理。

验证：前端 50 项定向回归、生产构建、流水线完整 Go 竞争检测、构建方案与 Compose 相关接口竞争检测通过。本批未更新运行实例，未做新的真实页面或镜像推送验收。
