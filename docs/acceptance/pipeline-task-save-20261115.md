# 流水线任务独立保存与异常提示验收

日期：2026-11-15。

原问题：任务面板复用了整条流水线的启用操作，保存 Kubernetes 任务时会被其他任务的就绪问题阻断。

| 用例 | 操作与结果 | 验证方式 |
| --- | --- | --- |
| TASK-001 | 当前任务独立保存，不提交其他任务、代码源和阶段的草稿，不触发流水线启用 | 应用与共用方案的服务层、真实 HTTP 回归及浏览器夹具 |
| TASK-002 | 新任务默认开启；关闭后保存、重新打开、再次修改仍保持关闭；流水线原启用状态保持不变 | 前后端回归及浏览器夹具 |
| TASK-003 | 关闭任务不进入新运行快照，不触发审核，不解析其部署目标；全部关闭不能创建空运行 | 服务层真实数据库回归；不执行实际部署 |
| TASK-004 | 开启任务显式引用关闭任务时，显示准确的依赖错误，不自动改用其他构建 | 服务层回归 |
| TASK-005 | 任务卡片顶部显示异常，配置顶部显示原因；流水线顶部按异常任务去重计数，点击定位 | 前端回归及真实浏览器 DOM/截图；浅色、深色、390px 窄屏 |
| TASK-006 | 保存失败保留草稿及当前任务；版本冲突仍拒绝，项目失效清理旧错误；打开配置不清除已知错误 | HTTP、前端回归及浏览器夹具 |

已通过：

- `internal/pipeline` 全量竞争检测回归，以及本次任务状态、依赖和 HTTP 保存的专项竞争检测回归。
- 前端 1948 项测试、Vue 类型检查及生产构建。
- 本地浏览器夹具的任务保存、关闭状态、异常定位及浅色/深色/窄屏交互。

扩展检查：一次 `internal/httpapi` 全量竞争检测使用了本地 10 分钟总时限，耗尽总时限后中止；当时的 SQL 工单用例仅运行 2 秒，不能据此认定该用例卡死或全量已通过。项目 CI 的原有 20 分钟单包时限未改动。

边界：测试数据库彼此隔离；浏览器使用合成数据，不连接 EDO 业务接口或 Kubernetes 集群。本次没有执行真实流水线、部署或发布到运行环境。
