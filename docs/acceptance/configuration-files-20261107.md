# 配置管理与内置部署参数验收

用户确认配置独立管理，支持多种文本格式；部署优先复用内置 Docker、Compose。选择 ENV 后不要求自定义命令，额外选项通过部署参数配置。配置引用、生成路径和参数沿用最近实际成功部署的记录；未执行流水线时，编辑或移除流程参数不改变已有实例。配置正文是例外：重启和重建读取原引用的最新已保存版本。内容有变化时，重启明确升级为重建并检查独立权限；确认后再次保存正文必须重新确认。保存配置本身不操作容器。

## 依赖选型

YAML 复用已有 yaml 2.9.1 和 CodeMirror。TOML 使用 smol-toml 1.9.1（BSD-3-Clause，无运行依赖）；审查已公开的旧版解析挂起修复，并回归不完整输入。INI 使用 npm 维护的 ini 7.0.0（ISC，无依赖），补充常见分节及 key=value 的行检查，因为解析器本身会容忍错误行；INI 方言差异仅作警告，不声称验证应用语义。JSON 使用 CodeMirror 官方 JSON 解析器（MIT）。未采用已归档的 legacy-modes；语言解析和编辑器依赖可以替换，配置原文和业务权限逻辑不依赖解析器输出。新增包适用项目容器 Node 24.16，当前本地 Node 25 会收到 ini 的版本范围警告，构建与测试实测通过。

## 内置部署接入与正文更新

- 流水线部署任务新增配置选择、相对生成路径、根目录与额外参数。新配置只按 UUID 明确选择；ENV 自动用于容器环境，其他格式只生成文件。多镜像 Compose 可通过 `${EDO_CONFIGURATION_DIRECTORY}/相对路径` 引用生成文件，标准 Compose 的 `environment` 优先于 `env_file` 规则保持不变。
- 配置默认保存到执行用户的 `~/edo/deply/<项目>/<应用>/<环境>/<运行>/<任务摘要>`，不依赖源码工作区；不自动迁移已有项目的 Compose 工作目录。每次操作重新取得正文，文件使用 0600 和原子替换，拒绝链接和越界路径。远程 Docker 的文件生成需要 SSH 连接，普通 TCP Docker API 不具备写入目标主机文件的能力；本地连接生成在 EDO 执行用户的文件系统中。
- 额外参数首批支持重复的 `--env-file 已选文件路径`。参数使用项目现有的 mvdan.cc/sh/v3 解析器识别引号，不执行 Shell 展开；未知参数、命令、重定向和未选择的文件一律拒绝。没有引入新后端依赖。暂不支持任意 Docker/Compose 参数或 `-f` 替换部署定义；避免绕过固定镜像、项目和服务范围。
- 部署固定当次运行的正文版本；重启与重建只刷新原引用的正文版本，不读取现在的流程草稿。容器标签记录已应用的版本引用摘要，不包含正文或正文哈希。配置变化时重启需要重建，Compose 确认列出该服务全部副本；未变化时仍只重启所选容器。普通停止不读取或应用配置。
- Docker 单容器与单镜像 Compose 也具备精确容器确认和重建，保留原镜像和数据卷；重建不构建或拉取新镜像。完整 Docker 命令方案不能混用新的配置注入，使用结构化 Docker 方案。配置授权、版本、容器身份在确认、取得目标锁后和执行前再次检查；确认返回及审计只记录路径、版本和受影响容器，不记录正文。

## 容器运行目录修正

正式 API 镜像 HOME 为 `/app/data`，逻辑默认路径仍为 `~/edo/deply`。仅设置 HOME 不能满足宿主机目录要求，因此正式 Compose 把宿主机执行 Compose 用户的 `${HOME}/edo/deply` 单独挂载到容器 `/app/data/edo/deply`。`EDO_DEPLOY_HOST_DIRECTORY` 可显式覆盖挂载源；SSH 部署仍使用目标登录用户的 HOME。新空目录只初始化顶层权限，已有非空且归属不符的目录拒绝接管，不递归更改。已有安装可以只执行 `--deployment-directory-only`，不读取或修改密钥、数据库及初始化标记。默认 `deply` 目录从 Git 和镜像构建上下文排除，避免将配置正文带入源码或镜像。
