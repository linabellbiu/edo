# 流水线任务异常隔离

日期：2026-11-16。

之前在创建整个运行快照时，任一任务的配置、资源、变量或制品链异常都会使整个创建失败；运行中任一任务失败也会取消其他排队任务。现在保留每个任务的失败及正常执行结果，按实际阶段边界停止推进。

| 场景 | 当前行为 |
| --- | --- |
| 同阶段一个任务的配置或资源失效 | 异常冻结到本次任务快照；到该阶段时该任务记为失败，不创建执行 Job，同阶段其他独立任务正常入队 |
| 并行任务执行失败 | 保留失败原因和日志，其他排队或运行中的任务继续，各自保存结果；当前阶段全部结束后整次运行汇总失败 |
| 串行后续任务异常 | 先执行此前正常阶段；到异常阶段时记录失败，该阶段的独立任务仍执行，后续串行阶段不启动 |
| 制品来源异常 | 只影响引用该来源的消费任务，不阻断其他合法来源；有失败的阶段仍形成屏障，不启动依赖它的下游 |
| Worker 中断或重试耗尽 | 同一事务内收敛准确任务、部署记录及有界日志，不把其他并行任务取消；停止、终态和重投校验继续保留 |
| 重复 Kubernetes 目标或镜像输出 | 冲突任务均被阻止，不让其中一个先执行；其他独立任务不受影响 |
| 权限、路径和环境错误 | 异常任务没有执行 Job，不冻结无权使用的变量或非法路径绑定；原权限和资源核验保留 |
| 结构、代码源和存储故障 | 不能建立可靠快照时继续整体拒绝；数据库故障不当作普通任务配置错误消费代码事件，恢复后仍可正常触发 |

任务失败时父运行保持执行中，直至当前并行任务全部结束；阶段耗时和当前状态继续使用真实运行记录。失败任务不能被迟到成功覆盖，正常任务的成功也不能把整次运行改成成功。用户主动停止继续作用于整次运行。

执行主机展开集中读取方案、目标及主机，不逐台查询 SQL。沿用现有阶段调度、任务幂等、权限、不可变快照、官方运行时和日志机制，无新增依赖；业务隔离规则保留在 EDO 内，不引入另一套调度器。
