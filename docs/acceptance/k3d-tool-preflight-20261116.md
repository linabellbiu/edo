# k3d 工具下载检测修复验收

日期：2026-11-16。

问题：k3d 检测把已有文件校验失败和官网下载失败合为一条提示。原连接时限 2 秒、请求总时限 4 秒，对间歇网络容易误判为不可安装。

| 用例 | 预期与结果 | 证据边界 |
| --- | --- | --- |
| K3D-TOOL-001 | 核对准确目标与已有文件：截图主机与 EDO 保存指纹匹配，k3d 工具尚不存在 | 真实主机只读 SSH；不绕过指纹、不读取或回显登录密码 |
| K3D-TOOL-002 | 原参数连续三次探测：两次 HTTP 200，一次 curl 28 且在 2 秒连接时限内退出 | 真实网络 HEAD 请求；复现间歇超时，未执行安装 |
| K3D-TOOL-003 | 修复后同一主机探测返回 `download passed`、`ready / 0 / 200` | 只执行产品的工具选择及 HEAD 探测片段；结束后工具仍不存在，不冒充完整 sudo 预检或集群安装成功 |
| K3D-TOOL-004 | 首次超时可重试成功；持续 DNS、连接或超时仅尝试两次；HTTP/TLS/重定向不无界重试 | 隔离 Shell 桩回归，模拟命令状态和调用次数，不连接真实仓库 |
| K3D-TOOL-005 | 文件、校验和、版本、网络及 HTTP 原因分别显示；未知、重复及矛盾反馈阻断；不回显远端原始错误 | 后端解析与完整性回归 |
| K3D-TOOL-006 | 现有官方 CLI、摘要、只读检测、权限、资源归属及失败保留继续有效 | K3s 模块全量与检测 HTTP 专项回归 |

实现保留官方 CLI 与已有 curl，未新增依赖、镜像搬运、主机修复或服务重启。单主机预检预算随两次最长 15 秒的网络读取调整为 65 秒，仍在安装检测接口的总预算内。
