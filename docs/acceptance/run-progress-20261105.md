# 运行总耗时与当前阶段

| ID | 角色与前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| RUN-PROG-01 | 有运行查看权限；运行正在构建 | 查看列表，等待计时并切换到部署阶段 | 一列显示总耗时和真实当前阶段；运行中黄色圆点呼吸，总耗时递增，阶段自动更新 | 隔离页面通过：真实列表组件、只读权限，计时递增并由构建自动更新为部署；浅色和深色均检查 |
| RUN-PROG-02 | 同一运行完成或失败 | 接收终态后继续停留页面 | 成功绿色、失败红色；保留最后完成或失败阶段，总耗时固定，停止呼吸 | 隔离页面通过：分别模拟成功和失败，终态颜色正确，等待后耗时固定且无动画 |
| RUN-PROG-03 | 排队、审核、停止、缺失历史与并行任务 | 查看列表、分组详情及对应接口 | 等待/停止不冒充成功；缺失时间显示未知；总耗时取实际跨度，不累加并行任务或使用更新时间补造；项目隔离及查看权限保持 | 自动回归通过：状态分支、跨度、并行、缺失时间、项目隔离和仅运行查看权限；缺失时间页面通过，560px 窄屏仅表格内部横向滚动；分组详情未作浏览器验收 |

总耗时复用当前项目内已有的批量任务时间查询，取最早实际进入时间到最终结束时间，包含有记录的代码源及阶段间等待。接口增加不持久化的 `timing`，不迁移数据库、不改执行与重试流程。列表和分组中各应用运行使用同一展示组件；分组只有部分记录时不冒充完整发布耗时。

阶段详细耗时继续保留在详情执行图中。状态事件、低频校准和页面重新可见同步继续复用既有机制，运行中总耗时以服务端采样和浏览器单调时钟递增。页面夹具使用合成数据，不触发真实构建或部署。

验证记录：

- 前端全套 1676 项通过；进度、阶段耗时及列表相关 13 项在深色样式修正后再次通过。
- 流水线时间聚合及项目隔离、HTTP 运行查看权限测试使用 `go test -race -count=1 -timeout=5m` 通过。
- `npm run build --prefix web` 通过。深色状态颜色选择器未向根节点泄漏变量，运行、成功和失败的实际计算颜色分别为 `#f1c359`、`#49c89c` 和 `#ff8490`。
- 页面夹具：`web/tests/fixtures/pipeline-run-progress.html`。本地验证不等于真实运行验收；本次未触发新的业务流水线。
