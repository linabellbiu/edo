# K3s 安装提权配置提示验收

问题：非 root SSH 账号未启用 sudo 时，预检被正确阻断，但业务层使用普通包装错误，接口只返回“安装配置无效”，未展示可操作原因。

| ID | 角色及前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| KP-SUDO-01 | 有 K3s 安装权限；非 root，未启用 sudo | 点击安装前检测、请求生成计划 | 明确指出准确主机及“使用 sudo 执行 Docker / 安装操作”设置；不连接主机、不创建计划、不修改凭据 | 通过 |
| KP-SUDO-02 | 同权限；root 无 sudo 或非 root 已启用 sudo | 检测并生成计划 | 沿用真实检测与计划流程，不扩大权限或自动启用 sudo | 通过 |
| KP-SUDO-03 | 隔离前端夹具 | 在表单点击安装前检测，接口返回 KP-SUDO-01 的业务文案 | 页面保留可操作文案，不能退回通用错误 | 通过 |

真实主机的 sudo 授权和安装不在本次执行范围；不会自动保存提权设置或执行安装。

验证：

- `go test -race -timeout 120s -run '^TestK3sHTTP(PreflightAndPlanExplainSudoRequirement|StandaloneCheck)' ./internal/httpapi` 通过，覆盖真实 HTTP 响应、独立测试数据库、模拟 SSH、原有权限/范围边界与失败无副作用。
- 前端安装、独立预检及夹具相关 87 个测试通过。
- 本机隔离页面选择测试主机并点击“安装前检测”：详细操作指引可见，生成计划禁用，计数为检测 1、计划 0、安装 0；浏览器没有脚本错误。截图 `/tmp/edo-k3s-sudo-preflight-error.png`。
- 用户本地主机 `vps` 的未启用 sudo 阻断来自实际运行日志；未修改其凭据、sudo 授权或执行安装，不能将提示修复称作真实主机已经通过检测。
