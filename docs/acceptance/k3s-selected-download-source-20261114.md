# K3s 显式下载源选择修复

问题：原生安装前端在默认安装时强制提交 `official`，覆盖用户选择；后端本身已经支持国内安装脚本与国内 K3s 程序下载。实际运行的旧任务快照为官方源，不能把修改页面当成已修改旧任务。

| ID | 前置及角色 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| SRC-01 | 有安装权限，新建/添加 Master/添加 Worker | 默认与自定义均选国内源，生成计划；两种安装方式往返切换 | 明确提交 `official_cn`，计划脚本/程序均为国内地址；不自动开始安装 | 通过：前端回归及隔离页面 |
| SRC-02 | 已有国内源计划 | 改官方下载源或切换模式 | 旧计划失效；来源不符的响应不能确认；k3d 不携带原生来源 | 前端回归通过 |
| SRC-03 | 已有运行中安装任务 | 更新 Web，检查既有任务与 API 容器 | 不重启 API，不修改旧任务来源，不冒充国内源安装已经完成 | 发布时单独核对，见交付回执 |

默认安装不提交隐藏的系统镜像仓库草稿，下载源选择不要求用户配置镜像仓库。仍执行未修改的官方文档推荐脚本，不加入环境预检、依赖安装或 GitHub 回退。

验证：121 项 K3s 前端回归通过，前端构建通过；国内来源后端定向竞争检测通过。独立页面选择国内源，往返切换默认/自定义后生成计划，安装脚本与版本制品地址均为 `rancher-mirror.rancher.cn`，命令携带 `INSTALL_K3S_MIRROR=cn`，请求记录中没有预检或安装请求。截图：`/tmp/edo-k3s-cn-plan-fixed.png`。本次未执行真实主机安装。

只读核对官方推荐国内脚本：`INSTALL_K3S_MIRROR=cn` 时校验文件与二进制均使用国内镜像分支；EDO 不修改脚本，不增加下载回退。
