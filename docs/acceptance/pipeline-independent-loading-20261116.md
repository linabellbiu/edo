# 流水线加载与慢任务隔离验收

日期：2026-11-16

## 现场原因

工作流详情 GET 同步执行每个 Kubernetes 部署任务的远程模板检查。现场同一路由出现 3176 ms、10023 ms 的响应，伴随集群检查错误；辅助目录接口只需 3–75 ms。截图的整页骨架首先由这个调用链造成，并非 Worker 没有并发能力。

另查到以下相同问题：

- 编辑器把应用、方案库、通知渠道和工作流图串成加载屏障。
- 发布记录先等其他目录，任务详情要等报告和回传读取完成才显示任务。
- 部署方案列表及内联编辑等待所有目标候选，候选未返回时可能将已有目标当成失效。
- 运行列表为补充提交人等待仓库检出锁；停止响应的展示补全还位于全局调度锁内。
- Kubernetes 镜像摘要查询位于父运行的数据库事务和行锁内，会影响其他并行节点状态更新。

## 修复

前端提交：`e419d86`、`8499703`。后端提交：`629a3b6`。

- 流水线图按路由身份直接读取，各目录独立回填、独立提示及重试。切换浏览历史、打开任务和返回不等候选目录。目录晚到或重试不能覆盖未保存草稿，旧项目响应不得回填。
- 应用、发布记录、任务详情及部署方案按区域异步更新；后台刷新保留现有内容及可点击入口。尚未返回的数据不伪装成资源不存在，目标候选未就绪时保留关联并阻止破坏性误保存。
- GET、普通保存和单任务保存只做本地配置、关联及权限校验。显式检查和启用仍做现场校验。运行创建去掉重复模板探测；真正部署在写入前仍检查资源冲突、权限和版本。
- 提交人缓存读取遇仓库检出或维护锁时不等待，不填造作者。停止后的详情补全移出调度锁。
- 镜像远程查询在事务外执行。结果返回后用短事务重新核对运行、任务 Job、权限、来源及完整仓库配置，再合并当前节点快照。同节点重投保留先固定的摘要，其他节点的快照不会丢失。

复用 Vue、Axios、AbortController、标准库同步能力及已有 registry SDK；这是页面状态和业务并发边界调整，未新增依赖或按某个应用、主机、地址编写特例。
