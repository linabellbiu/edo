# 菜单资源加载失败恢复验收

本次修复针对发布后已打开页面引用旧版 JS / CSS、菜单无法进入而刷新后恢复的问题。
沿用 Vite 官方 `vite:preloadError` 和 Vue Router，不新增依赖或常驻组件。入口 HTML 保持 `no-store`，不存在的资源仍返回 404。
参考：<https://vite.dev/guide/build#load-error-handling>。

| ID | 角色与前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| NAV-REC-01 | 有目标菜单权限；打开旧版本页面后更新静态资源 | 点击未访问过的菜单，附带查询参数和锚点 | 自动打开新页面，准确保留目标地址；其他菜单继续可用 | 通过，生产构建隔离浏览器 |
| NAV-REC-02 | 当前版本资源持续不可用 | 自动恢复后再次进入失败菜单 | 同一页面版本不再自动刷新；显示重新加载和留在当前页 | 通过，生产构建隔离浏览器；资源恢复后手动重试成功 |
| NAV-REC-03 | 编辑页有未保存内容 | 取消离开，再允许离开并遇到资源加载失败 | 取消时不加载目标、不刷新、不丢草稿；完整导航仍经过 beforeunload | 通过，真实 Vue Router 及浏览器两次取消均保留草稿，允许后进入新版 |
| NAV-REC-04 | 浏览器禁止 sessionStorage，或组件出现普通执行异常 | 点击目标菜单或触发异常 | 存储不可用时提供手动恢复；普通异常不触发页面重载 | 通过，专项自动化注入故障 |

单元测试验证恢复次数、资源错误范围、目标地址、初始导航及异常分支；生产构建浏览器夹具验证 Vite 实际资源失败、Vue Router 离开检查和完整导航。夹具仅为隔离回归，不代表真实业务资源验收。

执行记录：前端全量 1654 项通过；补充当前地址带锚点的文档重载回归后，专项 10 项通过；`npm run build --prefix web` 通过。浏览器中未出现未处理的 Promise 拒绝。目标地址为 `/target?range=3d&cluster=a&cluster=b#memory`，自动及手动恢复均完整保留。

回归方式：运行 `node --no-experimental-webstorage web/tests/chunkRecoveryBrowserHarness.mjs`，在 `http://127.0.0.1:5197/editor` 打开版本 a 后，向 `/__test/switch?version=b` 发送 POST 切换到版本 b；`fail=true` 模拟目标资源持续缺失。该服务仅监听本机。

发布后的存量页面仍运行修复前的入口代码，需要刷新一次才能取得恢复逻辑；后续发布可由该逻辑处理旧资源失效。
