# 镜像构建平台选择验收

构建方案与流水线任务在高级配置选择 AMD64（linux/amd64）或 ARM64（linux/arm64），默认 amd64。任务值覆盖方案；新运行固定平台并传给 Buildx，部署主机不改写选择。已有运行保留旧快照及原有平台解析能力。复用现有平台字段与 Docker Buildx 标准参数、现有平台校验，不引入依赖或修改业务 Dockerfile。

| ID | 角色与前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| BPA-01 | 构建方案可编辑，平台未配置 | 打开高级配置、新建保存 | 显示并保存 linux/amd64，只有两个单选项 | 通过 |
| BPA-02 | 同上 | 选 arm64，保存重开，查看列表及详情 | 各处显示 linux/arm64，不显示跟随主机 | 通过 |
| BPA-03 | 可编辑流水线任务，关联方案为 amd64/arm64 | 修改任务平台、切来源、保存重开 | 继承默认值，任务覆盖独立保存，不写公共方案 | 通过 |
| BPA-04 | 仅可查看任务 | 操作平台输入 | 禁用且回调不能写入配置 | 通过 |
| BPA-05 | 正常保存接口 | 提交未知架构或多平台列表 | 返回安全中文错误，不修改已保存值 | 通过 |
| BPA-06 | 独立数据库与构建快照 | 创建两种平台的运行，再改模板 | 每次运行固定选择，旧快照不变，执行器与 CLI 使用 --platform | 通过 |
| BPA-07 | 脚本任务或旧运行 | 打开表单、读取旧快照 | 脚本不显示或注入镜像平台，原平台推导及历史多架构能力保留 | 通过 |

页面使用真实组件及隔离内存接口，不触发业务流水线；服务、HTTP 与 CLI 测试分别验证持久化、冻结和参数。镜像目标平台与构建器自身运行架构分别处理，本批不替换本地构建器、不重启 Docker。

验证：前端全套 1812 项通过，生产类型检查及构建通过；完整流水线竞争检测、构建方案/任务覆盖 HTTP 专项及 Buildx 参数测试通过。新增测试证明固定平台优先于混合架构部署目标，旧快照架构推导仍有效。页面已确认默认 AMD64、仅两个单选项、选择 ARM64 保存及任务独立持久化；独立方案也已通过页面选择 ARM64 并保存，列表同步显示 linux/arm64；方案编辑回显与详情由共用表单、状态测试及生产类型检查覆盖。没有在 Rosetta 故障构建器上重跑业务构建，跨架构运行能力不在本批冒充验收成功。
