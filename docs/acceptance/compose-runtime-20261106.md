# Compose 多镜像运行状态修复

先同步 GitHub main，基线为 `8e45645`。线上记录为 SSH + compose_stack，原状态接口未实现该分支，前端将 compose_stack 错误归类为 Shell。

| ID | 角色、前置 | 操作 | 预期 |
| --- | --- | --- | --- |
| CMP-RUN-01 | 可查看部署；已有成功 Compose 多镜像发布及主机 Docker 接入 | 打开应用部署实例 | 从本次发布冻结的项目、工作目录及服务范围读取真实状态，不要求 Shell 命令；展示各服务状态及实例数量 |
| CMP-RUN-02 | 有停止/重启权限；独立测试 Compose 项目 | 确认后停止、重启；同时存在未选服务及其他项目 | 仅操作冻结范围内固定容器 ID；停止不删除资源，重启不改变镜像配置；不调用 down、remove 或业务 Shell |
| CMP-RUN-03 | 当前部署存在缺失、暂停、不健康服务或连接失败 | 查看及尝试操作 | 不标绿、不冒充已停止或零采样；缺失服务阻止整组操作；失败保留安全提示和诊断日志 |
| CMP-RUN-04 | 项目/主机/目录/节点快照不一致，或权限已撤销 | 读取及运行控制 | 拒绝错误归属及旧部署；沿用当前项目权限、等待锁后再次鉴权及审计 |
| CMP-RUN-05 | Compose 明确依赖一次性任务成功完成；独立测试项目 | 查看任务完成、失败、执行中状态，停止及重启常驻服务 | 成功退出显示已完成，不把常驻服务零退出误判为完成；操作跳过已完成任务，未完成任务在任何写入前阻断 |
| CMP-RUN-06 | 可查看部署；多副本 Compose 已运行 | 查看容器基本信息并打开所选副本详情、日志及终端 | 各副本分别展示真实创建时间、重启次数、镜像及状态；详情补充端口、网络及运行时间；日志和终端按权限复核精确身份，失效不换目标 |

选型沿用已有官方 Moby Docker SDK 和 Compose 标准容器标签，不新增第三方包或自行实现 Docker 协议。部署与运行控制共享同一服务范围计算；不从可编辑方案或临时 Shell 命令猜测当前运行对象。

## 验证结果

- CMP-RUN-01：本地通过。实际 DevOpsView 展示 Compose 类型、项目、逐服务状态与就绪实例数量，不显示 Shell 停止/重启命令或配置入口；后端测试通过当前部署正常入口读取冻结范围。线上只读确认原失败日志确为“不支持此操作”，原成功运行的项目、部门、方案、主机、目录等冻结字段与部署记录一致。
- CMP-RUN-02：真实 Docker 通过。独立本地 Compose 项目包含 api、worker，仅选择 api，经实际 Docker SDK 停止并重新启动 api，worker 的容器 ID、镜像与启动时间保持不变；测试项目已清理。合成接口页面确认重启弹窗明确列出 api、worker，确认后正常更新显示，不连接生产接口。
- CMP-RUN-03：通过。测试覆盖不健康、缺失服务、错误主机/目录、失效 Docker 接入；缺失服务时整组操作没有发出部分写入。前端区分部分异常、服务不存在、启动、暂停、未知等状态；失败不展示旧成功数据。状态输出不包含容器环境变量。
- CMP-RUN-04：通过。新增分支验证撤权拒绝且没有写请求，损坏冻结主机被拒绝；当前部署、等待锁后鉴权和旧实例规则的既有回归保留。
- deployment、dockerengine、pipeline 完整竞争检测通过；最终连接快照和就绪计数调整后重跑新增受影响分支通过。HTTP 运行控制/授权回归通过，相关前端回归、类型检查及生产构建通过。无新增持久化表或数据库迁移。
- 页面检查使用 `web/tests/fixtures/compose-runtime.html` 的实际组件与合成接口，覆盖浅色桌面、390px 深色窄屏与只读角色。窄屏表格支持触控横向滚动和可见键盘聚焦，不挤压服务名称。
- CMP-RUN-05：通过。仅从冻结 Compose 的 `service_completed_successfully` 条件识别任务，不按名称或零退出猜测。成功任务与健康常驻服务整体为运行中，常驻服务停止后整体为已停止，纯完成任务整体为已完成。失败、OOM、引擎错误、执行中及暂停任务均不冒充完成，停止和重启在写入前阻断。
- 一次性任务真实 Docker 回归通过：独立项目包含 setup、api、未选 worker。api 停止和重新启动后，setup 与 worker 的容器 ID、镜像、开始及结束时间全部不变；setup 没有重跑，测试项目已清理。SDK 测试进一步验证已运行 api 的重启也不向 setup 发出写请求。
- 本批 Go 受影响分支及真实 Docker 测试均开启竞争检测；40 项相关前端回归、类型检查及生产构建通过。前端验证完成任务显示“已完成”且不呼吸，确认窗口只列常驻服务，任务失败或未完成时禁用操作。
- CMP-RUN-06：通过。沿用已有官方 Moby SDK 的同次 Inspect 响应返回容器 ID、名称、镜像、创建/启动/结束时间、重启次数、端口和网络，输出不包含环境、命令、挂载及完整标签；缺失/无效时间保持空值。独立真实 Compose 将 api 扩展为两个副本，验证各自身份、创建时间、镜像和真实重启次数，原有停止、重启及一次性任务保护同时通过竞争检测。未新增依赖、表或迁移。
- 页面使用实际 DevOpsView 与合成接口检查浅色桌面、390px 深色窄屏、只读角色及容器详情。创建时间与重启次数直接列出，完整 ID、镜像、端口和网络在详情中可查看；第二个副本的终端抽屉绑定准确名称。窄屏页面宽度保持 390px，表格在区域内滚动，详情长值正常换行。
- 44 项相关前端回归通过：日志及终端打开前重新读取冻结范围，只连接原容器 ID；替换、停止、终端条件不满足、运行时改变、撤权、切项目及关闭详情均不自动改连；当前容器失效后关闭原流。没有日志/终端权限时不能发起连接，已完成任务仍可查看日志但不能进入终端。
- 容器终端沿用现有受控实现与权限，目标必须启用 init、使用独立 PID 命名空间并预装 EDO 终端工具；本次不安装工具、不修改业务容器、不退回直接 Shell。页面终端交互为合成连接，未以此声称线上容器已真实连通；运行条件不满足时明确说明原因。

首批修复 `8d9cb99` 已发布，线上只读验收确认可显示真实 Compose 逐服务状态且不再出现 Shell 配置入口，同时发现成功退出的初始化任务被误报为部分异常，因此追加 CMP-RUN-05 修复。本次所有真实停止和重启验收均在独立本地项目执行；线上业务实例仅用于只读验收，不重跑初始化任务。
