# 应用环境配置与 Compose 服务范围

| ID | 角色、前置 | 操作 | 预期 |
| --- | --- | --- | --- |
| APP-ENV-01 | 有变量权限的项目成员，应用存在测试/生产环境 | 从应用详情进入环境配置，选择环境并保存文本或逐条变量 | 项目、应用固定；按环境隔离；普通文本无需起引用名；自动关联对应部署；保存不发布 |
| APP-ENV-02 | 同一应用已有密钥和共享变量 | 编辑、保留密钥、选择共享引用，切项目或撤权 | 密钥不回显，未替换值保留；共享变量明确引用；无越权或草稿残留 |
| APP-ENV-03 | 相同应用的两个环境与已创建运行 | 更新某环境配置后创建运行 | 只作用于指定应用/环境，已有运行快照不变，后台重新检查权限与配置版本 |
| CMP-SCOPE-01 | Compose 有多个服务 | 留空启动服务或选择部分服务 | 留空不向 up 追加服务名；选择后仅追加已选服务；官方依赖语义保留 |
| CMP-SCOPE-02 | 前序多个镜像构建，部分共用镜像 | 保存部署任务并执行 | 无逐行上游选择；按完整镜像引用自动匹配，摘要与所属运行继续检查；歧义或无匹配明确失败 |
| CMP-SCOPE-03 | 没有上游构建的固定镜像 Compose | 执行部署任务 | 使用 Compose 配置的镜像执行；不伪造制品或要求空构建任务 |
| CMP-SCOPE-04 | 选定服务部署失败，有其他运行中服务 | 检查失败恢复范围 | 恢复仅限本次范围及官方依赖，不对未选择服务执行 up，不执行 down 或删除卷 |

## 使用入口

应用列表点击应用名称 → 环境配置（变量 / .env）→ 选择环境 → 添加配置。保存的新配置自动用于该应用对应环境的后续部署；已有手工变量在应用入口编辑保存后才开启自动使用。项目共享变量继续在项目变量页管理，由任务显式引用。

验收夹具：`web/tests/fixtures/application-env-scope.html`，使用合成数据，不连接业务 API。无需新增第三方包，继续复用现有加密修订、YAML 库与官方 Compose CLI。

页面、接口、持久化与真实 Compose 执行分别记录，不互相替代。
