# K3s 系统组件等待期限

真实安装中，国内 Metrics Server 镜像冷拉取耗时 5 分 34.848 秒。EDO 在组件等待固定 5 分钟后已将任务标记为失败；随后组件自然启动，集群总览恢复真实 CPU 和内存指标。没有人工修复主机或修改失败任务。

修复复用既有安装任务总超时，不再给系统组件等待另设较短的 5 分钟期限。实际就绪、权限、对象身份、集群连接和 Kubernetes 发布失败检查保留；父任务取消或超时仍立即结束。

| ID | 前置与操作 | 预期 | 状态 |
| --- | --- | --- | --- |
| KCW-01 | 安装任务还剩 10 分钟，开始组件等待 | 保留父任务截止时间，不提前截成 5 分钟 | 旧实现重现失败，修复后通过 |
| KCW-02 | Go 虚拟时钟模拟组件冷拉取 6 分钟后就绪 | 6 分钟前不成功，之后正常结束，不等待真实 6 分钟 | 虚拟时钟回归通过 |
| KCW-03 | 父任务只剩 30 秒，或取消/撤权/对象变化/发布失败 | 不延长父任务，继续按原校验阻断，不能伪报成功 | 新增期限用例及既有完整包回归通过 |
| KCW-04 | 真实集群只读页面检查 | 国内源实际生效，启动后出现真实 CPU/内存用量，历史失败任务仍为失败 | 页面与只读任务查询通过 |

本轮不执行卸载、重装、镜像搬运或主机修复。修复后的全新安装流程需要另一次由用户触发的真实安装验收，不能把本次旧失败任务改称成功。

验证：`go test -race -count=1 -timeout=5m ./internal/k3s` 通过（167.129 秒）。新增两个回归用例单独运行也通过；六分钟等待通过 Go 标准库 `testing/synctest` 模拟，没有改变系统时钟。日志：`/tmp/edo-k3s-component-deadline-before.log`、`/tmp/edo-k3s-component-deadline-regression.log`、`/tmp/edo-k3s-component-deadline-tests.log`。

只读现场：安装任务在 23:08:22 以本地存储组件就绪超时失败；Metrics Server 随后完成国内镜像拉取并启动。23:10:45 集群总览不再显示指标缺失告警，显示真实 CPU 51.84 m、内存 1.76 GiB。这是组件自然启动后的恢复，不是对原安装任务的成功验收。
