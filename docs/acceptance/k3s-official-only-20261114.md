# 原生 K3s 官方脚本安装验收

按用户最新要求，原生流程只确认配置并调用原版官方脚本，不要求 EDO 的系统、依赖、sudo、网络或镜像仓库预检，不另行安装依赖。权限、项目隔离、主机/配置快照、任务幂等和已有配置不覆盖继续保留；k3d 仍走独立流程。

| ID | 角色及前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| OF-01 | 有原生安装权限，默认新建 | 填写主机与 SQLite/etcd，生成并确认计划 | 无“安装前检测”步骤及镜像仓库必填；预览不 SSH 探测，官方源/默认镜像 | 通过（见下方证据及边界） |
| OF-02 | root/sudo 已配置，隔离 SSH 对端 | 仅有 curl 或仅有 wget，执行脚本 | 下载并执行未修改的官方安装器；无 EDO 额外依赖安装、HEAD 探测、系统工具门槛或自制二进制安装 | 通过（见下方证据及边界） |
| OF-03 | 无权限、跨项目、目标变化、重复或过期计划 | 生成或执行计划 | 仍明确拒绝；配置文件已存在时不覆盖，不自行卸载或清理 K3s | 通过（见下方证据及边界） |
| OF-04 | 隔离页面，浅色/深色/窄屏 | 从配置进入确认及任务，再关闭/重开 | 三步原生流程可用，参数/任务真实，官方失败不显示成功；k3d 检测规则不变 | 通过（见下方证据及边界） |

官方脚本事实：下载器支持 curl/wget，负责下载校验 K3s、服务安装启动，并按适用系统处理 SELinux 策略；并不会自动安装 EDO 此前要求的所有诊断命令。来源：https://get.k3s.io ，https://docs.k3s.io/quick-start 。本轮只读下载核对，未在用户目标主机执行安装。

验证记录（2026-11-14）：

- `go test -race -timeout 6m -json ./internal/k3s`：通过。另对最终计划提示、来源快照、撤权和 SSH 官方执行路径做定向竞争检测，通过。
- `go test -race -timeout 3m -run '^TestK3s' ./internal/httpapi`：通过。原生计划没有 SSH/权限探测调用，独立诊断仍只读，项目隔离、权限及重复提交仍覆盖。
- `node --test web/tests/k3s-*.test.mjs`：121 项通过；`npm --prefix web run build`：通过。
- OF-02 使用真实本地 SSH 和 POSIX shell，下载器返回受控脚本，执行路径全部映射到临时目录。验证脚本内容不被修改、curl/wget 二选一、0600 配置、引号与命令替换不执行、已有文件及符号链接不覆盖、退出码 17 失败、无下载器安全提示。未在真实主机安装 K3s，未变更 sudo 或主机依赖。
- OF-04 浏览器使用 `/tests/fixtures/k3s-official.html` 页面及页面专属内存适配器，所有未知请求拒绝。浅色桌面及 390×844 深色窄屏检查了配置、SQLite/etcd 说明、确认、开始安装与模拟失败。请求记录中没有 preflight 调用，确认前没有 installation 请求；窄屏无横向溢出。任务关闭/恢复、轮询失败及 k3d 检测门控由前端回归覆盖；模拟任务不冒充真实安装成功。
- 本地部署与真实目标主机安装分别记录：本轮只更新本地 EDO 的 API/Web，实际运行版本和健康结果以交付回执为准。
