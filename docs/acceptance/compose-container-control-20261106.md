## 权限与行为

- `deployment.container.restart`：重启单个容器。
- `deployment.container.stop`：停止单个容器。
- `deployment.container.recreate`：重建所选容器所属服务的全部副本。
- 单容器操作同时要求 `deployment.read`；使用 EDO 发布变量重建时，以当前操作者复查变量使用权限并读取原运行冻结的版本，不借用原自动发布身份；原发布和回滚的授权语义保持不变。Compose 多镜像整组停止/重启保留原 `deployment.execute` 并补查对应细粒度权限，避免从旧入口绕过。普通开发、只读角色和旧聚合权限不自动继承新动作，已有角色授权不批量改写。
- 后端在请求、等待目标锁之后及副作用执行前复查当前项目授权；记录操作者、动作、服务、受影响容器 ID 和确认摘要。审计不采集容器环境、配置正文、终端输出或密钥。
- 单独选择一次性任务重启或重建时明确提示会再次执行任务；原有 Compose 整组运行控制继续跳过已完成任务。重建普通服务使用 no-deps，不重跑初始化依赖。

## 选型与边界

沿用已安装的官方 Moby SDK 与 Docker Compose CLI，没有新增第三方依赖。官方 `up --force-recreate` 的作用对象是服务，因此没有自行复制容器配置来冒充单副本 Compose 重建。CLI 的 `config --hash`、`--no-deps`、`--no-build`、`--pull never` 与 `--scale` 经本机官方帮助和独立真实项目验证。

原发布生成的定界正文按项目协议恢复，同时校验命令快照摘要和正文摘要；不执行历史 Shell、不读取可编辑方案来替代冻结配置。重建前验证目标机保留的发布文件、Compose 配置摘要、镜像 ID 和完整副本集合。变量沿用冻结版本并复查授权；条件不满足时阻断。生成格式未来变化时需同步维护解码协议，不能用宽松 Shell 解析或当前主机文件兜底。

- CTNR-03：真实 HTTP 权限入口和部署服务集成验证通过。单独停止权限不能获得重启或重建权限；个人拒绝、跨项目、范围外 ID、陈旧确认均拒绝；通过真实锁等待钩子撤销权限后无 Docker 写请求。变量回归覆盖原自动发布身份不再有效、变量后续更新、伪造操作者和个人拒绝；权限、部署、Docker 完整竞争检测及 HTTP 权限/审计回归通过。
- CTNR-04：页面验收使用实际组件与合成接口，不连接线上业务。桌面确认窗口列出 api 的两个副本、完整 ID、镜像及重建影响，确认后关闭并更新列表。前端回归覆盖预检只读、提交防重、确认失效、撤权、切项目与迟到响应；页面与后台执行证据分别记录。
- 48 项相关前端回归及类型检查、生产构建通过。仅授予停止权限时，深色窄屏菜单只显示“停止容器”；停止确认只列所选副本。390px 页面和确认框没有横向溢出。

本地验收阶段没有修改业务仓库，没有在业务容器执行停止、重启或重建；当时尚未推送、部署 EDO。
