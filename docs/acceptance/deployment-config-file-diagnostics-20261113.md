# 部署配置文件与失败诊断

| 用例 | 角色与前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| DCD-01 | 可使用部署配置，配置正文包含 EDO_IMAGE_TAG、PATH、带引号和多行值 | 选择文件生成模式，添加 --env-file 引用 | 原样生成文件，不解析成 EDO 环境、不按保留变量名拒绝 | 通过 |
| DCD-02 | 内置 Tag 与 ENV 文件内同名默认值不同 | 准备 Compose 参数并运行只读 config 校验 | 使用 Compose 官方 dotenv；内置环境优先，文件正文不变，不把普通文件变量注入容器 | 通过 |
| DCD-03 | 旧运行使用环境注入模式；另有被撤权、跨项目或引用不一致的配置 | 解析或控制实例 | 保留旧保留名校验、版本、权限及身份边界 | 通过 |
| DCD-04 | 串行及并行任务遇到底层文件或网络错误，错误含已登记密钥 | 标记失败并查看任务日志 | 稳定业务提示与具体底层诊断分别保留；错误级别、脱敏、节点范围与日志配额有效 | 通过 |
| DCD-05 | 过期任务失败，当前任务已变化 | 回传旧失败结果 | 不覆盖当前状态、不增加旧任务诊断；不能串入其他运行 | 通过 |

不修改业务仓库、用户配置正文或已有失败记录，不代用户重新执行业务流水线。


部署、流水线两包完整 SQLite 竞争检测通过；隔离 MySQL 的配置版本、权限、串并行诊断及过期任务定向竞争检测通过。真实 Docker Compose 验证在临时目录按产品脚本原样生成 .env，再执行只读 `docker compose --env-file ... config --format json`，确认文件中的 PATH 不影响执行工具、内置 Tag 优先级一致、引号和多行值可用且正文不变；没有拉取镜像或启动业务容器。

错误诊断验证覆盖安全业务错误包装的底层文件错误、多个合并错误、脱敏、16 KiB 单条边界、任务定位和过期任务不写日志。普通运行状态提示保持原安全文案。Go 静态检查通过；隔离 MySQL 测试容器正在按本次测试范围清理。
