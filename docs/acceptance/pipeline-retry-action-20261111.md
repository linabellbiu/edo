# 流水线操作列重试验收

复用现有 `/retry-options` 与 `/retry` 流程，在操作列提供入口；保持固定 Commit、重新构建或原运行制品选择及确认。失败运行且有 `pipeline_run.execute` 权限才显示，发布执行分组不作为单条重试目标。无新增依赖、接口或自动重试。

| ID | 角色与前提 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| PRA-01 | 有执行权限，失败运行 | 查看操作列并点击重试 | 详情、日志、重试同行，打开固定版本确认，无执行请求 | 通过 |
| PRA-02 | 只读用户，或成功、运行中、停止状态，或发布分组 | 查看操作列 | 不显示重试，回调不能绕过权限执行 | 通过 |
| PRA-03 | 失败运行，无原制品 | 确认按固定版本重建，连续点击 | 仅一次重试请求，成功定位新运行 | 通过 |
| PRA-04 | 失败运行，有多个原制品 | 切换或选择制品再确认 | 未选择时不能提交，使用准确制品 ID | 通过 |
| PRA-05 | 打开重试中 | 取消、换运行、切项目或撤销权限 | 旧选项不能覆盖当前目标，受限上下文清理 | 通过 |
| PRA-06 | 隔离页面 | 从列表完整完成确认流程 | 新模拟运行出现在列表，不连接真实执行接口 | 通过 |

后端重试权限及固定版本、制品归属复用已有流程与测试；本批不重跑用户业务流水线。页面验收使用隔离内存接口，不能冒充真实构建成功。

验证：相关定向测试 19 项、前端全套 1816 项及生产构建通过。隔离真实页面确认失败记录的操作列展示三个按钮；点击只读取重试选项，确认后恰好一次模拟执行请求并定位新记录；只读角色不显示重试。无真实业务运行被重试。

补充 PRA-07：按用户指定路径“应用 → 流水线”打开关联流水线列表，每条流水线增加操作列“重新执行”，只重试该条流水线最近的失败运行；该条流水线最新运行已成功时，不取旧失败记录或其他流水线的失败记录。应用主列表继续保留检查更新及原菜单。结果：通过；29 项定向回归、前端全套 1817 项及生产构建通过。真实组件隔离页面按“应用 → 流水线 → 重新执行”打开确认，选项请求准确绑定 failed-flow-run，确认前无写入。
