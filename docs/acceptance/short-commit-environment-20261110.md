# 短 Commit 内置变量验收

`${EDO_COMMIT_SHA}` 统一提供本次固定 SHA 的前 12 位；原值不足 12 位时保留原值，缺失时不补造。`${EDO_GIT_TAG}` 有 Git Tag 时使用 Tag 名称，没有时使用相同短哈希。镜像名称与 Tag 模板、Dockerfile 构建参数、构建及部署脚本、Compose 和重启重建共用此规则。完整 SHA 继续用于数据库、运行记录、代码检出和制品身份检查，不做迁移或截断持久化值。

| ID | 角色与前置 | 操作与预期 | 结果 |
| --- | --- | --- | --- |
| SCE-01 | 可构建；Tag、分支、PR、固定提交 | 各执行上下文中的 Commit 为前 12 位，Tag 引用按有无 Git Tag 返回原名称或短哈希 | 通过：镜像 Tag、构建、部署与 Compose 上下文回归 |
| SCE-02 | 可构建；Dockerfile 构建参数引用 `${EDO_COMMIT_SHA}` | 只替换为短 Commit，保留其他未声明的模板和 Shell 字面文本 | 通过：构建参数回归 |
| SCE-03 | 独立工作区、已有 `/bin/sh` | 真实脚本读取 Commit 与 Git Tag，分别覆盖分支及 Tag 运行 | 通过：真实本机 Shell 执行，未构建或推送业务镜像 |
| SCE-04 | 可执行；已有流水线记录 | 脚本接收短 Commit，执行后数据库中的完整 40 位 SHA 不变 | 通过：正常 Shell 任务持久化及日志检查 |
| SCE-05 | 当前应用容器、重启与重建权限 | 按冻结命令执行，环境收到 12 位 Commit，完整运行 SHA 及精确容器归属继续有效 | 通过：隔离模拟 Docker/SSH 执行与数据库回归 |
| SCE-06 | 固定版本数据为 8、12、40、64 位或缺失 | 不越界、不填充，输出前 12 位或现有短值；缺少版本仍拒绝镜像构建 | 通过：执行上下文边界回归 |
| SCE-07 | 可查看变量目录 | 变量目录与问号说明显示前 12 位规则，前端沿用服务端目录 | 通过：目录更新、组件状态与 Web 构建 |
