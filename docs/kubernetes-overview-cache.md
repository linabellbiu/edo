# Kubernetes 总览缓存

总览短时间重复读取 16 类资源时，原实现会逐类重新读取集群和授权，再获取资源或元数据快照。现在一次获取集群与授权上下文后复用于本次聚合，保留实际原生请求的即时安全校验。

统计结果使用现有 client-go `LRUExpireCache`，每个身份绑定连接最多 64 条、有效期 5 秒；并发相同请求使用已引入的 `golang.org/x/sync/singleflight` 合并。两者持续随 client-go / Go 官方扩展库维护，许可证分别为 Apache-2.0 / BSD，无新增依赖。缓存与现有连接和 Watch 同生命周期，因此采用进程内缓存，避免把连接的权限状态或已失效快照共享到其他进程。

- 缓存键包含操作者、项目、部门、命名空间、可读取权限及资源变更代次；连接和授权版本由所属连接上下文隔离。
- 命中后仍核验当前数据库身份、项目和连接状态；受原生 RBAC 管理的身份还会核验对应原生读取权限。管理员降权、账户停用、会话授权版本及项目变更不会等待缓存过期。
- 未启用原生 RBAC 的普通用户也绑定其数据库授权版本；本次批量读取的有效权限会收紧旧候选权限，不额外创建原生角色或绑定。
- Watch 资源变更、连接失效及 EDO 写操作使对应统计失效；失败、部分结果和监控未就绪状态不进入缓存。保留原采集时间，不把缓存命中时间显示为采集时间。
- `fresh=1` 手动刷新绕过旧缓存及旧在途采样，并使旧采样不能随后覆盖新结果。一个等待者取消不影响其他等待者，采样仍有上限并随连接失效取消。
- 返回值深拷贝，调用方无法修改共享缓存。资源详情、编辑校验、写操作及其前置条件继续使用原有实时读取。

验收用例：缓存命中与到期、调用方修改隔离、命名空间与用户隔离、权限集合变化、并发合并与取消、手动刷新与旧结果竞态、Watch/写后失效、失败不缓存、管理员和原生权限撤销，以及聚合不再逐项重新加载集群。

本次验证通过 Kubernetes 整包竞态回归、HTTP 集群及撤权边界竞态回归；总览与身份撤销用例另外在隔离 MySQL 8.4 中通过竞态回归。Go API 的 Linux ARM64 构建通过。本地运行验收以对应版本的更新收据记录，不把隔离 TLS 夹具计为真实集群验收。
