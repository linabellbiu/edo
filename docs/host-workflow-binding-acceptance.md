# 主机与流水线关联验收

本次范围：部署选择未分组主机、主机分类调整不影响流水线、主机列表关联流水线。复用现有权限框架，不执行用户业务流水线。

| 编号 | 角色与前置 | 操作 | 预期 | 结果 |
| --- | --- | --- | --- | --- |
| HW-01 | 部署编辑者；有已就绪未分组主机 | 从树选择，保存并重新打开 | 显示未分组，保存明确主机 UUID，重开保持选择 | 通过：隔离页面保存/重开，前端正常保存请求及 SQLite/MySQL 持久化回读 |
| HW-02 | 部署编辑者；有内联或库方案关联的流水线 | 将选中主机从原组移到另一组或退出所有组，再解析新运行 | 选择、关联和新运行目标不变，不替换为原组剩余主机 | 通过：内联及库方案经真实分组服务移组后，正常运行解析与关联保持不变（SQLite/MySQL） |
| HW-03 | 执行者；已有不可变运行快照 | 调整组后执行快照及查看运行资源 | 仍使用原主机和运行时；失效能力、删除或停用主机不通过 | 通过：本地真实脚本和冻结 Compose 运行范围回归；Docker API 为隔离测试服务，未执行用户远程部署或重启 |
| HW-04 | 主机和流水线查看者 | 查看主机列表，打开关联流水线 | 内联和库方案均按明确主机统计，多个任务/归属去重，准确跳转；停用不等于解除关联 | 通过：真实 HostView 隔离页面、前端跳转断言及正常 HTTP 关联查询/去重 |
| HW-05 | 无流水线查看权限或其他项目用户 | 查询关联接口和查看列表 | 无权明确提示；跨项目关联不返回；失败不显示为无关联 | 通过：SQLite/MySQL 正常 HTTP 权限与项目隔离；前端无权和读取失败各自明确展示 |
| HW-06 | 部署编辑者 | 部分勾选、跨组、同主机多组及只读回显 | 精确 UUID、不扩大范围；Kubernetes 继续独立组/集群语义 | 通过：前端精确选择及原 Kubernetes 目标回归，SQLite/MySQL 目标校验 |


验收边界：浏览器使用真实组件配隔离接口；移组保存、关联查询、后台目标解析和权限使用独立真实数据库。用户当前 `127.0.0.1:18080` 实例未更新，也未触发用户业务流水线。

自动化入口：

- `web/tests/deployment-host-selection.test.mjs`：未分组、跨组去重、移动回显、只读和失效主机。
- `web/tests/deploymentTargets.test.mjs`：未分组连接检测、正常保存和重新打开。
- `web/tests/hosts-workspace-preview.test.mjs`：关联显示、准确跳转、失败与无权。
- `internal/pipeline/deployment_hosts_test.go`：方案/内联保存、真实分组事务、关联回读、新运行冻结、逐主机结果及跨项目拒绝；执行器为测试替身。
- `internal/httpapi/host_workflows_test.go`：正常鉴权接口，内联/库方案重复引用去重、停用与跨项目隔离。
- `internal/sshdeploy/service_test.go` 和 `internal/deployment/compose_runtime_test.go`：移除组关联后仍用冻结主机，继续拒绝能力失效和撤权。

MySQL 使用本次临时实例和每用例独立数据库。前端回归使用 Node 25.8.0 的 `--no-experimental-webstorage`，避免该版本默认的无存储文件全局对象干扰已有测试夹具；产品浏览器存储逻辑未改变。
