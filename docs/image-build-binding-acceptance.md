# 镜像构建关联验收

> 历史过渡方案，现已撤销。新运行使用纯 Tag，不再展示或要求构建任务关联；当前规则见[镜像 Tag 语义修正验收](image-tag-only-acceptance.md)。本文件仅保留历史实现的记录。

| ID | 角色与前置 | 操作 | 预期 |
| --- | --- | --- | --- |
| IMG-01 | 有流水线编辑权限，前序 api/web 镜像构建 | 部署分别关联 Compose 服务，保存再打开 | 关联准确回显；全局变量只读取明确选择的任务 |
| IMG-02 | 默认名称、手动名称及嵌套名称构建 | 使用 Git Tag 或无 Tag 的 Commit 构建 | `${EDO_IMAGE_TAG}` 是实际完整镜像地址及版本；纯版本使用 `${EDO_GIT_TAG}` |
| IMG-03 | 多个前序构建 | 不选任务、选同阶段或后续任务、重复服务关联 | 不猜测来源；无效关联被阻断；项目及产物身份检查保留 |
| IMG-04 | 有成功镜像产物 | Tag 被覆盖后部署所选构建 | 仍采用该次构建的 Digest，不能重新追踪可变 Tag |
| IMG-05 | 已成功部署或历史运行 | 恢复重启/重建环境 | 新运行恢复明确来源完整镜像；历史运行保留版本号语义 |
| IMG-06 | 自定义/库部署方案、只读用户 | 查看来源并尝试修改 | 任务关联独立保存，不写入通用方案；只读不可修改 |

本文件记录固定验收范围，执行结果以本次交付说明为准。业务仓库与业务流水线不由本次验收修改或触发。

解析继续复用已有的 Distribution reference 与 compose-go：前者处理 OCI 名称、Tag 和 Digest，后者处理 Compose 插值及必填/默认值语法。两者均为本项目已固定版本的 Apache-2.0 依赖，无新增包或运行组件。业务关联与权限边界由 EDO 自身校验。
