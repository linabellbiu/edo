# EDO 粗粒度业务验收用例

本轮按 24 条业务流程逐条验收，限时 12 小时交付结果。重点是功能能否完成，不做页面样式专项，也不为每条业务重复角色矩阵。历史证据见 [覆盖说明](acceptance-coverage.md) 和 [RBAC 验收记录](rbac-devops-acceptance-results.md)，本轮实际结果、版本和缺陷登记在独立验收目录。

## 执行与完成口径

- 先对账已有通过且未受改动影响的流程，直接引用证据，不重新创建全部角色或重跑成功链。每条只记录“通过、失败、部分通过、前提未满足、用户排除、未实现”，执行中的条目标明当前步骤。
- 每条用例按正常入口连续走完主要流程及一个有代表性的常见失败；只有不同业务实现才补必要子项，不做角色、资源、故障、主题的全排列。
- 公共权限集中抽样：管理员、可操作、只读、无权限。统一验证登录、中间件动作权限、项目隔离、个人拒绝和撤权；同一规则不按业务线重复。菜单和路由权限绑定用公共自动化/代码核对补充，不以中间件正确推定漏挂的接口安全。
- 指定审核人、禁止自审、最后 Owner、个人凭据所有权、密钥单独授权及后台固定目标属于业务规则，保留定向验证，不扩展为全站重复权限矩阵。
- 页面、正常接口和实际执行结果按步骤需要取证；不要求每次无关读取生成全套报告。功能要求页面完成时，不能拿接口或静态夹具替代。
- 发现产品缺陷保留失败、修复并回归原流程及受影响分支，每批已验证修改立即提交 main。测试工具故障不当作产品缺陷；有未知写结果时先查真实状态，不能盲目重复提交。
- 单项环境/工具问题排查到能确认原因或阻塞后，记录并继续下一项；不为一个辅助工具或缺少外部资源无限消耗时间。确需扩大权限仍先取得授权，不因限时而绕过限制。
- 第 8 小时以前完成业务用例执行或明确判定阻塞，预留 3 小时修复回归、1 小时关联自动化、清理和汇总。关键缺陷发现后立即处理，不必等第 8 小时；同一预算不重复计算。
- 12 小时结束时必须给出全部 24 条的实际结果和未解决缺陷，不承诺届时全部无缺陷。用户在2026-11-03允许三天保留和两小时终端期限采用可控时钟或独立短期限模拟；生产默认值不变、不改全局时钟，原自然长跑失败/中断保留，不将模拟称为自然长跑通过。
- 仅操作用户批准的独立本地 EDO 与专用本地 k3d；后续另行授权的指定SSH主机仅用于本轮独立文件发布及精确清理，不自动扩大为集群安装或服务器运维。不操作 CI/Runner、Docker 服务、既有业务数据或开发机已有 Kubernetes 连接。不自动推送、发布EDO；临时对象只按准确登记的目标清理，必要历史保留。

## 用例清单

各行前置均为本轮独立测试对象。普通功能复用合适的代表账号；只有审批等实际业务需要分工时使用不同账号。

| ID | 业务线 / 前置 | 顺序操作 | 通过标准 |
| --- | --- | --- | --- |
| BT-01 | 安装与登录 / 独立 Docker EDO | 1. 启动独立 API、Web 和依赖；2. 登录、退出、重新登录；3. 保存配置并正常重建应用容器后回读 | 页面、API 与长连接可用，前后端分离、数据保留；缺配置不带病启动。Mage/二进制成功启动缺独占环境时单列，不借既有服务冒充 |
| BT-02 | 数据库 / SQLite、PostgreSQL、MySQL 独立测试库 | 1. 各类型全新初始化；2. 升级已有结构并继续写入；3. 核 UUID 关联和 PG/MySQL 上海时区 | 三种真实数据库数据保留、可继续写入；不以 Mock 或 SQLite 代替其他两库；没有当前连接条件的子项明确阻塞 |
| BT-03 | 组织与账号 / 本轮新对象 | 1. 创建用户、部门、项目和成员；2. 修改角色、成员及账号状态；3. 验证在用保护、最后 Owner 保护并正常清理 | 正常管理流程完整，引用保护不破坏数据；不改既有恢复管理员或默认项目 Owner。公共权限直接引用 BT-04 |
| BT-04 | 公共权限 / 少量代表角色 | 1. 验证可操作、只读、无权限账号的合法读写及拒绝；2. 抽样同账号跨项目、个人 deny；3. 抽样撤权恢复和一个实际长连接/后台动作 | 公共规则生效，401/403及对象不可见符合范围，拒绝无写入；菜单与接口一致。已通过且未受改动影响的样本不重跑，不逐业务排列角色 |
| BT-05 | 仓库与凭据 / 专属测试仓库 | 1. 添加、编辑、测试连接；2. 选择 Branch/Tag/Commit；3. 停启并验证凭据引用保护 | 正常连接及版本可用，错误连接提示安全；凭据不回显、所有权与引用正确 |
| BT-06 | 代码触发与缓存 / 可控 Git 源 | 1. 正常提交和 Tag 触发；2. 同事件再次投递；3. 推进分支后核已运行任务 Commit 与缓存 | 触发和去重准确，已有任务固定来源，不被分支/Tag 或旧缓存替换。真实外站 PR/MR、回写、冷下载缺前提单列 |
| BT-07 | 应用与流水线 / 仓库已配置 | 1. 创建、改名应用及默认流水线，补一次名称边界；2. 配阶段、任务、拖动与公共模板；3. 保存重开、取消草稿及一次冲突 | 默认配置可用，顺序/并行及模板绑定正确，取消不写入，冲突不静默覆盖 |
| BT-08 | 构建与部署方案 / 本轮应用 | 1. 创建、编辑 Dockerfile/Shell 构建方案；2. 创建、编辑 Docker/Compose/脚本部署方案；3. 取消、停启、引用保护和删除新对象 | 类型切换只校验实际字段，保存、取消、状态及关联返回准确；引用方案不误删 |
| BT-09 | Docker 构建 / 隔离构建器与仓库 | 1. 正常测试和构建；2. 看日志、阶段结果、镜像及容量；3. 注入一次失败并核下游 | 构建真实执行、来源和制品一致，失败不继续发布；抽查构建密钥不进日志/快照/镜像。外部镜像仓库推拉独立标记 |
| BT-10 | 文件制品 / Shell 与上传入口 | 1. Shell 生成并收集文件；2. 普通上传、列表、详情及按钮下载核摘要；3. 用已有制品继续部署，补一次超限/取消 | 大小、归属、创建人及真实文件正确，历史保留；复用不重建、不把产物执行显示成分支构建。相同撤权机制引用 BT-04/既有证据 |
| BT-11 | 手动发布 / 发布组和单应用 | 1. 分别选择代码分支与已有制品；2. 提交后停留原页看后台记录；3. 验证分支条件不匹配时的后续节点 | 快速受理、不阻塞前台或强制跳页，运行与目标准确；不匹配规则按约定阻止下游，不漏执行记录 |
| BT-12 | 环境审批 / 申请与独立审核人员 | 1. 提交需审核发布；2. 首票、自审/重复和第二票；3. 环境停用/Ref 或时间窗口拒绝后恢复 | 审批不足不部署，达标才继续；指定人、禁止自审和冻结规则正确，上海时区正确。已有规则证据直接复用 |
| BT-13 | 发布失败与重试 / 独立可牺牲目标 | 1. 发布健康版本；2. 新版本健康失败，查看恢复；3. 推进代码后重试原版本或选择原产物，验证 Docker 回滚入口 | 健康失败及回滚结果与实际实例一致，后续阶段不误推进；重试保持所选固定来源，不重放错误生产来源 |
| BT-14 | 后台任务 / 独立 API、Redis、NATS | 1. 正常运行并停止一次本轮任务；2. 一个代表性进程退出/依赖恢复；3. 查看租约、有限重试和死信 | 任务不依赖页面存活，恢复可追踪，无重复外部效果；仅影响本轮组件。已验证故障矩阵复用，不遍历全部组合 |
| BT-15 | 主机与运行资源 / 本轮主机和容器 | 1. 查看真实资源并从 Docker 图标进入；2. 运行中/停止容器详情及日志；3. 跟随、断线恢复和关闭 | 主机资源口径准确，缺测不补零；容器日志只读、目标正确，系统日志不混入容器日志 |
| BT-16 | 终端与文件 / 主机、Docker、Pod已支持入口 | 1. 连接、输入、resize、关闭，主机最小化/恢复；2. 浏览、上传、下载、编辑并确认覆盖；3. 补一次摘要冲突及关闭/撤权回收 | 准确进入目标；仅主机可最小化，文件真实可用、原子保存和冲突提示正确，本会话进程可回收，不影响业务容器。超长时限与极限传输单列 |
| BT-17 | 手动 SQL 正常流程 / 专用数据库与分工账号 | 1. 配目标、添加 SQL 并自动检查；2. 指定人审核、驳回修改后重审；3. 执行及查看实际结果，重复执行/成功后改删 | 检查、审核、执行分离；默认发布前但不自动执行，准确本次目标执行一次，成功后不可改删，实际数据库结果一致 |
| BT-18 | 手动 SQL 异常与跳过 / 专属可牺牲数据库 | 1. 错误连接/不合理 SQL；2. 审核员填写原因跳过准确目标；3. 执行中故障后查看待核实及重试限制 | 不把检查故障当通过，跳过有准确范围/原因和审计；未知执行不自动重放。提交后丢回执等极端故障作为专项保留 |
| BT-19 | K8s 管理 / 专用本地 k3d | 1. 接入、总览、集群/命名空间筛选和历史返回；2. 查看节点、工作负载、配置、存储、网络；3. 用表单创建/编辑/普通删除准确新资源及节点停调度/恢复 | 各已支持资源的主要动作真实生效，列表与详情上下文正确；集群级资源不被命名空间误筛，旧资源不变。产品安装另列目标前提 |
| BT-20 | K8s 运行维护 / 本轮工作负载与密钥 | 1. 版本→Pod→容器查看日志和终端/文件；2. Secret独立授权查看并关闭重开；3. YAML格式/服务端校验及一次版本冲突 | 关联和容器身份正确，Secret默认脱敏；错误输入和冲突不覆盖数据，运行维护不触发K8s流水线发布 |
| BT-21 | 系统设置 / 独立目录与日志 | 1. 修改日志级别和访问日志；2. 查看、切换四类目录；3. 清理忙碌拒绝及合法清理，重启回读设置 | 热更新和持久化正确，目录隔离、用途和用量准确，产物迁移/历史保留，不清理Docker镜像或其他任务 |
| BT-22 | 审计与系统监控 / 已产生业务记录 | 1. 查看准确操作审计、分页及返回；2. 看EDO RSS/堆与历史、负载后恢复；3. 确认清理本轮死信 | actor/目标/结果准确、敏感值不泄露；进程与整机口径分开，无伪造零和历史；只清死信。三天保留与重负载专项不混为本条主流程通过 |
| BT-23 | 定时、监控规则与通知 / 可控接收端 | 1. 创建、停启、修改上海时区定时；2. 监控正常→失败→恢复；3. 看通知记录、失败重试及实际接收 | 后台触发、去重、告警/恢复和通知正确；本地接收端不冒充SMTP/企业外站真实联调 |
| BT-24 | 助手 / 默认关闭 | 1. 检查管理员启停和无Key草稿；2. 缺真实Key时确认不伪造调用；3. 有获准Key才验证只读排障与确认写 | 提醒、启停、范围和确认规则正确；不能执行删除/任意命令。真实模型缺Key记前提未满足，不无限等待 |

## 12 小时执行节奏

| 时段（从开始计） | 内容 |
| --- | --- |
| 0～0.5 小时 | 固定24条、对账当前环境与已有证据，结束重复权限准备；公共权限只补确实缺少的代表样本 |
| 0.5～2 小时 | 账号组织、仓库、应用、流水线及方案 |
| 2～4 小时 | 构建、制品、发布、审批、失败恢复及任务 |
| 4～5.5 小时 | 主机、日志、终端文件和SQL |
| 5.5～7 小时 | 本地K8s管理、设置、审计与监控 |
| 7～8 小时 | 定时通知、助手和必要主流程缺口 |
| 8～11 小时 | 修复、原失败用例回归及受影响分支，每批完成即提交 |
| 11～12 小时 | 关联自动化回归、临时对象清理、全部结果与遗留问题汇总 |

前半程可连续复用一套业务夹具：仓库 → 应用/流水线 → 构建 → 审批/发布 → 实例/日志/制品。不要每测一步重新搭一套环境和角色。可以提前完成后续阶段，不为排期空等；工具失败不无限重试，缺外部资源不占用剩余功能时间。

## 外部前提、排除与专项

- 外部前提：合格Linux SSH安装目标、真实外站Git/PR/Webhook、可推拉镜像仓库、远程SSH目标、真实模型Key/检查工具冷下载、独占Mage/二进制启动环境。前提不满足的子项写明阻塞，不能用本地成功或Mock填绿，也不扩大访问历史服务器。
- 用户排除：域名/DNS真实写入、第三方登录真实联调、K8s流水线发布计划/回滚。
- 未实现：Compose手动回滚/移除、k3d产品自动扩容/卸载、SQL自动发布门禁等，不发明接口或临时开发成新功能。
- 长期与深入专项：三天保留和终端期限按用户新口径模拟，明确实际覆盖，不替换旧自然长跑记录；跨数据库持锁/双后端极端竞争、大文件极限/HTTP2故障、SQL提交后丢回执等分别记录实际证据。保留未覆盖状态，不继续阻塞本轮粗粒度功能清单，也不笼统宣称全部专项通过。
