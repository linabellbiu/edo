# EDO 任务逻辑主题与传输主题

任务的 Job 与 Outbox 继续保存 `edo.task.<kind>` 逻辑主题，用于描述任务类型、校验封套和保留审计记录。实际传输主题由 `EDO_NATS_SUBJECT_PREFIX` 决定：例如逻辑主题 `edo.task.pipeline.build` 在前缀为 `edo.permissions.20261023.task` 时，投递到 `edo.permissions.20261023.task.pipeline.build`。

Outbox 构造必须显式接收整份 NATS 配置，在发布边界统一完成映射，Worker 使用相同映射校验消息；任务 Stream 与 Consumer 仍直接使用同一份 NATS 配置，不在缺少前缀时静默回退。配置默认前缀 `edo.task` 的传输行为保持不变。所有任务生产者及人工重试共用这条路径，不分别维护配置副本。

映射只接受主题与 kind 完全对应、kind 不含通配符或空分段的任务；Outbox 同时检查任务封套版本、Job ID 与 Aggregate ID。配置的精确死信主题先排除映射，即使它位于逻辑任务前缀下也按原主题发送；其他非任务事件同样保持原样。映射不修改已保存的逻辑主题、载荷、事件去重 ID、项目范围、执行次数或重试策略。

此修复不修改、清空或迁移 NATS Stream，不重投已发布的历史消息，也不更新既有业务数据。旧配置下已经投递到错误 Stream 的任务需要独立处理，不能把完成路由修复当作历史任务已恢复。

回归检查包含默认和自定义前缀下的真实数据库任务创建、Outbox 发布捕获、Worker 领取与重试完成，检查项目隔离、冻结范围、事件 ID 和载荷不变；另验证错误前缀拒绝、任务封套校验及死信主题原样投递。
