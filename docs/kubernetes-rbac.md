# 项目角色与集群 RBAC

EDO 的项目角色负责功能权限，集群授权负责资源范围。映射启用后，用户业务请求还必须通过 Kubernetes 原生 RBAC。实现复用现有项目成员、角色和有效权限计算，以及官方 client-go，不另建用户密码或长期访问令牌体系。

## 配置流程

1. 在项目成员中明确分配项目角色，并给角色配置所需的 Kubernetes 功能权限。平台角色分配不会自动授予项目能力。
2. 从角色页、集群列表或集群工作区进入“集群授权”。查看配置使用 `kubernetes.rbac.read`，修改使用 `kubernetes.rbac.update`。
3. 选择项目角色、明确的 Namespace 或集群级资源范围，以及操作子集。可以为同一角色配置 Namespace A 只读、B 可写。
4. 预览最终原生 RBAC 规则、受影响的用户身份和提示，再保存。映射未启用时只保存草稿，不修改集群。
5. 明确启用映射并等待同步成功。同步中或失败时，业务访问保持阻断；可以查看受控错误并重试同步。关闭映射也必须等受管理规则清理成功，失败不会自动退回旧模式。

部署及数据库迁移不会自动开启映射或给现有用户增加集群权限。首次初始化由超级管理员完成；普通授权管理员只能委派自己已经拥有的操作和集群范围。超级管理员保留配置、修复及关闭的管理入口，但业务数据仍要求实际项目成员角色和显式范围授权。

## 资源与规则

Namespace 范围明确具名，不接受通配符；空 Namespace 仅与显式集群级范围配合使用，不表示全部命名空间。集群级范围只覆盖 Node、Namespace、PV、StorageClass 等实际集群资源，不隐含全部 Namespace 内的工作负载权限。前端可选范围直接使用服务端编译器输出的 `resource_scopes`，与原生规则保持同一来源。

原生规则由资源注册表和操作编译得到，覆盖普通资源、Pod 日志、容器执行、工作负载重启与扩缩容等子资源。容器终端还需要 EDO 的 `terminal.open` 以及对应 Namespace 的 `kubernetes.workload.execute` 授权。不会授予通配符、RBAC 管理、`bind`、`escalate` 或任意主体模拟权限，也不会自动绑定 `cluster-admin`。

诊断中的事件读取还需要该 Namespace 的工作负载读取权限；普通网络、配置或存储读取不会自动获得其他资源的事件消息。原生 `patch` 无法区分重启和任意编辑，因此 EDO 还按具体操作校验范围，重启权限不会成为通用更新权限；没有读取范围的写入或执行响应只返回必要的资源标识。

Kubernetes RBAC 没有显式拒绝规则。EDO 先按当前数据库中的项目成员、角色权限和用户允许/拒绝计算有效权限，再与范围授权取交集生成规则。用户级允许不自动扩大角色的集群范围，显式拒绝会收窄最终规则。

Secret 明文使用独立的 `kubernetes.secret.read`。原生 RBAC 无法表达“只读 Secret 元数据而不能读内容”，因此普通配置读取不会隐含 Secret get/list/watch。严格模式下，Secret 写入也要求单独具备内容读取权限及对应配置写权限，以完成变更前校验；未满足的操作会拒绝，不能用管理凭据代办。

节点创建是受审计的控制平面操作：先检查明确的节点创建范围及主体的原生节点读取权限，再允许后台产生短期引导凭据。不会给普通用户投影 kube-system Secret 写权限。主机与集群关联校验也必须有明确的节点权限或配置集群授权的管理权限。

## 请求身份和同步

每个业务主体由项目、用户和有效策略版本生成独立身份。后端仅设置服务端推导的 Impersonate-User，剥离外部传入的身份模拟头，原生拒绝不会回退管理员。上传 kubeconfig 中的身份模拟配置继续被拒绝。管理同步使用独立的控制面连接路径；现有集群凭据需要具备管理目标 RBAC 对象和模拟对应主体的权限，否则同步失败。

同步仅管理带精确 EDO 项目、集群和主体归属标记的对象；同名非受管理对象不会覆盖。清理使用 UID 与 resourceVersion 前置条件，数据库同步租约和乐观版本避免多实例互删及旧计划重放。后台按周期收敛，显式同步接口可立即请求重试。

角色、成员、拒绝项或授权范围变化后，旧身份不再用于新请求。每次请求从当前数据库检查授权，不仅依赖 Redis 的异步策略通知；原生 SelfSubjectAccessReview 用于活跃流和不经过实时 API 的数据返回。Watch、日志及终端有短授权租约，撤权或无法核验时主动断开；已经执行的操作或启动的进程不会因断开连接自动回滚。

查询客户端、Watch、元数据新鲜度屏障和指标缓存按完整用户身份、策略及连接版本隔离。原生数据 API 继续由集群鉴权；缓存指标和历史数据返回前额外核验原生权限，不缓存授权成功。命名空间全选只遍历已授权范围，分页游标绑定身份与策略；没有身份的后台调用不会自动获得管理员权限，发布任务使用原请求人的身份。

更换已启用映射的集群连接需要配置授权权限，并使策略重新进入同步状态。将同一逻辑连接改指向不同物理集群时，旧集群上的受管理对象无法通过新连接清理；应在原连接仍可用时先关闭并完成清理，再迁移连接。此功能提供 EDO 内访问授权，不分发可用于 kubectl 直连的用户凭据。

参考：[Kubernetes RBAC](https://kubernetes.io/docs/reference/access-authn-authz/rbac/)、[用户身份模拟](https://kubernetes.io/docs/reference/access-authn-authz/user-impersonation/)。
